### Problem
- Under `bun test`, `t.signal` from `node:test` never aborts and a test ignores its `signal` option. An aborted test runs to the end and passes. Node cancels it.
- `TestContext#signal` (`src/js/node/test.ts:1709`) is an `AbortController` that nothing aborts. `executeTestNode` (`:2321`) arms only a timeout race.

### Fix
- `TestNode.cancel()` records the error, aborts `t.signal` and rejects the promise the run waits on. The timeout, the `signal` option and a finished parent call it.
- A finished test cancels the subtests it did not wait for.
- Each `--retry` attempt gets a new `TestNode`.
- Verified: 7 new tests in `test/js/node/test_runner/node-test.test.ts` fail on main. Fixtures 30 and 31 print the same lines under node v26.3.0. Also the vendored `test-runner-*` files.

### Background
- `TestNode` is the shim's record of one test. `executeTestNode` runs its hooks and body.
- A run waits on one promise: the body, a plan wait or the subtest queue. `cancel()` rejects it with a JSC intrinsic that ignores a second settle.
- Considered a stop promise raced against every body. It made an `AbortController` per test and broke `--retry`.

### Downsides
- A test whose `signal` aborts, or a subtest that outlives its parent, now fails.
- A plain test pays a 320 B `TestNode` (main 224 B) and +3,596 instructions with the JIT off (+5.1%, inside the noise with the JIT on).
- If `bun test`'s own timeout abandons a test whose `signal` aborts later, bun prints "Unhandled error between tests". That run already fails.

#### Repro (the report)

```js
import { test } from "node:test";
let abortSeen = false;
test("times out; cleanup keyed on t.signal", { timeout: 50 }, async t => {
  t.signal.addEventListener("abort", () => { abortSeen = true; });
  await new Promise(r => setTimeout(r, 200));
});
test("observer", () => { console.log("OBS abortSeen=" + abortSeen); });
const ac = new AbortController(); setTimeout(() => ac.abort(), 20);
test("external signal aborts mid-test", { signal: ac.signal }, async () => {
  await new Promise(r => setTimeout(r, 200));
  console.log("OBS signal-test body completed");
});
```

- node v26.3.0: `OBS abortSeen=true`, the third test is cancelled and its body does not run. pass 1, cancelled 2.
- main: `OBS abortSeen=false`, `OBS signal-test body completed`. 2 pass, 1 fail.
- this PR: `OBS abortSeen=true`, the third test fails with the abort reason and its body does not run. 1 pass, 2 fail.

#### The other 17 probe files

- Not in this PR: suite-level `signal` and `timeout` (#39312), the late subtest rule (#39286), `expectFailure` and todo accounting of a cancelled test (#47460), `failureType: 'testCodeFailure'` on a thrown error (#45717), todo bodies without `--todo`, and the order between a suite's children and a `t.test()` declared inside its `describe()` callback (same on main).
- The `signal` option gets its listener when the test starts, not when `test()` is called. A duck-typed signal without `addEventListener` therefore fails the test when it runs. Node throws from `test()`.
- Node throws inside its abort handler for a reason it cannot tag (a string). Bun fails the test with that reason.
- `bun test` exits when the last test is over. A cancelled subtest of that test has started its after hooks by then, but an async one may not finish. In Node the process waits.

#### Left for later

- bun:test's own timeout (5 s, `--timeout`) ends a test without telling the shim, so `t.signal` does not abort then and the third Downsides bullet exists. #43803 works on that path.
- `run()` has no `cancelled` count (22 in Node for fixture 31, 0 here). The events are `test:fail`.
- A subtest does not inherit its parent's timeout. Node uses it during the parent's async after hook.

#### Questions for a maintainer

- The plain path is main's `await` of the body plus one field write and one clear, so that `cancel()` can reject that promise from outside. If that is not acceptable, the fallback is to arm a stop promise only when a timeout, a `signal` option or a `t.signal` read exists.
- A new `TestNode` per `--retry` attempt can be its own PR. It is here because cancel state on a node that two attempts share fails every retried test.
