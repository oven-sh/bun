<Warning>Ahead-of-time compilation is experimental.</Warning>

```bash terminal icon="terminal"
bun compile --library
```

[`bun compile`](/bundler/aot) compiles a program, and the packages it imports, to machine code. It [uses TypeScript types](/bundler/aot-types#what-a-type-buys) to do that: with them, reading a property is a load from a known offset. Without them, it's a lookup by name.

Most packages on npm ship JavaScript and a `.d.ts` file. The `.d.ts` file describes the exports, not the code inside, so `bun compile` compiles the package without types.

`bun compile --library` builds a package that also ships a copy of its JavaScript with the types left in. A program built with `bun compile` gets typed code from that copy. Every other tool sees an ordinary package.

## Build the package

```ts src/index.ts icon="/icons/typescript.svg"
export interface Options {
  name: string;
  times: number;
}

export function greet(options: Options): string {
  return ("hello " + options.name + " ").repeat(options.times).trim();
}
```

```json package.json icon="file-json"
{
  "name": "greeter",
  "version": "1.0.0",
  "license": "MIT",
  "scripts": { "test": "bun test" },
  "devDependencies": { "@types/bun": "latest" }
}
```

```bash terminal icon="terminal"
bun compile --library
```

Bun type checks the package, then writes a `dist` folder that's ready to publish. A type error fails the build.

```txt
  index.js      135 bytes  (entry point)
  index.aot.ts  232 bytes  (typed source)
  index.d.ts    152 bytes  (declaration)
  package.json  407 bytes  (asset)
```

| File           | Holds                                                        | Read by                     |
| -------------- | ------------------------------------------------------------ | --------------------------- |
| `index.js`     | The bundle, as ES modules                                    | Every runtime and bundler   |
| `index.d.ts`   | Types for everything `index.js` exports, in one file         | Editors, `tsc`, `bun check` |
| `index.aot.ts` | `index.js` with its types put back, and nothing else changed | `bun compile`               |
| `package.json` | Your `package.json`, rewritten for the files above           | npm and whoever installs it |

The files are named after the entry point. Bun also copies your `README` and `LICENSE` files.

### The package.json that Bun writes

```json title="dist/package.json" icon="file-json"
{
  "name": "greeter",
  "version": "1.0.0",
  "license": "MIT",
  "type": "module",
  "main": "./index.js",
  "module": "./index.js",
  "types": "./index.d.ts",
  "exports": {
    ".": {
      "types": "./index.d.ts",
      "bun-aot": "./index.aot.ts",
      "default": "./index.js"
    },
    "./package.json": "./package.json"
  },
  "files": [
    "index.aot.ts",
    "index.d.ts",
    "index.js"
  ]
}
```

Bun keeps the fields that describe the package, such as `name`, `version`, `license` and `dependencies`. It leaves out `scripts`, `devDependencies`, `private` and `workspaces`. It writes its own `type`, `main`, `module`, `types`, `exports` and `files`.

Bun keeps an entry of your own `exports` if this build writes its file. The entry can point at the source (`./src/index.ts`) or at the file that the build writes (`./dist/index.js`). It keeps its name and its conditions, and Bun rewrites the paths.

```json
{
  "exports": {
    ".": "./src/index.ts",
    "./where": { "browser": "./src/where/browser.ts", "default": "./src/where/server.ts" }
  }
}
```

In `dist/package.json`, `"./where"` still has its two conditions. Each now holds the three files of its own entry point.

```json
{
  "./where": {
    "browser": { "types": "./where/browser.d.ts", "bun-aot": "./where/browser.aot.ts", "default": "./where/browser.js" },
    "default": { "types": "./where/server.d.ts", "bun-aot": "./where/server.aot.ts", "default": "./where/server.js" }
  }
}
```

If all the conditions of an entry lead to one file, Bun writes that file's three lines and nothing else.

Bun drops the rest of what your own `package.json` lists under `exports` and `files`, such as CSS or JSON assets. It doesn't copy those files either. It keeps a `bin` entry only if its file is one of the entry points. The build warns about each `exports` and `bin` entry that it drops, whole or in part.

```txt
warn: "./style.css" in "exports" of package.json is left out of dist/package.json: no entry point of this build is written there
warn: "rich" in "bin" of package.json is left out of dist/package.json: ./src/cli.ts is not an entry point of this build
```

Read `dist/package.json` before you publish.

The `"bun-aot"` condition points to the typed file, `index.aot.ts`. Other tools don't know the condition, so they never read that file. Its place among the other conditions doesn't matter.

## Try it in a program

```ts app.ts icon="/icons/typescript.svg"
import { greet } from "greeter";

console.log(greet({ name: "Ada", times: 2 }));
```

Put a small program next to your `package.json`, and build the package into `node_modules`.

```bash terminal icon="terminal"
bun compile --library --outdir node_modules/greeter && bun compile ./app.ts && ./app
```

```txt
note: "greeter" 1.0.0 is compiled from its typed version in node_modules/greeter
hello Ada hello Ada
```

When Bun compiles the program, it removes the types from `index.aot.ts` and compares the result with the installed `index.js`, byte for byte. If they differ, Bun prints a warning and compiles `index.js` without types.

```txt
warn: the typed version of "greeter" in node_modules/greeter is not used: index.aot.ts without its types is not index.js (was the package patched?): the package is compiled untyped
```

## Test before you publish

`bun compile` [holds a program to its types](/bundler/aot-types#where-untyped-values-meet-typed-code). Once your package ships a typed file, the code inside your package is held to its types too. Code that gets by on `any` or `as` can behave differently in your users' compiled programs than it does in `bun run` or Node.js. Run your package's tests under the same rules.

```bash terminal icon="terminal"
bun test --aot
```

Bun type checks the typed file once more before it writes it, with `"lib": ["esnext"]` added to the `lib` in your `tsconfig.json`. Most projects that use Bun have that `lib`, and your typed file is checked with theirs, not yours. If your code only passes with an older `lib`, Bun prints a warning with the first error and writes no typed file. The rest of the package is written as usual.

## Publish it

```bash terminal icon="terminal"
cd dist
bun publish
```

## What changes for your users

Your users don't have to set anything up.

- **The package is an ES module.** `require("greeter")` works in Bun, and in versions of Node.js that can `require()` an ES module: 20.19, 22.12 and later. If you ship CommonJS today, users on older versions can no longer `require()` your package. You can [ship both](#ship-commonjs-and-the-typed-file).
- **Your types are enforced.** If a compiled program passes your function an `any` that doesn't match the declared parameter, the call throws a `TypeError`. Without the typed file, the same call goes through.
- **Only `bun compile` reads `index.aot.ts`.** For everyone else it's one more file in the package.
- **The typed file never fails a build.** If it doesn't match `index.js`, or it has a type error in your user's project, Bun prints a warning and compiles `index.js` without types.

## Entry points, dependencies and flags

- Without an entry point, Bun builds every TypeScript file that `"exports"` in `package.json` points at. If there is none, it builds the file that `"module"` or `"main"` points to, if it's a TypeScript file. Otherwise it looks for `index.ts`, then `src/index.ts`.
- With several entry points, each gets its own files and its own entry in `exports`: `./src/index.ts ./src/version.ts` gives `"."` and `"./version"`.
- Bun leaves `dependencies`, `peerDependencies` and `optionalDependencies` as imports. It bundles the `devDependencies` that your code imports.
- `--outdir` sets the output folder. The default is `dist`.
- `--target` is `node` by default. `browser` and `bun` work too.
- `--format` is `esm` by default. [`cjs`](#commonjs) works too, but Bun writes no typed file for it.
- `--minify`, `--splitting` and `--sourcemap=inline` work, but Bun prints a warning and writes no typed file. `--sourcemap=linked` keeps it.
- An entry point inside `--outdir` is an error, because the build would overwrite it.

`--library` writes a package into a folder, so it rejects `--outfile` and [`--trim`](/bundler/aot-size).

```bash terminal icon="terminal"
bun compile --library --outfile greeter
```

```txt
error: --library writes a folder. Use --outdir instead of --outfile
```

## JavaScript packages

`--library` also takes a JavaScript entry point. Bun writes the `.js` file, a `.d.ts` file that it infers from the code and its JSDoc comments, and the `package.json`. `bun compile` doesn't use JSDoc types, so Bun writes no typed file.

## CommonJS

If your sources use `require()` and `module.exports`, pass `--format=cjs`. Bun writes the bundle, a `.d.ts` file and the `package.json`, but no typed file.

```js index.js icon="/icons/javascript.svg"
/**
 * @param {string} name
 * @returns {string}
 */
function greet(name) {
  return "hello " + name;
}

module.exports = greet;
```

```bash terminal icon="terminal"
bun compile --library --format=cjs ./index.js
```

The package stays CommonJS.

```json title="dist/package.json" icon="file-json"
{
  "name": "greeter",
  "version": "1.0.0",
  "license": "MIT",
  "type": "commonjs",
  "main": "./index.js",
  "types": "./index.d.ts",
  "exports": {
    ".": {
      "types": "./index.d.ts",
      "default": "./index.js"
    },
    "./package.json": "./package.json"
  },
  "files": [
    "index.d.ts",
    "index.js"
  ]
}
```

If you leave out `--format=cjs`, Bun wraps `index.js` in an ES module with a default export, and doesn't warn you. That breaks your users in two ways:

- `require("greeter")` returns `{ default: greet }`, so `require("greeter")("Ada")` throws `greeter is not a function`.
- The `.d.ts` file still says `export = greet`. `import greet from "greeter"` runs, but `bun check` reports `TS1192: Module ... has no default export`.

### Ship CommonJS and the typed file

Bun only writes the typed file for ES modules. If you build TypeScript sources with `--format=cjs`, Bun prints a warning and leaves the typed file out. When your users run `bun compile`, it compiles your package as plain JavaScript.

To serve both, build twice. Put the CommonJS build in a folder inside the first one.

```bash terminal icon="terminal"
bun compile --library && bun compile --library --format=cjs --outdir dist/cjs
```

```txt
warn: the typed JavaScript that --aot compiles a package from is left out: it does not support --format other than esm yet
```

Then add a `"require"` condition to `dist/package.json`, and add `"cjs"` to its `"files"`.

```json title="dist/package.json" icon="file-json"
{
  "exports": {
    ".": {
      "types": "./index.d.ts",
      "bun-aot": "./index.aot.ts",
      "require": "./cjs/index.js",
      "default": "./index.js"
    }
  }
}
```

`require("greeter")` now loads `cjs/index.js`, in Bun and in Node.js. `import` loads `index.js`, and `bun compile` still finds the typed file. `dist/cjs/package.json` says `"type": "commonjs"`, which is what makes Node.js read `cjs/index.js` as CommonJS.

## If you keep your own package.json

[`bun build --dts`](/bundler#dts) writes `index.js`, `index.d.ts` and `index.aot.ts` and leaves `package.json` to you. Add the `"bun-aot"` condition yourself. Without it, `bun compile` doesn't look for the typed file and silently compiles the package as JavaScript.

```json title="package.json" icon="file-json"
{
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "bun-aot": "./dist/index.aot.ts",
      "default": "./dist/index.js"
    }
  }
}
```

To add types to a package that you don't maintain, see [Typed versions of packages](/bundler/executables#typed-versions-of-packages).
