<Warning>Ahead-of-time compilation is experimental.</Warning>

A build with [`--aot`](/bundler/aot) never tells you that a line is slow. It compiles typed code to fast machine code, compiles the rest like plain JavaScript, and both behave the same. These commands show which is which.

| Question                                                     | Command                                            |
| ------------------------------------------------------------ | -------------------------------------------------- |
| Which lines of my program cost the most?                     | [`--aot-explain`](#the-most-expensive-lines)       |
| Which types and classes lost their layout, and why?          | [`--aot-warn=all`](#every-finding)                 |
| How do I keep a fixed problem from coming back?              | [`--aot-deny`](#fail-the-build)                    |
| Which type checks can fail when the program runs?            | [`--aot-explain=throws`](#checks-that-can-fail)    |
| What changes under `--aot` with the data my tests use?       | [`bun --aot-audit`](#run-with-your-own-data)       |
| What should I look at in my source before I build?           | [`bun lint --aot`](#lint-your-source)              |
| Which checks fail in production?                             | [`--aot-type-errors=log`](#log-in-production)      |
| How much of my program has types?                            | [the last line of a build](#the-summary-line)      |

Every flag that starts with `--aot-` works with `bun check --aot` and with `bun compile`. `bun check --aot` builds nothing, so it is the faster of the two.

## The example

This page runs every command on one program. The program adds up the value of a stock list.

```ts stock.ts icon="/icons/typescript.svg"
export interface Item {
  sku: string;
  price: number;
  quantity: number;
}

export class Stock {
  items: Item[] = [];

  add(item: Item): void {
    this.items.push(item);
  }

  value(): number {
    let sum = 0;
    for (const item of this.items) sum += item.price * item.quantity;
    return sum;
  }
}
```

```ts main.ts icon="/icons/typescript.svg"
import { Stock } from "./stock";

const stock = new Stock();
stock.add({ sku: "A-1", price: 2.5, quantity: 4 });

const saved: any = JSON.parse(await Bun.file("stock.json").text());
for (const item of saved) stock.add(item);

console.log(stock.value());
```

```json stock.json icon="file-json"
[{ "sku": "B-2", "price": "10", "quantity": 3 }]
```

It has two problems. `saved` is an `any`, so objects that the compiler knows nothing about reach `Stock`. And the `price` in `stock.json` is a string. Without `--aot` nobody notices, because JavaScript converts `"10"` when it multiplies.

```bash terminal icon="terminal"
bun main.ts
```

```txt
40
```

## The most expensive lines

Start here. `--aot-explain` leads everything that the compiler gives up back to the line that causes it, and prints the most expensive lines first.

```bash terminal icon="terminal"
bun check --aot ./main.ts --aot-explain
```

```txt
aot: 3 places where the compiler gives something up, 3 with a cost that can be counted. The most expensive first:

  1. main.ts:6:25 [can-throw]
     | const saved: any = JSON.parse(await Bun.file("stock.json").text());
     The value comes from JSON.parse(..).
     cost: 1 check that may copy the object into another layout in 1 function
     fix: validate the value once, where it enters the program, and build a typed value from it

  2. main.ts:7:27 [open-layout]
     | for (const item of saved) stock.add(item);
     A value of type 'any' or 'unknown' is assigned to it here.
     cost: 5 field accesses that test the object first in 2 functions
     types: 'Item'
     fix: give the value its type before it gets here, or copy its fields into a new object literal of the declared type
```

Both problems are in `main.ts`, and the cost is in `stock.ts`: one `any` makes every access to an `Item`, anywhere in the program, test the object first.

The third place is in Bun's own type declarations. Objects that Bun provides, such as the result of `Bun.file()`, have no layout that the compiler knows. You can't change that, and the report marks it `(in a dependency)`.

[What costs the most](/bundler/aot-debugging#what-costs-the-most) explains each line of a row. `--aot-explain=costs-json` prints the rows as JSON, for a script or a coding agent.

## Every finding

A rule reports one kind of loss. `--aot-warn=all` turns all of them on, and prints each finding with its reasons under it.

```bash terminal icon="terminal"
bun check --aot ./main.ts --aot-warn=all
```

```txt
main.ts(7,37): warning TS100028: This type check can fail when the program runs: the annotation: expected Item, may get any. [can-throw]
  main.ts(6,25): The value comes from JSON.parse(..).
  main.ts(7,37): To fix it: validate the value once, where it enters the program, and build a typed value from it.
stock.ts(1,18): warning TS100022: 'Item' can hold objects that typed code did not create, so every property access through it checks the object first. [open-layout]
  main.ts(7,27): A value of type 'any' or 'unknown' is assigned to it here.
```

In a terminal, Bun prints the source line above each finding instead.

The name in brackets is the rule. [Rules](/bundler/aot-debugging#rules) lists all ten.

### Fail the build

`--aot-deny` makes a rule an error. Bun writes no executable and exits with code `1`.

```bash terminal icon="terminal"
bun compile ./main.ts --aot-deny=open-layout
```

```txt
1 | export interface Item {
                     ^
error: TS100022: 'Item' can hold objects that typed code did not create, so every property access through it checks the object first. [open-layout]
    at /path/to/stock.ts:1:18

7 | for (const item of saved) stock.add(item);
                              ^
note: TS100040: A value of type 'any' or 'unknown' is assigned to it here.
   at /path/to/main.ts:7:27
```

Use it once a part of your program is clean, to keep it clean:

- for some files only: `--aot-deny=open-layout:src/server/**`
- for one class or type: a `// @aot-strict` comment above it
- for every build: `deny = ["open-layout"]` under `[aot]` in `bunfig.toml`
- in a large program that has findings already: `--aot-baseline`, which accepts what is there and fails when there is more

See [Code that loses its types](/bundler/aot-debugging#code-that-loses-its-types).

## Checks that can fail

Where a value without a type reaches a declared type, the executable checks it. [How `--aot` uses your types](/bundler/aot-types#where-untyped-values-meet-typed-code) says what each check does. `--aot-explain=throws` lists the checks that can fail, with where the value comes from.

```bash terminal icon="terminal"
bun check --aot ./main.ts --aot-explain=throws
```

```txt
[aot] type-check 4ff048784881 enter-argument main.ts:7:37 (module main.ts): the annotation: expected Item, may get any; warning; logged as e7b5fb1063d7; value from JSON.parse(..) at main.ts:6:25; fix: validate the value once, where it enters the program, and build a typed value from it
[aot] type-check bcfe102c3c34 copy-on-enter main.ts:7:37 (module main.ts): an object from untyped code may be copied here: writes go to the copy, and `===` with the original is false: expected Item, may get untyped object; warning; value from JSON.parse(..) at main.ts:6:25; fix: build the typed object from the external one yourself and use only the typed object: code that keeps the external object does not see later writes
```

[Reading a line](/bundler/aot-adoption#reading-a-line) explains the parts. `throws-json` prints one JSON object per line.

## Run with your own data

The reports above read your source. They can't know what is in `stock.json`. `--aot-audit` runs your program the way Bun always does, and writes a line to stderr wherever it would behave differently under `--aot`.

```bash terminal icon="terminal"
bun --aot-audit main.ts
```

```txt
[aot] type-error fd6a234f98bd read-property stock.ts:16:43 (value): expected number, got string; would-throw; count 1; from main.ts:9
40
```

The program still prints `40`. The line says that the executable throws at `stock.ts:16:43`, where `value()` reads `item.price`.

`bun test --aot-audit` does the same for your tests. See [Audit while you develop](/bundler/aot-adoption#1-audit-while-you-develop).

## Lint your source

`bun lint --aot` turns on six rules that find the code `--aot` affects.

```bash terminal icon="terminal"
bun lint --aot main.ts
```

```txt
6 | const saved: any = JSON.parse(await Bun.file("stock.json").text());
7 | for (const item of saved) stock.add(item);
                                        ^
warn: Under `--aot`, this `any` is checked against `Item` here when the program runs, and throws a `TypeError` if it does not match.  bun/aot-no-any-to-typed
   at main.ts:7:37

note: It comes from `item`, declared at line 7. Give it a type there, or validate it.
```

See [Before you compile with `--aot`](/lint#before-you-compile-with-aot).

## What the executable does

The audit was right.

```bash terminal icon="terminal"
bun compile ./main.ts && ./main
```

```txt
16 |     for (const item of this.items) sum += item.price * item.quantity;
                                               ^
TypeError: expected number, got string "10" (bun --aot: https://bun.com/docs/bundler/executables#ahead-of-time-compilation)
      at value (/$bunfs/root/stock.ts:16:43)
      at /$bunfs/root/main.ts:9:19
```

## Log in production

Your tests don't see all the data that production sees. `--aot-type-errors=log` builds an executable that writes a line to stderr for each check that fails. Where it can, it then goes on as plain JavaScript does. Here it can't, so it writes the line and throws.

```bash terminal icon="terminal"
bun compile --aot-type-errors=log ./main.ts && ./main
```

```txt
[aot] type-error fd6a234f98bd read-property stock.ts:16:43 (value): expected number, got string; threw; count 1; from main.ts:9
TypeError: expected number, got string "10" (bun --aot: https://bun.com/docs/bundler/executables#ahead-of-time-compilation)
```

The id, `fd6a234f98bd`, is the one that the audit printed for this place. The line names the kind of the value, `string`, and never the value itself.

[Log in production](/bundler/aot-adoption#3-log-in-production) says where such an executable keeps going, and how to send the lines to a file as JSON.

## Fix it

Every report gives the same advice: check the value where it enters the program, and build a typed object from it.

```ts main.ts icon="/icons/typescript.svg"
import { Stock, type Item } from "./stock";

function toItem(value: unknown): Item {
  if (typeof value !== "object" || value === null) throw new TypeError("stock.json: not an item");
  const { sku, price, quantity } = value as Record<string, unknown>;
  if (typeof sku !== "string") throw new TypeError("stock.json: sku must be a string");
  if (typeof price !== "number") throw new TypeError("stock.json: price must be a number");
  if (typeof quantity !== "number") throw new TypeError("stock.json: quantity must be a number");
  return { sku, price, quantity };
}

const stock = new Stock();
stock.add({ sku: "A-1", price: 2.5, quantity: 4 });

const saved: unknown = JSON.parse(await Bun.file("stock.json").text());
if (!Array.isArray(saved)) throw new TypeError("stock.json: not an array");
for (const value of saved) stock.add(toItem(value));

console.log(stock.value());
```

`toItem` returns an object literal, so typed code creates every `Item` in the program. The rules find nothing any more, and no check can fail.

```bash terminal icon="terminal"
bun check --aot ./main.ts --aot-warn=all --aot-explain=throws
```

```txt
[aot] type-check summary: 0 checks can fail when the program runs, 0 always fail; 1 more fails only if TypeScript code of the program itself produces a value of the wrong type (--aot-explain=throws-all lists it)
✓ No type errors in 2 files [44.16ms]
aot: 54.5% of reads typed, 0 of 2 types open, 0 classes without a layout, 0 packages and 0 files untyped (--aot-warn=all lists them)
```

The mistake in `stock.json` is now reported where the data enters, in your own words, with and without `--aot`.

```bash terminal icon="terminal"
bun compile ./main.ts --aot-deny=open-layout && ./main
```

```txt
TypeError: stock.json: price must be a number
      at toItem (/$bunfs/root/main.ts:7:44)
      at /$bunfs/root/main.ts:17:38
```

## The summary line

Every build, and every `bun check --aot`, ends with a line about the whole program.

```txt
aot: 54.5% of reads typed, 0 of 2 types open, 0 classes without a layout, 0 packages and 0 files untyped (--aot-warn=all lists them)
```

| Part                            | Counts                                                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `54.5% of reads typed`          | Property and element reads where the compiler knows the type of the value that the read produces             |
| `0 of 2 types open`             | Declared types that can also hold objects that typed code did not create. The rule is `open-layout`          |
| `0 classes without a layout`    | Classes whose instances are accessed by name. The rules are `lost-layout` and `untyped-base`                 |
| `0 packages and 0 files untyped` | JavaScript dependencies, and files of your own that are compiled without types                               |

Get the last three to zero in the code that has to be fast.

Treat the percentage as a rough guide. It counts reads of what Bun and JavaScript provide as untyped: `console.log`, `Bun.file`, `items.push`. The example read 75.0% before the fix and reads 54.5% after it, because `toItem` adds reads of a `Record<string, unknown>`. The compiler gives up less than before, and `--aot-explain` has nothing left to report in your files.

## More reports

| Flag                          | Reports                                                                                                                                              |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--aot-deny=interpreted`      | `eval`, `new Function` and `node:vm` in your program and its dependencies. The executable has no JIT, so Bun interprets that code                     |
| `--aot-deny=untyped-package`  | Each JavaScript file of your own. Each dependency that is JavaScript, and how much of the program it is: only a build reports those                  |
| `--aot-explain=rules-json`    | The findings of the rules, one JSON object per line                                                                                                  |
| `--aot-explain=runtime-use`   | The globals, `Bun` APIs and built-in modules that your program names. [`--compile-trim-runtime`](/bundler/executables#parts-your-program-does-not-use) goes by this list |
