<Warning>Ahead-of-time compilation is experimental.</Warning>

Without `--aot`, Bun removes your TypeScript types before it runs your program. With [`--aot`](/bundler/aot), the compiler reads them first and generates machine code that depends on them.

## What a type buys

```ts account.ts icon="/icons/typescript.svg"
class Account {
  constructor(
    public id: number,
    public balance: number,
  ) {}
}

function total(accounts: Account[]): number {
  let sum = 0;
  for (const account of accounts) sum += account.balance;
  return sum;
}

const accounts: Account[] = [];
for (let id = 0; id < 1000; id++) accounts.push(new Account(id, id % 100));
console.log(total(accounts));
```

```bash terminal icon="terminal"
bun check --aot ./account.ts --aot-explain
```

```txt
aot: there is no place where the compiler gives something up
```

- **A fixed layout.** Every `Account` has the same two fields at the same offsets. `account.balance` is a load from a known offset, with no lookup and no cache to check.
- **Unboxed numbers.** `balance` is stored as a raw 64-bit number, not as a boxed value.
- **Direct calls.** The compiler knows which function `total(accounts)` calls, so it can call that function directly or inline it.

Here is the same program as JavaScript.

```js account.js icon="/icons/javascript.svg"
class Account {
  constructor(id, balance) {
    this.id = id;
    this.balance = balance;
  }
}

function total(accounts) {
  let sum = 0;
  for (const account of accounts) sum += account.balance;
  return sum;
}

const accounts = [];
for (let id = 0; id < 1000; id++) accounts.push(new Account(id, id % 100));
console.log(total(accounts));
```

```bash terminal icon="terminal"
bun check --aot ./account.js --aot-explain
```

```txt
aot: 1 place where the compiler gives something up, 1 with a cost that can be counted. The most expensive first:

  1. account.js:1:1 [untyped-package]
     'account.js' is JavaScript, so it is compiled without types.
     cost: 3 reads by name, 2 stores by name, 3 calls by name in 3 functions (2 run only while the program starts)
     fix: turn the file into TypeScript
```

Both programs compile, and both print `49500`. In the second one, the compiled code looks up `balance` by its name each time the loop runs.

## Where untyped values meet typed code

TypeScript lets you call a value a `number` when it isn't one: through `any`, `as`, `!`, `JSON.parse` and declaration files. Without `--aot` nothing happens, because the types are gone when the program runs. With `--aot`, what happens depends on how the value got its type.

| You write                                                                                                      | If the value doesn't match                                    |
| -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| An `any` where a type is declared: `double(anyValue)`, `const n: number = anyValue`, `return anyValue`         | [A `TypeError`](#an-any-that-reaches-a-declared-type)          |
| `anyValue as number`, `as string`, `as boolean`                                                                | [The value is converted](#as-converts-between-primitives)      |
| A type for data from outside: `JSON.parse(text) as User`, `const user: User = JSON.parse(text)`                | [Nothing. The code is slower](#data-from-outside-keeps-its-shape) |
| An object literal with a type it lacks members of: `{ name: "x" } as Options`                                  | [A `TypeError` where a missing number is used](#a-literal-that-lacks-a-member) |
| `value!`                                                                                                       | [Nothing](#the-non-null-assertion-checks-nothing)              |

A [type error](/bundler/aot#type-errors-stop-the-build) stops the build, so none of this concerns code that TypeScript itself rejects.

### An `any` that reaches a declared type

```ts visits.ts icon="/icons/typescript.svg"
function double(n: number): number {
  return n * 2;
}

const body: any = JSON.parse('{"visits":"3"}');
console.log(double(body.visits));
```

```bash terminal icon="terminal"
bun visits.ts
```

```txt
6
```

```bash terminal icon="terminal"
bun compile ./visits.ts && ./visits
```

```txt
6 | console.log(double(body.visits));
                       ^
TypeError: expected number | undefined, got string "3" (bun --aot: https://bun.com/docs/bundler/executables#ahead-of-time-compilation)
      at /$bunfs/root/visits.ts:6:20
```

The compiled `double` takes a raw number, so a string can't enter it. The executable checks an `any` at the first place with a declared type that it reaches: a parameter, a variable, a property or a return type. A value that doesn't match throws a `TypeError`.

An object passes the check at the parameter. The executable then checks each property when your code reads it.

```ts label.ts icon="/icons/typescript.svg"
interface User {
  id: number;
  name: string;
}

function label(user: User): string {
  return user.name + " #" + user.id;
}

const body: any = JSON.parse('{"id":"7","name":"Ada"}');
console.log(label(body));
```

```bash terminal icon="terminal"
bun compile ./label.ts && ./label
```

```txt
TypeError: expected number, got string "7" (bun --aot: https://bun.com/docs/bundler/executables#ahead-of-time-compilation)
      at label (/$bunfs/root/label.ts:7:29)
      at /$bunfs/root/label.ts:11:13
```

| The property                                | Reading it                   |
| ------------------------------------------- | ---------------------------- |
| has a value of another type                 | throws a `TypeError`         |
| is a `number` or a `boolean`, and is missing | throws a `TypeError`         |
| is a `string` or an object, and is missing  | gives `undefined`            |
| isn't declared in the type                 | works as in plain JavaScript |

To fix it, narrow the value before it reaches the type. TypeScript doesn't narrow a property of an `any`, so give the value a name of type `unknown` first.

```ts
const body: any = JSON.parse('{"visits":"3"}');
console.log(double(body.visits)); // [!code --]
const visits: unknown = body.visits; // [!code ++]
if (typeof visits !== "number") throw new Error("visits must be a number"); // [!code ++]
console.log(double(visits)); // [!code ++]
```

[`--aot-explain=throws`](/bundler/aot-reports#checks-that-can-fail) lists every such check in your program. [`bun --aot-audit`](/bundler/aot-reports#run-with-your-own-data) logs the ones that fail while your program runs as usual. `--aot-type-errors=log` builds an executable that [logs and keeps going where it can](/bundler/aot-adoption#3-log-in-production).

### `as` converts between primitives

```ts page.ts icon="/icons/typescript.svg"
const query: any = { page: "2" };
const page = query.page as number;
console.log(typeof page, page + 1);
```

```bash terminal icon="terminal"
bun page.ts
```

```txt
string 21
```

```bash terminal icon="terminal"
bun compile ./page.ts && ./page
```

```txt
number 3
```

After the cast, the value is what the cast says.

| Cast         | Converts like    | Examples                                      |
| ------------ | ---------------- | --------------------------------------------- |
| `as number`  | `Number(value)`  | `"12"` to `12`, `""` to `0`, `"twelve"` to `NaN` |
| `as string`  | `String(value)`  | `7` to `"7"`                                  |
| `as boolean` | `Boolean(value)` | `"yes"` to `true`, `0` to `false`             |

`null`, `undefined`, objects and arrays pass through every cast unchanged.

Write the conversion out, and the program does the same with and without `--aot`.

```ts
const page = query.page as number; // [!code --]
const page = Number(query.page); // [!code ++]
```

### Data from outside keeps its shape

An object from `JSON.parse`, `response.json()`, `structuredClone` or a function that only has a declaration (`.d.ts`) is data. When you give it a type where you receive it, with `as` or with an annotation, the compiler takes the type as a prediction. An object that doesn't match is never refused and never changed.

```ts user.ts icon="/icons/typescript.svg"
interface User {
  id: number;
  name: string;
}

const user = JSON.parse('{"id":"7"}') as User;
console.log(typeof user.id, user.id, user.name);
```

```bash terminal icon="terminal"
bun compile ./user.ts && ./user
```

```txt
string 7 undefined
```

`bun user.ts` prints the same.

You pay for that in speed. The compiler can no longer rely on the shape of a `User`, of the types inside it, or of the types its values are assigned to.

```bash terminal icon="terminal"
bun check --aot ./user.ts --aot-warn=external-type
```

```txt
user.ts(1,11): warning TS100029: 'User' describes data from outside the type system, so the compiler cannot rely on its shape: every property access through it is looked up by name or checked when the program runs. [external-type]
  user.ts(6,14): A value from outside the type system is used as 'User' here.
```

To keep `User` typed, check the data where it enters and build a new object from it. [Fix it](/bundler/aot-reports#fix-it) shows how.

Store the same data in a variable of type `any` first, and it is an `any` like any other: [the section above](#an-any-that-reaches-a-declared-type) applies.

### A literal that lacks a member

```ts options.ts icon="/icons/typescript.svg"
interface Options {
  name: string;
  times: number;
}

function twice(options: Options): number {
  return options.times * 2;
}

console.log(twice({ name: "x" } as Options));
```

```bash terminal icon="terminal"
bun compile ./options.ts && ./options
```

```txt
TypeError: expected number, got undefined (bun --aot: https://bun.com/docs/bundler/executables#ahead-of-time-compilation)
      at twice (/$bunfs/root/options.ts:7:10)
```

`bun options.ts` prints `NaN`. The cast itself doesn't throw. The `TypeError` comes where typed code uses a `number` or a `boolean` that the literal lacks. A missing `string` or object reads `undefined`.

Tests often build partial objects this way. The lint rule [`bun/aot-cast-lacks-member`](/lint/rules/bun/aot-cast-lacks-member) finds such casts.

### The non-null assertion checks nothing

```ts port.ts icon="/icons/typescript.svg"
const ports = new Map<string, number>();
const port: number = ports.get("http")!;
console.log(port);
```

```bash terminal icon="terminal"
bun compile ./port.ts && ./port
```

```txt
undefined
```

`bun port.ts` prints the same.

## Patterns that lose types

The compiler never stops because it can't use a type. It compiles that part like plain JavaScript. Each of these patterns has a [rule](/bundler/aot-debugging#rules) that reports it.

| Pattern                                                             | What it costs                                                          | Rule              |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------- | ----------------- |
| `JSON.parse(text) as Config`                                        | `Config` and every type inside it are looked up by name                | `external-type`   |
| An `any` that is returned or passed as a declared type              | Every access through that type tests the object first                  | `open-layout`     |
| `class HttpError extends Error`, or a base class from JavaScript    | The class has no fixed layout                                          | `untyped-base`    |
| A member whose name is computed: `[hook]() {}`                      | Declared fields of the class are looked up by name                     | `lost-layout`     |
| `Object.freeze(value)` where `value` is an `any`                    | Every store to a field, in the whole program, tests for a frozen object | `reshaped-layout` |
| A `.js` file or a JavaScript package                                | All of its code is compiled without types                              | `untyped-package` |
| `eval`, `new Function`, `node:vm`                                   | Bun interprets that code                                               | `interpreted`     |

### Build the object in typed code

```ts point.ts icon="/icons/typescript.svg"
interface Point {
  x: number;
  y: number;
}

function fromPlugin(value: any): Point {
  return value;
}

const origin: Point = { x: 0, y: 0 };
console.log(origin.x + fromPlugin({ x: 3, y: 4 }).y);
```

```bash terminal icon="terminal"
bun check --aot ./point.ts --aot-warn=open-layout
```

```txt
point.ts(1,11): warning TS100022: 'Point' can hold objects that typed code did not create, so every property access through it checks the object first. [open-layout]
  point.ts(7,10): A value of type 'any' or 'unknown' is assigned to it here.
```

Even `origin.x` pays, though `origin` never comes near the `any`. Return a new object literal instead, and typed code creates every `Point`.

```ts
function fromPlugin(value: any): Point {
  return value; // [!code --]
  return { x: Number(value.x), y: Number(value.y) }; // [!code ++]
}
```

### Say what you freeze

```ts settings.ts icon="/icons/typescript.svg"
class Settings {
  retries = 3;
}

function lock(value: any): void {
  Object.freeze(value);
}

const settings = new Settings();
lock(settings);
console.log(settings.retries);
```

```bash terminal icon="terminal"
bun check --aot ./settings.ts --aot-warn=reshaped-layout
```

```txt
settings.ts(6,17): warning TS100080: This can freeze any object of the program, because the compiler does not know what it is applied to: every store to a field first tests whether the object is frozen. [reshaped-layout]
```

The same goes for `Object.seal`, `Object.preventExtensions` and `Object.setPrototypeOf`. Give the parameter a type.

```ts
function lock(value: any): void { // [!code --]
function lock(value: Settings): void { // [!code ++]
```

### Subclasses of built-in classes

```ts http-error.ts icon="/icons/typescript.svg"
class HttpError extends Error {
  status: number;
  constructor(status: number, message: string) {
    super(message);
    this.status = status;
  }
}

console.log(new HttpError(404, "Not found").status);
```

```bash terminal icon="terminal"
bun check --aot ./http-error.ts --aot-warn=untyped-base
```

```txt
http-error.ts(1,7): warning TS100027: Class 'HttpError' extends a class from outside typed code, so it has no fixed layout and its instances are compiled as untyped objects. [untyped-base]
  http-error.ts(1,25): This base class is a built-in or comes from JavaScript.
```

An error class is rarely in a hot loop, so leave it as it is. `// @aot-allow untyped-base` above the class turns the rule off for it. For a class that you create by the million, hold the built-in object in a field instead of extending it.

## More that types can do

- [`int32`](/bundler/executables#32-bit-integers) is a 32-bit integer that the build proves and the executable never checks. It halves the size of a number field.
- [Typed versions of packages](/bundler/executables#typed-versions-of-packages) give a JavaScript package its types back, without changing its code.
- An array type means an ordinary array. [Every difference](/bundler/executables#ahead-of-time-compilation) says what that excludes.
