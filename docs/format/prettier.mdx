---
title: "Migrate from Prettier"
description: "Replace Prettier with bun format: same configuration, same flags, same output"
---

[`bun format`](/runtime/format) reads your Prettier configuration and prints what Prettier 3 prints. Most projects only change the command.

<Steps>
  <Step title="Change the scripts">

    ```json package.json icon="file-json"
    {
      "scripts": {
        "format": "bun format",
        "format:check": "bun format --check"
      }
    }
    ```

    Do this first. While the `format` script says `prettier`, `bun format` [runs that script](/runtime/format#notes).

  </Step>
  <Step title="See what Bun will do">

    ```bash terminal icon="terminal"
    bun format --doctor
    ```

    `--doctor` reads your configuration and changes nothing.

  </Step>
  <Step title="Check that nothing changes">

    ```bash terminal icon="terminal"
    bun format --check
    ```

    ```txt
    $ bun format --check
    Checking formatting...
    All matched files use Prettier code style!
    ```

  </Step>
  <Step title="Change CI and Git hooks">

    Replace `prettier`, `npx prettier`, and `bunx prettier` with `bun format`. You can drop lint-staged for [`bun format --staged`](/runtime/format#format-before-you-commit).

  </Step>
  <Step title="Remove the packages">

    ```bash terminal icon="terminal"
    bun remove prettier
    ```

    Keep `prettier` if `--doctor` says it is still needed, or if your editor's Prettier extension uses it.

  </Step>
</Steps>

| Instead of                       | Run                                |
| -------------------------------- | ---------------------------------- |
| `prettier --write .`             | `bun format`                       |
| `prettier --write src test`      | `bun format src test`              |
| `prettier --check .`             | `bun format --check`               |
| `prettier -l .`                  | `bun format -l`                    |
| `prettier --stdin-filepath a.ts` | `bun format --stdin-filepath a.ts` |

## What Bun reads

- **Configuration files**: `.prettierrc` in JSON, YAML, TOML, JavaScript, or TypeScript, `prettier.config.*`, and `"prettier"` in `package.json`. Each file uses the nearest one, and `overrides` work.
- **`.editorconfig`**, `.prettierignore`, and `.gitignore`.
- **Comments**: `// prettier-ignore`, `@format`, `@prettier`, `@noformat`, `@noprettier`.
- **Flags**: every flag of Prettier 3 except `--file-info` and `--support-info`.

With a Prettier configuration, `--check` and `--list-different` print what Prettier prints, so scripts that read the output keep working.

A `[format]` section in [`bunfig.toml`](/runtime/bunfig#formatter) overrides the Prettier configuration, like a flag does.

## Plugins

Bun does not load Prettier plugins. What happens depends on the plugin.

- **Built in**: `@trivago/prettier-plugin-sort-imports`, `@ianvs/prettier-plugin-sort-imports`, and `prettier-plugin-organize-imports`, with every option. Keep the name in `plugins`. You can uninstall the package.
- **Sent to your installed Prettier**: the files of a plugin that adds a language, like `prettier-plugin-svelte` or `prettier-plugin-astro`. Keep `prettier` and every plugin in `plugins` installed.
- **Not supported**: any other plugin. Bun skips the files that configuration covers and exits with `2`.

`--allow-unsupported` formats the skipped files without the plugin, and turns the error into a warning.

Files that go to your installed Prettier are formatted at Prettier's speed. If `prettier` or the plugin is missing, Bun leaves those files alone, formats the rest, and exits with `2`.

## What differs

If `bun format` prints something Prettier 3 does not, that is a bug. [Open an issue](https://github.com/oven-sh/bun/issues) with the code.

These differences are on purpose:

- **It writes by default.** `--write` is accepted and changes nothing.
- **No arguments means the current directory.**
- **It only prints the files it changed**, then a summary on stderr.
- **An unknown flag is an error.** Prettier warns and goes on.
- **Exit code `2` means something went wrong**, like a syntax error or a skipped file. Prettier uses `1` for some of these.
- **It never damages a file.** Before writing, Bun checks that the result is the same program or document. If not, it leaves the file alone and reports it. This covers a few inputs where Prettier drops code, such as `<!DOCTYPE html>` in a Handlebars template.
- **Bytes that are not UTF-8 stay as they are.** Prettier replaces them.
- **It does not write through a symlink that leaves the repository.**
- **`--cache` has no effect.** Every run formats every file.
