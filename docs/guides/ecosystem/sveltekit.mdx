[SvelteKit](https://svelte.dev/docs/kit) is a framework for building full-stack web applications with [Svelte](https://svelte.dev/). It supports server-side rendering (SSR), static site generation (SSG), client-side rendering (CSR), and API routes, and can also be compiled into standalone executables with the Bun adapter.

---

<Steps>
  <Step title="Create a new SvelteKit app">
    Use the official Svelte CLI (`sv`) to scaffold a new SvelteKit project and select **bun** as the package manager:

    ```sh terminal icon="terminal"
    bunx --bun sv create my-app
    ```

    Follow the interactive prompts to choose a template (such as *SvelteKit demo* or *Minimal skeleton*) and add TypeScript support:

    ```txt
    ┌  Welcome to the Svelte CLI!
    │
    ◇  Which template would you like?
    │  SvelteKit minimal
    │
    ◇  Add type checking with Typescript?
    │  Yes, using Typescript syntax
    │
    ◆  Project created
    │
    ◇  What would you like to add to your project?
    │  none
    │
    ◇  Which package manager do you want to install dependencies with?
    │  bun
    │
    ◇  Successfully installed dependencies
    └  You're all set!
    ```

  </Step>
  <Step title="Start the dev server">
    Change to the project directory and start the Vite dev server with Bun runtime:

    ```sh terminal icon="terminal"
    cd my-app
    bun --bun run dev
    ```

    ```txt
      VITE ready in 350 ms

      ➜  Local:   http://localhost:5173/
      ➜  Network: use --host to expose
      ➜  press h + enter to show help
    ```

    Open [`http://localhost:5173`](http://localhost:5173/) in your browser. Editing files in `src/routes/+page.svelte` will hot-reload automatically in your browser.

    <Note>
      The `--bun` flag forces Vite and its dependency graph to execute directly under Bun's runtime rather than Node.js.
    </Note>

  </Step>
  <Step title="Update scripts in package.json">
    Prefix the CLI commands in your `package.json` scripts with `bun --bun` so Bun executes Vite for development, building, and previews:

    ```json package.json icon="file-json"
    {
      "scripts": {
        "dev": "bun --bun vite dev", // [!code ++]
        "build": "bun --bun vite build", // [!code ++]
        "preview": "bun --bun vite preview" // [!code ++]
      }
    }
    ```

  </Step>
</Steps>

## Production Hosting

SvelteKit uses adapters to transform your application into production artifacts tailored to specific target environments.

Starting with **SvelteKit 3**, the framework includes an **official Bun adapter** (`@sveltejs/adapter-bun`). For SvelteKit 2.4+ in the 2.x series, use the community-maintained `svelte-adapter-bun`.

<Tabs>
  <Tab title="Official Adapter (SvelteKit 3+)">
    <Note>
      The official [`@sveltejs/adapter-bun`](https://svelte.dev/docs/kit/adapter-bun) adapter was introduced in SvelteKit 3. It requires **Bun 1.4 or newer** and builds your application into a high-performance standalone Bun server utilizing `Bun.serve` and `Bun.file`.
    </Note>

    <Steps>
      <Step title="Install the official Bun adapter">
        Add `@sveltejs/adapter-bun` to your development dependencies:

        ```sh terminal icon="terminal"
        bun add -D @sveltejs/adapter-bun
        ```

      </Step>
      <Step title={<span>Configure the adapter in <code>vite.config.ts</code></span>}>
        In SvelteKit 3, project configuration is declared inside `vite.config.ts` (or `vite.config.js`). Replace `@sveltejs/adapter-auto` with `@sveltejs/adapter-bun`:

        ```ts vite.config.ts icon="/icons/typescript.svg"
        import adapter from "@sveltejs/adapter-auto"; // [!code --]
        import adapter from "@sveltejs/adapter-bun"; // [!code ++]
        import { sveltekit } from "@sveltejs/kit/vite";
        import { defineConfig } from "vite";

        export default defineConfig({
          plugins: [
            sveltekit({
              adapter: adapter(), // [!code ++]
            }),
          ],
        });
        ```

      </Step>
      <Step title="Build the production bundle">
        Run the build command:

        ```sh terminal icon="terminal"
        bun --bun run build
        ```

        This outputs the compiled server and client assets to the `build/` directory.

        <Note>
          Deploying an uncompiled server requires `build/`, `package.json`, `bun.lock`, and production dependencies installed on the host with `bun install --production --frozen-lockfile`. To deploy without `node_modules`, compile into a [standalone executable](#standalone-executable-single-file-binary) instead.
        </Note>
      </Step>
      <Step title="Start the production server">
        Start your standalone Bun server:

        ```sh terminal icon="terminal"
        bun ./build/index.js
        ```

        ```txt
        Listening on http://0.0.0.0:3000/
        ```

      </Step>
    </Steps>

    ### Standalone Executable (Single-File Binary)

    One of the major advantages of `@sveltejs/adapter-bun` is native support for compiling your SvelteKit server, client assets, and prerendered pages into a **single standalone executable binary** using Bun's built-in bundler:

    ```ts vite.config.ts icon="/icons/typescript.svg"
    import adapter from "@sveltejs/adapter-bun";
    import { sveltekit } from "@sveltejs/kit/vite";
    import { defineConfig } from "vite";

    export default defineConfig({
      plugins: [
        sveltekit({
          adapter: adapter({
            buildOptions: {
              compile: true, // [!code ++]
              minify: true, // [!code ++]
              bytecode: true, // [!code ++]
            },
          }),
        }),
      ],
    });
    ```

    Build and run the compiled binary directly without requiring Bun or `node_modules` installed on the target machine:

    ```sh terminal icon="terminal"
    bun --bun run build
    ./build/server
    ```

    You can also cross-compile for another platform target (e.g. `linux-x64` or `darwin-arm64`) using `compile: { target: "bun-linux-x64", outfile: "my-app" }`.

    ### Environment Variables

    Bun loads `.env` files automatically. Configure the host and port using `HOST` and `PORT`:

    ```sh terminal icon="terminal"
    HOST=0.0.0.0 PORT=8080 bun ./build/index.js
    ```

    For advanced runtime options (such as Unix domain sockets, payload body limits, and idle timeouts), refer to the [official `@sveltejs/adapter-bun` documentation](https://svelte.dev/docs/kit/adapter-bun#Environment-variables).

  </Tab>

  <Tab title="Legacy Projects (SvelteKit 2.4–2.x)">
    <Warning>
      Use this adapter only if your project runs **SvelteKit 2.4 or later in the 2.x series**. For SvelteKit 3+, use the official `@sveltejs/adapter-bun` described in the first tab.
    </Warning>

    For SvelteKit 2.x projects prior to SvelteKit 3, the community-maintained [`svelte-adapter-bun`](https://github.com/gornostay25/svelte-adapter-bun) package is used.

    <Steps>
      <Step title="Install community adapter">
        Install `svelte-adapter-bun`:

        ```sh terminal icon="terminal"
        bun add -D svelte-adapter-bun
        ```

      </Step>
      <Step title={<span>Configure in <code>svelte.config.js</code></span>}>
        In SvelteKit 2, adapter settings reside in `svelte.config.js`:

        ```js svelte.config.js icon="/icons/javascript.svg"
        import adapter from "svelte-adapter-bun"; // [!code ++]

        export default {
          kit: {
            adapter: adapter(), // [!code ++]
          },
        };
        ```

        *(Note: If you migrated to SvelteKit 2.62+ with `vite.config.ts`, you can configure the adapter inside `sveltekit({ adapter: adapter() })`).*

      </Step>
      <Step title="Build and run">
        Build your production bundle and start the server:

        ```sh terminal icon="terminal"
        bun --bun run build
        bun ./build/index.js
        ```

      </Step>
    </Steps>

  </Tab>
</Tabs>
