---
title: "bun:test/no-interpolation-in-snapshots"
description: "Disallow `${}` in inline snapshots"
---

An inline snapshot is text that the test runner writes into your file and rewrites when you update snapshots. With `${}` in it, the expected text is computed while the test runs, so the runner cannot write it back, and the snapshot no longer shows what the output looks like.

The rule checks the template literals passed to `toMatchInlineSnapshot` and `toThrowErrorMatchingInlineSnapshot`.

## Examples

Reported:

{/* bad */}

```ts
import { expect, test } from "bun:test";

test("creates a user", () => {
  const user = createUser("Ada");
  expect(user).toMatchInlineSnapshot(`
    {
      "id": ${user.id},
      "name": "Ada",
    }
  `);
});
```

{/* bad */}

```ts
import { expect, test } from "bun:test";

test("rejects a missing file", () => {
  expect(() => load(path)).toThrowErrorMatchingInlineSnapshot(`"cannot read ${path}"`);
});
```

Not reported. For a value that changes from run to run, pass a property matcher as the first argument and keep the snapshot plain text:

{/* good */}

```ts
import { expect, test } from "bun:test";

test("creates a user", () => {
  const user = createUser("Ada");
  expect(user).toMatchInlineSnapshot(
    { id: expect.any(Number) },
    `
    {
      "id": Any<Number>,
      "name": "Ada",
    }
  `,
  );
});
```
