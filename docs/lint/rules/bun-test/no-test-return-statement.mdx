---
title: "bun:test/no-test-return-statement"
description: "Disallow `return expect(..)` in a test"
---

`bun test` ignores what a test returns, unless it is a promise to wait for. A matcher such as `toBe()` returns nothing, so the `return` in `return expect(total).toBe(3)` does nothing. It only makes the reader wonder what the value is for.

The rule reports `return expect(..).matcher(..)` in the callback of `test` or `it`, and in a function declaration that is passed to one of them.

## Examples

Reported:

{/* bad */}

```ts
import { expect, test } from "bun:test";

test("adds the prices", () => {
  const total = sum([1, 2]);
  return expect(total).toBe(3);
});
```

{/* bad */}

```ts
import { expect, test } from "bun:test";

test("adds the prices", addsThePrices);

function addsThePrices() {
  return expect(sum([1, 2])).toBe(3);
}
```

Not reported:

{/* good */}

```ts
import { expect, test } from "bun:test";

test("adds the prices", () => {
  const total = sum([1, 2]);
  expect(total).toBe(3);
});
```

Other `return` statements are not reported. That includes a returned promise, which `bun test` waits for:

{/* good */}

```ts
import { expect, test } from "bun:test";

test("loads the prices", () => {
  return expect(loadPrices()).resolves.toEqual([1, 2]);
});

test("loads the taxes", () => {
  return loadTaxes().then(taxes => {
    expect(taxes).toEqual([0.2]);
  });
});
```
