---
title: "bun:test/prefer-expect-type-of"
description: "Require `toBeTypeOf` instead of `expect(typeof value).toBe(...)`"
---

`expect(typeof value).toBe("string")` hands `expect` only the name of the type. When the test fails, the output compares `"number"` with `"string"` and does not show the value. `expect(value).toBeTypeOf("string")` shows it.

The rule reports `typeof` inside `expect` with `toBe` or `toEqual`, also after `.not`.

`--fix` rewrites the assertion.

## Examples

Reported:

{/* bad {"count": 2} */}

```ts
import { expect, test } from "bun:test";

test("the user has a name", () => {
  expect(typeof user.name).toBe("string");
  expect(typeof user.save).not.toEqual("undefined");
});
```

Not reported:

{/* good */}

```ts
import { expect, test } from "bun:test";

test("the user has a name", () => {
  expect(user.name).toBeTypeOf("string");
  expect(user.save).not.toBeTypeOf("undefined");
});
```
