---
title: "bun:test/prefer-mock-return-shorthand"
description: "Require `mockReturnValue()` for a mock that only returns a value"
---

`mockImplementation(() => value)` wraps a value in a function that does nothing but return it. `mockReturnValue(value)` says the same with less to read. The same goes for `mockImplementationOnce()` and `mockReturnValueOnce()`.

`--fix` rewrites the call. If the returned value contains a function call or `new`, the mock is reported but not rewritten, because `mockReturnValue(createUser())` runs `createUser()` once instead of on every call.

## Examples

Reported:

{/* bad {"count": 2} */}

```ts
import { mock } from "bun:test";

const getPort = mock().mockImplementation(() => 3000);

const getUser = mock().mockImplementationOnce(() => {
  return { name: "Ada" };
});
```

Not reported:

{/* good */}

```ts
import { mock } from "bun:test";

const getPort = mock().mockReturnValue(3000);

const getUser = mock().mockReturnValueOnce({ name: "Ada" });
```

A function that takes parameters, is `async`, does more than return, or returns a variable that can change needs `mockImplementation()`, so it is not reported:

{/* good */}

```ts
import { mock } from "bun:test";

let visits = 0;

const double = mock().mockImplementation((n: number) => n * 2);
const load = mock().mockImplementation(async () => "done");
const countVisits = mock().mockImplementation(() => visits);
const nextVisit = mock().mockImplementation(() => {
  visits += 1;
  return "ok";
});
```

## When not to use it

`mockReturnValue({ name: "Ada" })` returns the same object on every call, and `mockImplementation(() => ({ name: "Ada" }))` returns a new one. If the code under test changes what the mock returns, keep the function and disable the rule on that line.
