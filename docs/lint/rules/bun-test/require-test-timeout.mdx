---
title: "bun:test/require-test-timeout"
description: "Require every test to set a timeout"
---

A test without a timeout of its own gets the default, 5 seconds unless you run `bun test --timeout`. That is a long wait for a unit test that hangs, and too short for a test that starts a server, which then fails now and then on a slow machine. This rule makes you choose the limit for each test.

You can give the timeout as a number after the test function, as `{ timeout }` in the options, or for all the tests below with `setDefaultTimeout()` or `jest.setTimeout()`.

Tests marked `.skip` or `.todo` are not checked.

## Examples

Reported:

{/* bad */}

```ts
import { expect, test } from "bun:test";

test("loads the report", async () => {
  expect(await loadReport()).toBeDefined();
});
```

Not reported:

{/* good */}

```ts
import { expect, test } from "bun:test";

test("loads the report", async () => {
  expect(await loadReport()).toBeDefined();
}, 10_000);

test(
  "exports the report",
  async () => {
    expect(await exportReport()).toBeDefined();
  },
  { timeout: 30_000 },
);
```

{/* good */}

```ts
import { expect, setDefaultTimeout, test } from "bun:test";

setDefaultTimeout(10_000);

test("loads the report", async () => {
  expect(await loadReport()).toBeDefined();
});
```

The timeout has to be written as a number that is not negative. A variable is reported, and so are options without `timeout`:

{/* bad {"count": 2} */}

```ts
import { test } from "bun:test";

const SLOW = 30_000;

test(
  "exports the report",
  async () => {
    await exportReport();
  },
  SLOW,
);

test(
  "prints the report",
  async () => {
    await printReport();
  },
  { retry: 2 },
);
```

## When not to use it

If the default timeout, or the one you pass to `bun test --timeout`, suits all your tests, a number on each test adds nothing.
