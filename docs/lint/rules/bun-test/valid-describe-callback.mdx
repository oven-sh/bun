---
title: "bun:test/valid-describe-callback"
description: "Require `describe` to get a callback that is a function with no parameters"
---

`bun test` calls the callback of `describe` to collect the tests inside it. Without a callback there is nothing to collect. The callback is not a test, so it has no `done` to call at the end.

The rule reports a `describe` with no callback, a callback that is not a function, and a callback with parameters. An `async` callback is allowed, because `bun test` waits for the promise it returns.

This rule is on by default in files that import from `"bun:test"`.

## Examples

Reported:

{/* bad */}

```ts
import { describe, test } from "bun:test";

describe("cart", done => {
  test("adds an item", () => {});
  done();
});
```

{/* bad {"count": 2} */}

```ts
import { describe } from "bun:test";

describe("cart");

describe("checkout", "adds the tax");
```

Not reported:

{/* good */}

```ts
import { describe, expect, test } from "bun:test";

describe("cart", () => {
  test("adds an item", () => {
    expect(add(item).length).toBe(1);
  });
});

describe("checkout", async () => {
  const rates = await loadRates();

  test("adds the tax", () => {
    expect(total(100, rates)).toBe(108);
  });
});
```

`describe.todo` and `describe.skip` need only a title. A callback that you pass by name is taken to be a function:

{/* good */}

```ts
import { describe } from "bun:test";
import { cartTests } from "./shared";

describe.todo("refunds");
describe.skip("exports");

describe("cart", cartTests);
```

The callback of `describe.each` gets the values of a row, so it can have parameters:

{/* good */}

```ts
import { describe, expect, test } from "bun:test";

describe.each([1, 2, 3])("cart with %i items", count => {
  test("counts them", () => {
    expect(fill(count).length).toBe(count);
  });
});
```
