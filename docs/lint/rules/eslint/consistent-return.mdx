---
title: "consistent-return"
description: "Require every `return` in a function to have a value, or none of them"
---

A function that returns a value on one path and nothing on another sometimes gives its caller `undefined`. That can be on purpose, but often a value was forgotten, or the function runs off its end by accident.

The first `return` of the function sets what is expected. Every `return` that differs is reported, and so is a function that returns a value and can also run to its end.

## Examples

Reported:

{/* bad */}

```js
function findUser(id) {
  if (!id) {
    return;
  }
  return users.get(id);
}
```

{/* bad */}

```js
function discount(order) {
  if (order.total > 100) {
    return 10;
  }
}
```

Not reported:

{/* good */}

```js
function findUser(id) {
  if (!id) {
    return undefined;
  }
  return users.get(id);
}

function discount(order) {
  if (order.total > 100) {
    return 10;
  }
  return 0;
}

function log(message) {
  if (!enabled) {
    return;
  }
  console.log(message);
}
```

## Options

| Option                        | Default | What it does                                                          |
| ----------------------------- | ------- | --------------------------------------------------------------------- |
| `treatUndefinedAsUnspecified` | `false` | Treat `return undefined;` and `return void 0;` the same as `return;`. |

{/* bad {"options": [{"treatUndefinedAsUnspecified": true}]} */}

```js
function findUser(id) {
  if (!id) {
    return undefined;
  }
  return users.get(id);
}
```

## When not to use it

In TypeScript, the compiler option `noImplicitReturns` finds the same mistakes and knows the return type of the function.
