---
title: "eqeqeq"
description: "Require `===` and `!==` instead of `==` and `!=`"
---

`==` and `!=` convert their operands before comparing them, so `"" == 0` and `[] == false` are both `true`. `===` and `!==` compare without converting.

## Examples

Reported:

{/* bad */}

```js
if (count == 0) {
  reset();
}
```

Not reported:

{/* good */}

```js
if (count === 0) {
  reset();
}
```

## Options

```toml bunfig.toml
[lint.rules]
eqeqeq = ["error", "smart"]
```

| Option               | What it does                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| `"always"` (default) | Report every `==` and `!=`.                                                                         |
| `"smart"`            | Allow `==` when comparing with `null`, comparing two literals, or comparing the result of `typeof`. |

With `"always"`, a second option decides what happens with `null`: `{ "null": "always" }` (default) reports `x == null`, `"ignore"` allows it, and `"never"` reports `x === null` instead.

With `"smart"`, this is allowed, because `== null` is a common way to test for both `null` and `undefined`:

{/* good {"options": ["smart"]} */}

```js
if (value == null) {
  value = fallback;
}
```

And this is still reported:

{/* bad {"options": ["smart"]} */}

```js
if (value == other) {
  merge(value, other);
}
```
