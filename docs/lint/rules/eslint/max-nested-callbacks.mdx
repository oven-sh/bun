---
title: "max-nested-callbacks"
description: "Enforce a maximum depth that callbacks can be nested"
---

Callbacks inside callbacks push the code to the right, and each level needs its own error handling. This rule reports a callback that is nested deeper than the maximum, which is 10 by default.

A callback is a function expression or an arrow function that is passed as an argument to a call.

## Examples

With a maximum of 2, the third callback is reported:

{/* bad {"options": [2]} */}

```js
readConfig(config => {
  connect(config, db => {
    db.query("select 1", rows => {
      console.log(rows);
    });
  });
});
```

Not reported:

{/* good {"options": [2]} */}

```js
const config = await readConfig();
const db = await connect(config);
const rows = await db.query("select 1");
console.log(rows);
```

## Options

```toml bunfig.toml
[lint.rules]
max-nested-callbacks = ["error", 3]
```

| Option                          | Default | What it does                                                                  |
| ------------------------------- | ------- | ----------------------------------------------------------------------------- |
| `max`                           | `10`    | The deepest level that is allowed. `maximum` is an older name for it.         |
| `checkConstructorCallCallbacks` | `false` | Also count a function that is passed to `new`, as in `new Promise(() => {})`. |

A number alone is short for `{ "max": number }`.

By default the function passed to `new Promise` is not a level:

{/* good {"options": [1]} */}

```js
button.addEventListener("click", () => {
  return new Promise(resolve => {
    setTimeout(resolve, 100);
  });
});
```

With `checkConstructorCallCallbacks` it is the second level:

{/* bad {"options": [{"max": 1, "checkConstructorCallCallbacks": true}]} */}

```js
button.addEventListener("click", () => {
  return new Promise(resolve => {
    setTimeout(resolve, 100);
  });
});
```
