---
title: "no-const-assign"
description: "Disallow reassigning `const`, `using` and `await using` variables"
---

Assigning to a variable declared with `const`, `using` or `await using` throws a `TypeError` when that line runs. The rule catches it earlier, including in branches your tests never reach.

`=`, compound assignments such as `+=`, `++` and `--` all count.

This rule is on by default in JavaScript files. It is off in TypeScript files, where TypeScript reports the same mistake.

## Examples

Reported:

{/* bad {"count": 2} */}

```js
const retries = 0;

function onFailure() {
  retries += 1;
}

function reset() {
  retries = 0;
}
```

Not reported:

{/* good */}

```js
let retries = 0;

function onFailure() {
  retries += 1;
}
```

`const` protects the variable, not the value it holds. Changing a property is fine:

{/* good */}

```js
const settings = { theme: "light" };
settings.theme = "dark";
```
