---
title: "no-constant-binary-expression"
description: "Disallow comparisons and `&&`, `||`, `??` that always give the same result"
---

Some expressions look like they depend on a value but always give the same result. `a + b ?? c` means `(a + b) ?? c`, and a sum is never `null`, so `c` is never used. `items === []` is always `false`, because `[]` is a new array that is equal to nothing else.

The rule reports:

- `&&` and `||` where the left side is always truthy or always falsy
- `??` where the left side is never `null` or `undefined`, or always is
- `==`, `!=`, `===` and `!==` where the result is always the same

This rule is on by default.

## Examples

Reported:

{/* bad {"count": 3} */}

```js
const label = "Hello, " + user.name ?? "guest";

if (items === []) {
  showEmptyState();
}

const isMissing = !user.email === undefined;
```

Not reported:

{/* good */}

```js
const label = "Hello, " + (user.name ?? "guest");

if (items.length === 0) {
  showEmptyState();
}

const isMissing = user.email === undefined;
```

## Options

| Option                       | Default | What it does                                                                                                  |
| ---------------------------- | ------- | ------------------------------------------------------------------------------------------------------------- |
| `checkRelationalComparisons` | `false` | Also report `<`, `<=`, `>` and `>=` between two literal values. With an oxlint config, the default is `true`. |

{/* bad {"options": [{"checkRelationalComparisons": true}]} */}

```js
const isLarge = 1024 > 4096;
```

{/* good */}

```js
const isLarge = 1024 > 4096;
```
