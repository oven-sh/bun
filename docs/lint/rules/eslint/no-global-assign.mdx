---
title: "no-global-assign"
description: "Disallow assigning to built-in and other read-only global variables"
---

Assigning to a global such as `Promise` or `window` replaces it for all the code that runs afterwards, including libraries. More often it is an accident: a `const` or `let` is missing, and the name you picked is already a global of the browser.

This rule is on by default.

## Examples

Reported:

{/* bad {"count": 3} */}

```js
Promise = loadPromiseLibrary();
window = createFakeWindow();
status = "ready";
```

Not reported:

{/* good */}

```js
const Promise = loadPromiseLibrary();
let status = "ready";
status = "done";
```

A global that is declared as writable can be assigned:

{/* good */}

```js
/* global analytics:writable */
analytics = createAnalytics();
```

{/* bad */}

```js
/* global analytics:readonly */
analytics = createAnalytics();
```

## Options

| Option       | Default | What it does                                     |
| ------------ | ------- | ------------------------------------------------ |
| `exceptions` | `[]`    | Names of read-only globals that may be assigned. |

{/* good {"options": [{"exceptions": ["Promise"]}]} */}

```js
Promise = loadPromiseLibrary();
```
