---
title: "no-inline-comments"
description: "Disallow comments on the same line as code"
---

A comment next to code makes the line longer, and it is easy to miss when you scan down the left edge of a file. With this rule, every comment goes on its own line.

Comments that configure the linter, such as `// eslint-disable-line`, are not reported.

## Examples

Reported:

{/* bad {"count": 3} */}

```js
const retries = 3; // the network is flaky
const timeout = /* seconds */ 30;
/* legacy */ connect(retries, timeout);
```

Not reported:

{/* good */}

```js
// The network is flaky.
const retries = 3;

/* In seconds. */
const timeout = 30;

connect(retries, timeout); // eslint-disable-line no-undef
```

In JSX, a comment in braces is fine if the braces have their lines to themselves:

{/* good */}

```jsx
const page = (
  <main>
    {/* The header comes from the layout. */}
    <Article />
  </main>
);
```

{/* bad */}

```jsx
const page = (
  <main>
    <Article /> {/* The header comes from the layout. */}
  </main>
);
```

## Options

| Option          | Default | What it does                                                               |
| --------------- | ------- | -------------------------------------------------------------------------- |
| `ignorePattern` | none    | A regular expression. A comment with text that matches it is not reported. |

{/* good {"options": [{"ignorePattern": "webpackChunkName"}]} */}

```js
const locale = import(/* webpackChunkName: "locale-en" */ "./locale/en.js");
```

{/* bad {"options": [{"ignorePattern": "webpackChunkName"}]} */}

```js
const locale = import(/* the default */ "./locale/en.js");
```
