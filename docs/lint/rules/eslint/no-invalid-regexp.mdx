---
title: "no-invalid-regexp"
description: "Disallow invalid patterns and flags in `RegExp()` and `new RegExp()`"
---

A mistake in a regular expression literal is a syntax error, so you see it at once. A pattern passed to `RegExp` as a string is only checked when that line runs, and then it throws a `SyntaxError`. This rule checks the string ahead of time.

Only string literals are checked. If the pattern or the flags come from a variable, that part is skipped.

This rule is on by default.

## Examples

Reported:

{/* bad {"count": 4} */}

```js
const letters = new RegExp("[a-z");
const digits = RegExp("(\\d+");
const twice = new RegExp("\\d+", "gg");
const unknown = new RegExp("\\d+", "x");
```

Not reported:

{/* good */}

```js
const letters = new RegExp("[a-z]");
const digits = RegExp("(\\d+)", "g");
const search = new RegExp(pattern, flags);
```

## Options

| Option                  | Default | What it does                                                                                                     |
| ----------------------- | ------- | ---------------------------------------------------------------------------------------------------------------- |
| `allowConstructorFlags` | `[]`    | Extra flags to accept, one letter each, for a runtime that knows flags the standard does not have. Case matters. |

{/* good {"options": [{"allowConstructorFlags": ["x"]}]} */}

```js
const digits = new RegExp("\\d+", "x");
```

{/* bad {"options": [{"allowConstructorFlags": ["x"]}]} */}

```js
const digits = new RegExp("\\d+", "X");
```
