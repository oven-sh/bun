---
title: "no-process-env"
description: "Disallow `process.env`"
---

`process.env` is global state. When it is read all over a project, nobody can list which variables the project needs, every reader has to deal with a missing or misspelled value, and tests have to change the environment of the whole process.

Read the environment in one file, check the values there, and import that file everywhere else. Turn the rule off for that one file.

Only `process.env` is checked, not `Bun.env` or `import.meta.env`.

## Examples

Reported:

{/* bad */}

```js
function connect() {
  return open(process.env.DATABASE_URL);
}
```

Not reported:

{/* good */}

```js
import { config } from "./config.js";

function connect() {
  return open(config.databaseUrl);
}
```

## When not to use it

In a small script, or in a project that has no single place for its configuration, reading `process.env` directly is fine.
