---
title: "no-return-assign"
description: "Disallow assignments in `return` statements"
---

`return total = price + tax;` can be a typo for `return total === price + tax;`, and a reader cannot tell which one you meant. Even when the assignment is wanted, it hides a side effect in a line that looks like it only returns a value.

The rule also covers an arrow function that has an assignment as its body.

## Examples

Reported:

{/* bad {"count": 2} */}

```js
function setName(user, name) {
  return (user.name = name);
}

const select = item => (selected = item);
```

Not reported:

{/* good */}

```js
function setName(user, name) {
  user.name = name;
  return name;
}

const select = item => {
  selected = item;
};
```

## Options

| Option                      | What it does                                        |
| --------------------------- | --------------------------------------------------- |
| `"except-parens"` (default) | Allow an assignment that is wrapped in parentheses. |
| `"always"`                  | Report every assignment in a `return`.              |

The parentheses say that the assignment is on purpose:

{/* good */}

```js
function next() {
  return (current = current.next);
}
```

{/* bad {"options": ["always"]} */}

```js
function next() {
  return (current = current.next);
}
```
