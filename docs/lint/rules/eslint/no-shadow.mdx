---
title: "no-shadow"
description: "Disallow a variable with the same name as one in an outer scope"
---

When an inner variable has the name of an outer one, the outer one cannot be reached from there anymore. A reader who has the outer meaning in mind reads the inner code wrong, and moving a line in or out of the block silently changes what the name refers to.

## Examples

Reported:

{/* bad */}

```js
const user = currentUser();

function greet(user) {
  return `Hello, ${user.name}`;
}
```

Not reported:

{/* good */}

```js
const user = currentUser();

function greet(guest) {
  return `Hello, ${guest.name}, I am ${user.name}`;
}
```

## Options

| Option                                       | Default       | What it does                                                                       |
| -------------------------------------------- | ------------- | ---------------------------------------------------------------------------------- |
| `allow`                                      | `[]`          | Names that may be shadowed.                                                        |
| `builtinGlobals`                             | `false`       | Also report names of globals, such as `Map` or `Object`.                           |
| `hoist`                                      | `"functions"` | Whether to report when the outer declaration comes after the inner one. See below. |
| `ignoreOnInitialization`                     | `false`       | Allow a callback's variable to shadow the variable that the call is assigned to.   |
| `ignoreTypeValueShadow`                      | `true`        | Allow a value with the name of a type, and the reverse.                            |
| `ignoreFunctionTypeParameterNameValueShadow` | `true`        | Allow the parameter names of function types and signatures.                        |

### `allow`

{/* good {"options": [{"allow": ["error"]}]} */}

```js
load((error, data) => {
  parse(data, (error, result) => {
    show(error ?? result);
  });
});
```

### `builtinGlobals`

{/* bad {"options": [{"builtinGlobals": true}]} */}

```js
function index(entries) {
  const Map = createIndex(entries);
  return Map;
}
```

### `hoist`

An inner variable can come before the outer declaration of the same name. `hoist` says when that is reported.

| Value                   | What is reported                                           |
| ----------------------- | ---------------------------------------------------------- |
| `"functions"`           | Only when the outer declaration is a function declaration. |
| `"types"`               | Only when it is a type alias or an interface.              |
| `"functions-and-types"` | When it is any of these.                                   |
| `"all"`                 | Always.                                                    |
| `"never"`               | Never.                                                     |

{/* good */}

```js
function render() {
  const title = "Draft";
  return title;
}

const title = "Home";
```

{/* bad {"options": [{"hoist": "all"}]} */}

```js
function render() {
  const title = "Draft";
  return title;
}

const title = "Home";
```

### `ignoreOnInitialization`

{/* good {"options": [{"ignoreOnInitialization": true}]} */}

```js
const item = items.find(item => item.selected);
```

### `ignoreTypeValueShadow`

{/* bad {"options": [{"ignoreTypeValueShadow": false}]} */}

```ts
type Config = { port: number };

function load() {
  const Config = read("config.json");
  return Config;
}
```

### `ignoreFunctionTypeParameterNameValueShadow`

{/* bad {"options": [{"ignoreFunctionTypeParameterNameValueShadow": false}]} */}

```ts
const value = 1;

type Handler = (value: string) => void;
```
