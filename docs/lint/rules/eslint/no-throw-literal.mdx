---
title: "no-throw-literal"
description: "Require `throw` to be given something that can be an `Error`"
---

JavaScript lets you throw any value, but code that catches expects an `Error`. A thrown string has no stack trace, so you cannot see where it came from. `error.message` is `undefined` on it, and `error instanceof Error` is `false`.

The rule goes by the syntax. It reports what can never be an `Error`: strings, numbers, `null`, `undefined`, object literals, template literals, a string put together with `+`. A variable, a property or the result of a call could hold an `Error`, so these are allowed. `@typescript-eslint/only-throw-error` looks at their types.

## Examples

Reported:

{/* bad {"count": 4} */}

```js
function find(id) {
  if (!id) throw "id is required";
  if (id < 0) throw { code: 400 };
  if (id > max) throw "no such id: " + id;
  throw undefined;
}
```

Not reported:

{/* good */}

```js
function find(id) {
  if (!id) throw new Error("id is required");
  if (id > max) throw new RangeError(`no such id: ${id}`);

  const error = new Error("bad request");
  error.code = 400;
  throw error;
}
```
