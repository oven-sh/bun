---
title: "require-await"
description: "Disallow async functions that never use `await`"
---

An `async` function with no `await` does nothing asynchronous, but it still wraps its result in a promise, so every caller has to await it. Often the `await` was removed in a refactor and the `async` stayed, or an `await` is missing.

`for await` and `await using` count as awaiting. Functions with an empty body and async generators are not reported. An `await` in a nested function does not count for the outer one.

The report comes with a suggestion that removes `async`.

## Examples

Reported:

{/* bad */}

```js
async function getUser(id) {
  return cache.get(id);
}
```

Not reported:

{/* good */}

```js
function getUser(id) {
  return cache.get(id);
}

async function loadUser(id) {
  const response = await fetch(`/users/${id}`);
  return response.json();
}
```

The `await` here belongs to the callback, so `saveAll` is reported:

{/* bad {"count": 1} */}

```js
async function saveAll(items) {
  items.forEach(async item => {
    await save(item);
  });
}
```

## When not to use it

An `async` function turns a thrown error into a rejected promise. If a function has to return a promise to fit an interface, and you rely on `async` for that, turn the rule off for it.
