---
title: "valid-typeof"
description: "Require `typeof` to be compared with a valid type name"
---

`typeof` returns one of eight strings: `"undefined"`, `"object"`, `"boolean"`, `"number"`, `"string"`, `"function"`, `"symbol"` or `"bigint"`. A comparison with anything else, usually a typo such as `"strnig"`, is never true, and nothing tells you.

The rule checks `==`, `===`, `!=` and `!==` where one side is a `typeof` expression. It reports a string that is not one of the eight, any other literal such as `null` or a number, and the bare identifier `undefined`. For `undefined`, the report comes with a suggestion that writes `"undefined"`.

This rule is on by default.

## Examples

Reported:

{/* bad {"count": 3} */}

```js
if (typeof name === "strnig") {
  trim(name);
}

if (typeof callback === undefined) {
  callback = noop;
}

if (typeof user === null) {
  signIn();
}
```

Not reported:

{/* good */}

```js
if (typeof name === "string") {
  trim(name);
}

if (typeof callback === "undefined") {
  callback = noop;
}

if (typeof left === typeof right) {
  compare(left, right);
}
```

## Options

| Option                  | Default | What it does                                                                                                 |
| ----------------------- | ------- | ------------------------------------------------------------------------------------------------------------ |
| `requireStringLiterals` | `false` | Also report a comparison with anything that is not a string literal or another `typeof`, such as a variable. |

By default a variable is allowed, because the rule cannot know what it holds:

{/* good */}

```js
if (typeof value === expectedType) {
  accept(value);
}
```

With `requireStringLiterals` it is reported:

{/* bad {"options": [{"requireStringLiterals": true}]} */}

```js
if (typeof value === expectedType) {
  accept(value);
}
```
