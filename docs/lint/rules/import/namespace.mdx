---
title: "import/namespace"
description: "Require each property read from an `import * as` namespace to be exported by that file"
---

With `import * as api from "./api"`, reading a name that `./api` does not export gives `undefined`, and nothing fails until you call it. Assigning to `api.save` throws, because a namespace object is read-only.

The rule reads the imported file and checks `api.name`, `const { name } = api` and `<api.Name />`. It follows namespaces inside namespaces, such as `export * as dates from "./dates"`. A computed read like `api[key]` cannot be checked, so it is reported as well unless you allow it.

## Examples

Reported:

{/* file "api.js" */}

```js
export function save(item) {}
export function load(id) {}
```

{/* bad {"count": 4} */}

```js
import * as api from "./api.js";

api.remove("draft");
const { update } = api;
api.save = () => {};

const action = "load";
api[action]("draft");
```

Not reported:

{/* file "api.js" */}

```js
export function save(item) {}
export function load(id) {}
```

{/* good */}

```js
import * as api from "./api.js";

api.save({ id: "draft" });
const { load } = api;
load("draft");
```

## Options

| Option          | Default | What it does                                                   |
| --------------- | ------- | -------------------------------------------------------------- |
| `allowComputed` | `false` | Allow computed reads such as `api[key]`. They are not checked. |

{/* file "api.js" */}

```js
export function save(item) {}
export function load(id) {}
```

{/* good {"options": [{"allowComputed": true}]} */}

```js
import * as api from "./api.js";

const action = "load";
api[action]("draft");
```
