---
title: "import/no-named-as-default"
description: "Disallow naming a default import after a named export of the same module"
---

`import Button from "./button"` gets the default export, whatever you call it. If `./button` also has a named export `Button`, the braces were probably forgotten, and the code uses a different value than its name says.

The rule reads the imported module. It only reports if that module has both a default export and a named export with the name you chose.

## Examples

Reported:

{/* file "button.js" */}

```js button.js
export const Button = props => render("button", props);

export default withTheme(Button);
```

{/* bad */}

```js
import Button from "./button";
```

Not reported:

{/* file "button.js" */}

```js button.js
export const Button = props => render("button", props);

export default withTheme(Button);
```

{/* good */}

```js
import ThemedButton, { Button } from "./button";
```

## When not to use it

Some modules export the same value both ways on purpose, so that `import Button` and `import { Button }` both work. The rule reports the first form there too.
