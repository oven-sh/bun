---
title: "import/no-unassigned-import"
description: "Disallow imports that bind no name"
---

`import "./setup.js"` runs a module only for its side effects. Nothing in the file shows what the module changes, and the order of such imports matters without saying so. With this rule, every import has to bring in a name you can follow.

A `require()` call that stands alone as a statement is reported too, and so is an import with empty braces.

## Examples

Reported:

{/* bad {"count": 3} */}

```js
import "./register-globals.js";
import {} from "lodash";
require("./patch-console.js");
```

Not reported:

{/* good */}

```js
import { registerGlobals } from "./register-globals.js";
const patchConsole = require("./patch-console.js");

registerGlobals();
patchConsole();
```

## Options

| Option  | Default | What it does                                                   |
| ------- | ------- | -------------------------------------------------------------- |
| `allow` | `[]`    | Globs for modules that can be imported for their side effects. |

A package name is matched as you wrote it. A relative path is made absolute first, so a glob for files either starts with `**/` or is relative to the directory you run `bun lint` in.

```toml bunfig.toml
[lint.rules]
"import/no-unassigned-import" = ["error", { allow = ["**/*.css", "reflect-metadata"] }]
```

With this configuration, these are allowed:

{/* good {"options": [{"allow": ["{**,}/*.css", "reflect-metadata"]}]} */}

```js
import "./app.css";
import "reflect-metadata";
```

And this is still reported:

{/* bad {"options": [{"allow": ["{**,}/*.css", "reflect-metadata"]}]} */}

```js
import "./register-globals.js";
```

## When not to use it

Stylesheets, polyfills and test setup files are meant to be imported this way. If `allow` would have to list most of your side-effect imports, leave the rule off.
