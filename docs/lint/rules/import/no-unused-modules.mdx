---
title: "import/no-unused-modules"
description: "Disallow exports that no other file imports, and files that export nothing"
---

An export that nothing imports is dead code that looks alive: it still gets maintained, tested and refactored. This rule reads the files of the project, collects what each one imports, and reports the exports that are left over.

The rule does nothing until you turn on `unusedExports` or `missingExports`.

`unusedExports` lists the project's files the way ESLint 8 does. It needs an `.eslintrc` file, or `eslintConfig` in `package.json`, in or above every folder it searches. Without one it reports nothing.

## Examples

Reported, because nothing imports `formatTime`:

{/* file "shop/.eslintrc.json" */}

```json shop/.eslintrc.json
{
  "root": true,
  "plugins": ["import"],
  "parserOptions": { "ecmaVersion": "latest", "sourceType": "module" },
  "rules": { "import/no-unused-modules": ["error", { "unusedExports": true }] }
}
```

{/* file "shop/app.js" */}

```js shop/app.js
import { formatDate } from "./format.js";

console.log(formatDate(new Date()));
```

{/* bad {"filename": "shop/format.js", "count": 1, "options": [{"unusedExports": true, "src": ["{**,}/shop/*.js"]}]} */}

```js shop/format.js
export function formatDate(date) {}
export function formatTime(date) {}
```

Not reported:

{/* file "shop/.eslintrc.json" */}

```json shop/.eslintrc.json
{
  "root": true,
  "plugins": ["import"],
  "parserOptions": { "ecmaVersion": "latest", "sourceType": "module" },
  "rules": { "import/no-unused-modules": ["error", { "unusedExports": true }] }
}
```

{/* file "shop/app.js" */}

```js shop/app.js
import { formatDate, formatTime } from "./format.js";

console.log(formatDate(new Date()), formatTime(new Date()));
```

{/* good {"filename": "shop/format.js", "options": [{"unusedExports": true, "src": ["{**,}/shop/*.js"]}]} */}

```js shop/format.js
export function formatDate(date) {}
export function formatTime(date) {}
```

What counts as a use:

- `import * as format from "./format.js"` and `import("./format.js")` use every export of the file.
- `export * from "./format.js"` uses every export but the default.
- `require("./format.js")` uses nothing.

## Options

| Option                    | Default                             | What it does                                                                                              |
| ------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `unusedExports`           | `false`                             | Report exports that no other file imports.                                                                |
| `missingExports`          | `false`                             | Report files that export nothing.                                                                         |
| `src`                     | the directory you run `bun lint` in | Files, folders and globs to search for imports. A file outside of them is not checked for unused exports. |
| `ignoreExports`           | `[]`                                | Files, folders and globs with exports that are never reported, such as entry points and tests.            |
| `ignoreUnusedTypeExports` | `false`                             | Do not report an unused exported `type`, `interface` or `enum`.                                           |

Only `.js`, `.mjs` and `.cjs` files are searched, unless the `import/extensions` setting of an ESLint config lists others.

The files that `main`, `bin` and `browser` in the closest `package.json` point to are entry points. Their exports are not reported, unless the package is `"private": true`.

With `missingExports`, this file is reported:

{/* bad {"options": [{"missingExports": true}]} */}

```js
function formatDate(date) {}
```

## When not to use it

A library's exports are used by other projects, which the rule cannot see. List the public files in `ignoreExports`, or leave the rule off.
