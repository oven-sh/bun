---
title: "import/order"
description: "Enforce a consistent order of imports, by group and optionally by name"
---

When imports are added wherever there is room, you cannot see at a glance what a file depends on, and two branches that add an import in the same spot conflict. This rule sorts imports into groups by where they come from.

The default order is Node.js built-ins, packages, parent folders (`../`), the same folder (`./`), then the folder's own index (`.` or `./`). Inside a group any order is fine, unless you set `alphabetize`.

- `import` and top-level `const x = require()` are checked. All `require()` calls go after all `import` statements.
- `import "./app.css"` and other imports without a name are skipped, because moving them can change what the code does.

`--fix` moves the imports, unless there is other code between them.

## Examples

Reported:

{/* bad */}

```js
import { formatDate } from "./format.js";
import express from "express";
import fs from "node:fs";
```

Not reported:

{/* good */}

```js
import fs from "node:fs";
import express from "express";
import { config } from "../config.js";
import { formatDate } from "./format.js";
import { routes } from "./";
```

## Options

| Option                          | Default                                                 | What it does                                                                                                                                                                                                                                       |
| ------------------------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `groups`                        | `["builtin", "external", "parent", "sibling", "index"]` | The order of the groups. Also available: `"internal"`, `"unknown"`, `"object"`, `"type"`. A nested array makes several groups count as one. Groups you leave out come last, together.                                                              |
| `newlines-between`              | `"ignore"`                                              | `"always"`: one or more empty lines between groups, none inside. `"always-and-inside-groups"`: the same, but empty lines inside a group are fine. `"never"`: no empty lines at all.                                                                |
| `alphabetize`                   | `{ order: "ignore" }`                                   | Sort each group by path. `order`: `"asc"` or `"desc"`. `caseInsensitive`: `false` by default. `orderImportKind`: for two imports of the same path, `"asc"` puts the `import type` first and `"desc"` puts it last.                                 |
| `named`                         | `false`                                                 | Also sort the names inside `{ }`, by `alphabetize.order`. `true`, or an object that turns on some of `import`, `export`, `require`, `cjsExports`. Its `types` key says where inline `type` names go: `"mixed"`, `"types-first"` or `"types-last"`. |
| `pathGroups`                    | `[]`                                                    | Puts paths that match a glob into a group: `{ pattern, group, position }`. `position` is `"before"` or `"after"` the rest of the group.                                                                                                            |
| `pathGroupsExcludedImportTypes` | `["builtin", "external", "object"]`                     | Kinds of imports that `pathGroups` leaves alone.                                                                                                                                                                                                   |
| `distinctGroup`                 | `true`                                                  | For `newlines-between`, treat a path group with a `position` as a group of its own.                                                                                                                                                                |
| `sortTypesGroup`                | `false`                                                 | Order the imports in the `"type"` group by `groups` too.                                                                                                                                                                                           |
| `newlines-between-types`        | same as `newlines-between`                              | With `sortTypesGroup`, the empty lines around and between `import type` statements.                                                                                                                                                                |
| `consolidateIslands`            | `"never"`                                               | `"inside-groups"`, with `"always-and-inside-groups"`: an empty line around each multi-line import, none between single-line imports of a group.                                                                                                    |
| `warnOnUnassignedImports`       | `false`                                                 | Also check imports without a name. `--fix` does not move them.                                                                                                                                                                                     |

### `newlines-between`

{/* bad {"options": [{"newlines-between": "always"}]} */}

```js
import fs from "node:fs";
import express from "express";
```

{/* good {"options": [{"newlines-between": "always"}]} */}

```js
import fs from "node:fs";

import express from "express";
```

### `alphabetize` and `named`

```toml bunfig.toml
[lint.rules]
"import/order" = ["error", { named = true, alphabetize = { order = "asc", caseInsensitive = true } }]
```

{/* bad {"count": 2, "options": [{"named": true, "alphabetize": {"order": "asc", "caseInsensitive": true}}]} */}

```js
import { writeFile, readFile } from "node:fs/promises";
import express from "express";
import chalk from "chalk";
```

{/* good {"options": [{"named": true, "alphabetize": {"order": "asc", "caseInsensitive": true}}]} */}

```js
import { readFile, writeFile } from "node:fs/promises";
import chalk from "chalk";
import express from "express";
```

### `pathGroups`

Use it for path aliases, which otherwise count as `"unknown"`:

```toml bunfig.toml
[lint.rules]
"import/order" = ["error", { groups = ["builtin", "external", "internal", "parent", "sibling", "index"], pathGroups = [{ pattern = "@/**", group = "internal" }] }]
```

{/* bad {"options": [{"groups": ["builtin", "external", "internal", "parent", "sibling", "index"], "pathGroups": [{"pattern": "@/**", "group": "internal"}]}]} */}

```js
import { config } from "../config.js";
import { Button } from "@/components/button";
```

{/* good {"options": [{"groups": ["builtin", "external", "internal", "parent", "sibling", "index"], "pathGroups": [{"pattern": "@/**", "group": "internal"}]}]} */}

```js
import { Button } from "@/components/button";
import { config } from "../config.js";
```

### The `"type"` group

With `"type"` in `groups`, every `import type` goes to that place, wherever it imports from:

{/* bad {"options": [{"groups": ["builtin", "external", "parent", "sibling", "index", "type"]}]} */}

```ts
import type { Server } from "node:http";
import { formatDate } from "./format.ts";
```

{/* good {"options": [{"groups": ["builtin", "external", "parent", "sibling", "index", "type"]}]} */}

```ts
import { formatDate } from "./format.ts";
import type { Server } from "node:http";
```
