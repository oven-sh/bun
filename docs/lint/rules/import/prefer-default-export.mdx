---
title: "import/prefer-default-export"
description: "Require a default export in a file that exports a single name"
---

This is a style rule. If a file exports one thing, that thing is what the file is for, and a default export says so. Whoever imports it does not have to look up the name.

A file is left alone if it has a default export, an `export *`, or an exported `type` or `interface`.

## Examples

Reported:

{/* bad */}

```js
export function formatDate(date) {
  return date.toISOString();
}
```

Not reported:

{/* good */}

```js
export default function formatDate(date) {
  return date.toISOString();
}
```

{/* good */}

```js
export function formatDate(date) {}
export function formatTime(date) {}
```

{/* good */}

```ts
export type UserId = number;
```

## Options

| Option   | Default    | What it does                                                                                                                      |
| -------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `target` | `"single"` | `"single"` reports a file with exactly one named export. `"any"` reports every file that has named exports and no default export. |

{/* bad {"options": [{"target": "any"}]} */}

```js
export function formatDate(date) {}
export function formatTime(date) {}
```

{/* good {"options": [{"target": "any"}]} */}

```js
export function formatTime(date) {}
export default function formatDate(date) {}
```

## When not to use it

Named exports keep the same name everywhere, which helps auto-import and renaming. If your project prefers them, use `import/no-default-export` and leave this rule off.
