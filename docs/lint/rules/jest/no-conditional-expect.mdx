---
title: "jest/no-conditional-expect"
description: "Disallow `expect` inside `if`, `catch` and other code that only runs sometimes"
---

An `expect` that only runs under a condition may not run at all. If the condition is false, or nothing is thrown, the test passes without checking anything.

In a test, the rule reports an `expect` inside an `if`, a `switch`, a `catch` block, a `.catch()` callback, `a ? b : c`, or an operand of `&&`, `||` or `??`.

It also checks `function` declarations that a test uses. It does not look inside an anonymous `function () {}`, even when that is the test callback.

## Examples

Reported, because the test passes if `JSON.parse` stops throwing:

{/* bad */}

```ts
import { expect, test } from "@jest/globals";

test("rejects bad JSON", () => {
  try {
    JSON.parse("{");
  } catch (error) {
    expect(error).toBeInstanceOf(SyntaxError);
  }
});
```

{/* bad */}

```ts
import { expect, test } from "@jest/globals";
import { readFile } from "node:fs/promises";

test("rejects a missing file", async () => {
  await readFile("missing.txt").catch(error => {
    expect(error.code).toBe("ENOENT");
  });
});
```

{/* bad */}

```ts
import { expect, test } from "@jest/globals";

const users = [{ name: "Ada", admin: true }];

test("finds the admin", () => {
  const admin = users.find(user => user.admin);
  if (admin) {
    expect(admin.name).toBe("Ada");
  }
});
```

Not reported:

{/* good */}

```ts
import { expect, test } from "@jest/globals";
import { readFile } from "node:fs/promises";

const users = [{ name: "Ada", admin: true }];

test("rejects bad JSON", () => {
  expect(() => JSON.parse("{")).toThrow(SyntaxError);
});

test("rejects a missing file", async () => {
  await expect(readFile("missing.txt")).rejects.toThrow("ENOENT");
});

test("finds the admin", () => {
  const admin = users.find(user => user.admin);
  expect(admin).toBeDefined();
  expect(admin?.name).toBe("Ada");
});
```
