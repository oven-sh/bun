---
title: "jest/no-confusing-set-timeout"
description: "Disallow `jest.setTimeout` inside a block, after a test, or more than once in a file"
---

`jest.setTimeout` sets the timeout for the whole test file. A call inside a `describe` or a test looks like it only applies there, but it does not. With two calls in a file, it is hard to tell which one a given test gets.

The rule reports a `jest.setTimeout` call that is:

- not at the top level of the file
- after another Jest function such as `test` or `expect`
- not the first one in the file

To give one test more time, pass the timeout as the third argument of `test`.

## Examples

Reported:

{/* bad */}

```ts
import { describe, expect, jest, test } from "@jest/globals";
import { upload } from "./upload";

describe("upload", () => {
  jest.setTimeout(10_000);

  test("sends the file", async () => {
    expect(await upload("report.pdf")).toBe(true);
  });
});
```

{/* bad {"count": 1} */}

```ts
import { jest } from "@jest/globals";

jest.setTimeout(5_000);
jest.setTimeout(10_000);
```

Not reported:

{/* good */}

```ts
import { describe, expect, jest, test } from "@jest/globals";
import { upload } from "./upload";

jest.setTimeout(10_000);

describe("upload", () => {
  test("sends the file", async () => {
    expect(await upload("report.pdf")).toBe(true);
  });
});
```

{/* good */}

```ts
import { expect, test } from "@jest/globals";
import { upload } from "./upload";

test("sends the file", async () => {
  expect(await upload("report.pdf")).toBe(true);
}, 10_000);
```
