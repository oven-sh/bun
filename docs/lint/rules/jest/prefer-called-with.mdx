---
title: "jest/prefer-called-with"
description: "Require `toHaveBeenCalledWith()` instead of `toHaveBeenCalled()`"
---

`toHaveBeenCalled()` passes whatever the mock was called with, so the test keeps passing when the code starts to pass the wrong arguments. `toHaveBeenCalledWith(...)` checks the arguments too. The alias `toBeCalled()` is reported the same way.

`.not.toHaveBeenCalled()` is allowed: a mock that never ran has no arguments to check.

`--fix` renames the matcher and leaves the parentheses empty. Fill in the arguments you expect: `toHaveBeenCalledWith()` only passes for a call without arguments.

## Examples

Reported:

{/* bad */}

```js
import { expect, jest, test } from "@jest/globals";

test("sends a welcome email", () => {
  const send = jest.fn();
  register("ada@example.com", send);
  expect(send).toHaveBeenCalled();
});
```

Not reported:

{/* good */}

```js
import { expect, jest, test } from "@jest/globals";

test("sends a welcome email", () => {
  const send = jest.fn();
  register("ada@example.com", send);
  expect(send).toHaveBeenCalledWith("ada@example.com", "welcome");
});

test("sends nothing for an invalid address", () => {
  const send = jest.fn();
  register("not an address", send);
  expect(send).not.toHaveBeenCalled();
});
```
