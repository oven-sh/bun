---
title: "jest/prefer-importing-jest-globals"
description: "Require `describe`, `test`, `expect` and `jest` to be imported from `@jest/globals`"
---

Jest puts `describe`, `test`, `expect`, `jest` and the hooks in the global scope of every test file, so nothing in the file says where they come from. An import from `@jest/globals` says it, and it brings the types with it.

A file gets one report, which lists every name to import.

`--fix` adds the import, or adds the names to the import from `@jest/globals` that is already there. In a CommonJS file it writes `require("@jest/globals")`.

## Examples

Reported:

{/* bad {"count": 1} */}

```ts
describe("cart", () => {
  test("starts empty", () => {
    expect(cart.items).toHaveLength(0);
  });
});
```

Not reported:

{/* good */}

```ts
import { describe, expect, test } from "@jest/globals";

describe("cart", () => {
  test("starts empty", () => {
    expect(cart.items).toHaveLength(0);
  });
});
```

## Options

| Option  | Default     | What it does                                                                                                                          |
| ------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `types` | all of them | The kinds of globals to report: `"hook"` (`beforeEach` and the like), `"describe"`, `"test"` (`test` and `it`), `"expect"`, `"jest"`. |

With `{ "types": ["jest"] }`, only the `jest` object has to be imported:

{/* bad {"options": [{"types": ["jest"]}]} */}

```ts
jest.useFakeTimers();

test("expires", () => {
  expect(session.expired).toBe(false);
});
```

{/* good {"options": [{"types": ["jest"]}]} */}

```ts
import { jest } from "@jest/globals";

jest.useFakeTimers();

test("expires", () => {
  expect(session.expired).toBe(false);
});
```
