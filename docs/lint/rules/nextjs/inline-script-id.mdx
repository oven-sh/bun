---
title: "@next/next/inline-script-id"
description: "Require an `id` on `next/script` components that have inline content"
---

Next.js uses the `id` of an inline `<Script>` to keep track of it, so that the code runs once and not again after each navigation. A script with a `src` is tracked by its URL. An inline script has none, so it needs an `id`.

A script is inline if it has children or a `dangerouslySetInnerHTML` prop. The rule follows the name you give to the default import of `next/script`.

## Examples

Reported:

{/* bad */}

```jsx
import Script from "next/script";

export default function Page() {
  return <Script>{`window.startedAt = Date.now();`}</Script>;
}
```

{/* bad */}

```jsx
import Script from "next/script";

export default function Page() {
  return <Script dangerouslySetInnerHTML={{ __html: "window.startedAt = Date.now();" }} />;
}
```

Not reported:

{/* good */}

```jsx
import Script from "next/script";

export default function Page() {
  return (
    <>
      <Script id="started-at">{`window.startedAt = Date.now();`}</Script>
      <Script src="https://example.com/widget.js" />
    </>
  );
}
```

If you spread a variable into the props, the `id` may be in it, so the element is not reported:

{/* good */}

```jsx
import Script from "next/script";

export default function Tracker(props) {
  return <Script {...props}>{`window.startedAt = Date.now();`}</Script>;
}
```
