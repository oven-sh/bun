---
title: "n/no-sync"
description: "Disallow calls to functions with names that end in `Sync`"
---

A function such as `fs.readFileSync()` blocks the thread until it is done. In a server, every other request waits for that one file to be read. The versions that return a promise or take a callback let other work run in the meantime.

The rule goes by the name alone: any call to a function or method with a name that ends in `Sync` is reported. Mentioning the function without calling it is not.

## Examples

Reported:

{/* bad */}

```js
function handle(request) {
  const page = fs.readFileSync("index.html", "utf8");
  return new Response(page);
}
```

Not reported:

{/* good */}

```js
async function handle(request) {
  const page = await fs.promises.readFile("index.html", "utf8");
  return new Response(page);
}
```

## Options

| Option             | Default | What it does                                                                 |
| ------------------ | ------- | ---------------------------------------------------------------------------- |
| `allowAtRootLevel` | `false` | Allow calls outside of any function, which run once when the file is loaded. |
| `ignores`          | `[]`    | Names of functions that are never reported.                                  |

{/* good {"options": [{"allowAtRootLevel": true}]} */}

```js
const template = fs.readFileSync("index.html", "utf8");
```

{/* bad {"options": [{"allowAtRootLevel": true}]} */}

```js
function template() {
  return fs.readFileSync("index.html", "utf8");
}
```

{/* good {"options": [{"ignores": ["existsSync"]}]} */}

```js
function hasConfig() {
  return fs.existsSync("config.json");
}
```

## When not to use it

In scripts, build steps and command line tools nothing else waits for the thread, and the synchronous calls are simpler.
