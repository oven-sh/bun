---
title: "n/no-unsupported-features/node-builtins"
description: "Disallow Node.js APIs that the Node.js versions you support do not have"
---

A Node.js API that is newer than the oldest version you support is missing there. An `import` of it fails when the file loads, and a call throws a `TypeError`. You only find out when somebody runs the code on that version.

The rule checks what you take from built-in modules with `import`, `require()` or `process.getBuiltinModule()`, globals such as `fetch`, and the properties of `import.meta`. It takes the versions you support from `engines.node` in your `package.json`. Without that, it assumes `>=16.0.0`. Every version in the range must have the API, and have it as stable: an API that is still experimental is reported too.

## Examples

Reported, because `util.parseArgs` is stable since 20.0.0 and `import.meta.dirname` since 24.0.0:

{/* bad {"count": 2} */}

```js
import { parseArgs } from "node:util";

const { values } = parseArgs({ options: { port: { type: "string" } } });
console.log(import.meta.dirname, values.port);
```

Not reported:

{/* good */}

```js
import { dirname } from "node:path";
import { fileURLToPath } from "node:url";

console.log(dirname(fileURLToPath(import.meta.url)), process.argv[2]);
```

With a newer `engines.node`, `parseArgs` is fine:

{/* file "package.json" */}

```json
{
  "name": "app",
  "engines": { "node": ">=20.0.0" }
}
```

{/* good */}

```js
import { parseArgs } from "node:util";

const { values } = parseArgs({ options: { port: { type: "string" } } });
```

A bare global such as `fetch`, and `require()`, are only followed if your config declares them as globals. `globalThis.fetch` is checked either way:

{/* bad */}

```js
const response = await globalThis.fetch("https://example.com");
```

## Options

| Option              | Default                         | What it does                                                                                 |
| ------------------- | ------------------------------- | -------------------------------------------------------------------------------------------- |
| `version`           | `engines.node`, or `">=16.0.0"` | The range of Node.js versions you support, written as in `package.json`.                     |
| `allowExperimental` | `false`                         | Allow an API if every version in the range has it, even as experimental.                     |
| `ignores`           | `[]`                            | APIs that are never reported, by the name in the message, such as `"fs.cpSync"` or `"test"`. |

```toml bunfig.toml
[lint.rules]
"n/no-unsupported-features/node-builtins" = ["error", { version = ">=22.5.0", allowExperimental = true }]
```

`node:sqlite` is experimental since 22.5.0:

{/* bad {"options": [{"version": ">=22.5.0"}]} */}

```js
import { DatabaseSync } from "node:sqlite";
```

{/* good {"options": [{"version": ">=22.5.0", "allowExperimental": true}]} */}

```js
import { DatabaseSync } from "node:sqlite";
```

{/* bad {"options": [{"version": ">=22.0.0", "allowExperimental": true}]} */}

```js
import { DatabaseSync } from "node:sqlite";
```

{/* good {"options": [{"ignores": ["fs.cpSync"]}]} */}

```js
import fs from "node:fs";

fs.cpSync("public", "dist", { recursive: true });
```
