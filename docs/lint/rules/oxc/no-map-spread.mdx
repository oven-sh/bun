---
title: "oxc/no-map-spread"
description: "Disallow object and array spreads in the return value of `map` and `flatMap` callbacks"
---

`tasks.map(task => ({ ...task, done: false }))` copies every property of every item into a new object. On a large array that is a lot of work and memory. If nothing else uses the old items, you can change them in place.

The rule looks at the object or array that the callback returns, directly or through a variable. It does not look at what is spread, so `ids.map(id => ({ ...defaults, id }))` is reported too.

`--fix-suggestions` rewrites `{ ...task, done: false }` to `Object.assign(task, { done: false })`. That changes the items of the original array.

## Examples

Reported:

{/* bad */}

```js
function loadTasks() {
  const tasks = readTasks();
  return tasks.map(task => ({ ...task, done: false }));
}
```

{/* bad */}

```js
const rows = readRows().map(row => [...row, total(row)]);
```

Not reported:

{/* good */}

```js
function loadTasks() {
  const tasks = readTasks();
  return tasks.map(task => Object.assign(task, { done: false }));
}
```

{/* good */}

```js
const rows = readRows();
for (const row of rows) {
  row.push(total(row));
}
```

An array that belongs to `this` is never reported, because changing its items would change the instance:

{/* good */}

```js
class TaskList {
  snapshot() {
    return this.tasks.map(task => ({ ...task }));
  }
}
```

## Options

| Option          | Default | What it does                                                                                             |
| --------------- | ------- | -------------------------------------------------------------------------------------------------------- |
| `ignoreRereads` | `true`  | Allow the spread if the array variable is read again after the call. The copy is then likely on purpose. |
| `ignoreArgs`    | `true`  | Allow the spread if the array is a parameter of a function. The caller may still use its items.          |

Allowed by default, because `tasks` is used afterwards:

{/* good */}

```js
const tasks = readTasks();
const drafts = tasks.map(task => ({ ...task, done: false }));
console.log(tasks.length, drafts.length);
```

{/* bad {"options": [{"ignoreRereads": false}]} */}

```js
const tasks = readTasks();
const drafts = tasks.map(task => ({ ...task, done: false }));
console.log(tasks.length, drafts.length);
```

Allowed by default, because `tasks` is a parameter:

{/* good */}

```js
function markDone(tasks) {
  return tasks.map(task => ({ ...task, done: true }));
}
```

{/* bad {"options": [{"ignoreArgs": false}]} */}

```js
function markDone(tasks) {
  return tasks.map(task => ({ ...task, done: true }));
}
```

## When not to use it

If your code treats data as immutable, as React state and Redux stores require, the copy is the point. The cost also does not matter for small arrays.
