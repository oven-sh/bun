---
title: "oxc/no-optional-chaining"
description: "Disallow optional chaining (`?.`)"
---

Engines older than ES2020 cannot parse `?.`, so a file that uses it fails to load there. If a compiler lowers it for such a target, each `?.` turns into temporary variables and `null` and `undefined` checks, which makes the output larger.

The rule reports each chain once, however many `?.` it has.

## Examples

Reported:

{/* bad {"count": 1} */}

```js
const city = user?.address?.city;
```

{/* bad {"count": 2} */}

```js
const first = items?.[0];
onSave?.(first);
```

Not reported:

{/* good */}

```js
const city = user && user.address && user.address.city;

if (onSave) {
  onSave(city);
}
```

## Options

| Option    | Default | What it does                                                                             |
| --------- | ------- | ---------------------------------------------------------------------------------------- |
| `message` | `""`    | Text to show as help under the report, for example why your project does not allow `?.`. |

{/* bad {"options": [{"message": "We ship ES2016 without a compile step."}]} */}

```js
const city = user?.address;
```

## When not to use it

Every current browser and runtime supports `?.`. Use this rule only if your code has to run on older ones.
