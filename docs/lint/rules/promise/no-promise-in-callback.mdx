---
title: "promise/no-promise-in-callback"
description: "Disallow promises inside error-first callbacks"
---

The code that calls a callback ignores what it returns. Nobody awaits a promise started inside one, so a rejection goes unhandled, and the code now reports errors in two different ways.

A function counts as a callback if its first parameter is named `err` or `error`. Inside one, the rule reports calls of `then()`, `catch()`, `finally()` and of static methods such as `Promise.all()`.

A call that is the value of a `return` statement is not reported. A function passed to `then()` or `catch()` does not count as a callback, whatever its first parameter is called.

## Examples

Reported:

{/* bad */}

```js
fs.readFile(path, "utf8", (err, text) => {
  if (err) throw err;
  upload(text).then(notify);
});
```

Not reported:

{/* good */}

```js
import { readFile } from "node:fs/promises";

async function publish(path) {
  const text = await readFile(path, "utf8");
  await upload(text);
  notify();
}

upload(draft).catch(err => retry(draft).then(notify));
```

## Options

| Option               | Default | What it does                                                                                    |
| -------------------- | ------- | ----------------------------------------------------------------------------------------------- |
| `exemptDeclarations` | `false` | Do not treat function declarations as callbacks, only function expressions and arrow functions. |

{/* bad */}

```js
function onFailure(error) {
  report(error).then(close);
}
```

{/* good {"options": [{"exemptDeclarations": true}]} */}

```js
function onFailure(error) {
  report(error).then(close);
}
```
