---
title: "react-hooks/capitalized-calls"
description: "Disallow calling a function with a capitalized name from a component or a hook"
---

A capitalized name says "component". If you call a component as a plain function, React does not know it is there. Its hooks run as hooks of the caller, so its state gets mixed up with the caller's as soon as the call becomes conditional. Render it with JSX instead.

The rule looks inside components and hooks. It reports a call of a capitalized function that comes from outside the component, and a call of a capitalized method such as `ui.Avatar()`. Names without a lowercase letter such as `T()`, and built-in functions such as `Number()` and `String()`, are allowed.

## Examples

Reported:

{/* bad */}

```jsx
import Avatar from "./Avatar";

function Profile({ user }) {
  return <section>{Avatar({ user })}</section>;
}
```

{/* bad */}

```jsx
import * as ui from "./ui";

function Profile({ user }) {
  return <section>{ui.Avatar({ user })}</section>;
}
```

Not reported:

{/* good */}

```jsx
import Avatar from "./Avatar";
import { T } from "./translate";

function Profile({ user }) {
  const age = Number(user.age);
  return (
    <section>
      <Avatar user={user} />
      {T("profile.age")}: {String(age)}
    </section>
  );
}
```

## When not to use it

If your code has plain functions with capitalized names, such as factories, every call of them from a component is reported. Rename them, or leave the rule off.
