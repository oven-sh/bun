---
title: "react-hooks/error-boundaries"
description: "Disallow JSX inside a `try` block, where `catch` cannot see rendering errors"
---

`<Chart />` does not call `Chart`. It only describes what to render, and React calls the component later, after your function has returned. So if `Chart` throws while rendering, the `try` around the JSX is long over and its `catch` never runs.

To handle an error from rendering, wrap the component in an error boundary.

JSX in the `catch` block is allowed, unless that `catch` is itself inside another `try`.

## Examples

Reported:

{/* bad */}

```jsx
function Dashboard({ data }) {
  try {
    return <Chart data={data} />;
  } catch {
    return <p>Could not draw the chart.</p>;
  }
}
```

Not reported:

{/* good */}

```jsx
function Dashboard({ data }) {
  return (
    <ErrorBoundary fallback={<p>Could not draw the chart.</p>}>
      <Chart data={data} />
    </ErrorBoundary>
  );
}
```

A `try` around code that runs right away is fine:

{/* good */}

```jsx
function Dashboard({ json }) {
  let data;
  try {
    data = JSON.parse(json);
  } catch {
    return <p>Could not read the data.</p>;
  }
  return <Chart data={data} />;
}
```
