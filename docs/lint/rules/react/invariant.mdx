---
title: "react-hooks/invariant"
description: "Report code that makes the React Compiler fail one of its internal checks"
---

The React Compiler checks its own work while it analyzes a component. When one of these checks fails, it gives up on that component or hook and leaves it unoptimized. The code still runs as written.

A report from this rule does not mean that your code breaks a rule of React. It means that the compiler cannot handle the way it is written. Writing it another way usually gets the component compiled again.

## Examples

Reported, because one destructuring assignment writes to a variable that a function captures and to one that no function captures:

{/* bad */}

```jsx
function Results(props) {
  let rows = [];
  let total = 0;
  ({ rows, total } = props.load());
  const logRows = () => console.log(rows);
  return <div onClick={logRows}>{total}</div>;
}
```

Not reported:

{/* good */}

```jsx
function Results(props) {
  const { rows, total } = props.load();
  const logRows = () => console.log(rows);
  return <div onClick={logRows}>{total}</div>;
}
```

## When not to use it

If you do not build with the React Compiler, nothing is lost when it gives up on a component. Turn this rule off.
