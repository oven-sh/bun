---
title: "react/jsx-handler-names"
description: "Enforce naming conventions for event handlers and the props they are passed to"
---

With one convention, a name tells you which side of a component you are on: a prop that takes a handler starts with `on`, and the function that handles the event starts with `handle`. The rule reports an `on` prop that gets a function with another name, and a `handle` function that is passed to a prop with another name.

By default only methods and properties such as `this.handleChange` or `props.onChange` are checked. Local variables and inline functions are not. `ref` is never checked.

## Examples

Reported:

{/* bad {"count": 2} */}

```jsx
class Form extends React.Component {
  render() {
    return <Input onChange={this.updateName} blur={this.handleBlur} />;
  }
}
```

Not reported:

{/* good */}

```jsx
class Form extends React.Component {
  render() {
    return (
      <Input
        onChange={this.handleChange}
        onBlur={this.props.onBlur}
        onFocus={() => this.track("focus")}
        ref={this.handleRef}
      />
    );
  }
}
```

## Options

| Option                   | Default    | What it does                                                                                        |
| ------------------------ | ---------- | --------------------------------------------------------------------------------------------------- |
| `eventHandlerPrefix`     | `"handle"` | The prefix of a handler function.                                                                   |
| `eventHandlerPropPrefix` | `"on"`     | The prefix of a prop that takes a handler.                                                          |
| `checkLocalVariables`    | `false`    | Also check handlers that are plain variables, such as `onChange={updateName}`.                      |
| `checkInlineFunction`    | `false`    | Also check the function that an arrow function calls, such as `onChange={() => this.updateName()}`. |
| `ignoreComponentNames`   | `[]`       | Components that are not checked. A name can be a glob pattern.                                      |

Function components keep their handlers in local variables, so they need `checkLocalVariables`:

{/* bad {"options": [{"checkLocalVariables": true}]} */}

```jsx
function Form() {
  const updateName = event => setName(event.target.value);
  return <Input onChange={updateName} />;
}
```

{/* good {"options": [{"checkLocalVariables": true}]} */}

```jsx
function Form() {
  const handleChange = event => setName(event.target.value);
  return <Input onChange={handleChange} />;
}
```

{/* bad {"options": [{"checkInlineFunction": true}]} */}

```jsx
const field = <Input onChange={() => this.updateName()} />;
```

{/* bad {"options": [{"eventHandlerPrefix": "do", "eventHandlerPropPrefix": "when"}]} */}

```jsx
const field = <Input whenChange={this.handleChange} />;
```

{/* good {"options": [{"ignoreComponentNames": ["Legacy*"]}]} */}

```jsx
const field = <LegacyInput onChange={this.updateName} />;
```

Either prefix can also be `false`. Each check compares a prop's name with a function's name, so without one of the prefixes nothing is reported:

{/* good {"options": [{"eventHandlerPropPrefix": false}]} */}

```jsx
const field = <Input onChange={this.updateName} blur={this.handleBlur} />;
```

{/* good {"options": [{"eventHandlerPrefix": false}]} */}

```jsx
const field = <Input onChange={this.updateName} blur={this.handleBlur} />;
```
