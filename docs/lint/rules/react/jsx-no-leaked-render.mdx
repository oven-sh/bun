---
title: "react/jsx-no-leaked-render"
description: "Disallow `&&` conditions in JSX that can render `0`, `NaN` or an empty string"
---

`{count && <List />}` evaluates to `count` when `count` is falsy. React renders nothing for `false`, `null` and `undefined`, but it does render `0` and `NaN`, so an empty list shows a stray `0` on the page. In React Native, a number or a string outside of `<Text>` crashes the app.

The rule reports `&&` in JSX braces, in children and in props, unless its left side looks like a boolean: a `!` or `!!`, a comparison, a call such as `Boolean(count)`, or a variable declared as `true` or `false`. It does not look at what a call returns.

`--fix` rewrites the condition with the first of the allowed strategies.

## Examples

Reported:

{/* bad {"count": 2} */}

```jsx
function Cart({ items, note }) {
  return <Panel footer={note && <Note text={note} />}>{items.length && <List items={items} />}</Panel>;
}
```

Not reported:

{/* good */}

```jsx
function Cart({ items }) {
  return (
    <div>
      {items.length > 0 && <List items={items} />}
      {!!items.length && <Total items={items} />}
      {Boolean(items.length) && <Coupon />}
      {items.length ? <Checkout /> : null}
    </div>
  );
}
```

## Options

| Option            | Default                 | What it does                                                                                                                         |
| ----------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `validStrategies` | `["ternary", "coerce"]` | The ways to write a condition that are allowed. `"ternary"` is `test ? <A /> : null`. `"coerce"` is `&&` with a boolean on the left. |

With only `"ternary"`, every `&&` is reported:

{/* bad {"options": [{"validStrategies": ["ternary"]}]} */}

```jsx
const cart = <div>{!!items.length && <List items={items} />}</div>;
```

{/* good {"options": [{"validStrategies": ["ternary"]}]} */}

```jsx
const cart = <div>{items.length ? <List items={items} /> : null}</div>;
```

With only `"coerce"`, a ternary that ends in `null` or `false` is reported:

{/* bad {"options": [{"validStrategies": ["coerce"]}]} */}

```jsx
const cart = <div>{items.length ? <List items={items} /> : null}</div>;
```

{/* good {"options": [{"validStrategies": ["coerce"]}]} */}

```jsx
const cart = <div>{items.length > 0 && <List items={items} />}</div>;
```

## When not to use it

The rule does not know types. It also reports a left side that can only be an object, a boolean prop or `undefined`, where nothing can leak.
