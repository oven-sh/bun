---
title: "react-hooks/no-did-update-set-state"
description: "Disallow `this.setState()` in `componentDidUpdate`"
---

`componentDidUpdate` runs after every update, and `setState` causes an update. A call that is not behind a condition loops forever. One that is behind a condition still renders the component twice for each change.

A `setState` in a callback inside `componentDidUpdate` is allowed by default, because it runs later: when a request finishes or an event fires.

If your ESLint config sets `settings.react.version` to 16.3 or later, the rule reports nothing.

## Examples

Reported:

{/* bad */}

```jsx
class Cart extends React.Component {
  componentDidUpdate() {
    this.setState({ total: sum(this.props.items) });
  }
}
```

Not reported:

{/* good */}

```jsx
class Cart extends React.Component {
  componentDidUpdate(previous) {
    if (previous.coupon !== this.props.coupon) {
      checkCoupon(this.props.coupon).then(discount => {
        this.setState({ discount });
      });
    }
  }

  render() {
    return <Total value={sum(this.props.items)} />;
  }
}
```

## Options

| Option               | What it does                                                      |
| -------------------- | ----------------------------------------------------------------- |
| `"disallow-in-func"` | Also report `setState` in a function inside `componentDidUpdate`. |

{/* bad {"options": ["disallow-in-func"]} */}

```jsx
class Cart extends React.Component {
  componentDidUpdate() {
    checkCoupon(this.props.coupon).then(discount => {
      this.setState({ discount });
    });
  }
}
```
