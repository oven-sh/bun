---
title: "react/no-unescaped-entities"
description: 'Disallow `"` and `''` as plain characters in JSX text'
---

A stray `"` or `'` in JSX text is often a slip: a quote that was meant to end an attribute lands after the `>` of the tag, and it shows up on the page.

If you do want the character, write it as an HTML entity, or put the text in a string inside braces. In an editor, the rule suggests the entities to replace it with.

The default list also has `>` and `}`. In JSX text these two are syntax errors, so you get a parsing error for them and not a report of this rule.

## Examples

Reported:

{/* bad {"count": 1} */}

```jsx
const label = <label htmlFor="name">" Your name</label>;
```

{/* bad {"count": 1} */}

```jsx
const note = <p>Don't close this window.</p>;
```

Not reported:

{/* good */}

```jsx
const note = <p>Don&apos;t close this window.</p>;

const hint = <p>{"Don't close this window."}</p>;
```

## Options

| Option   | Default            | What it does                                                   |
| -------- | ------------------ | -------------------------------------------------------------- |
| `forbid` | `>`, `"`, `'`, `}` | The characters to report. Your list replaces the default list. |

An item of `forbid` is a single character, or an object with the character and the entities to name in the message and to suggest: `{ "char": "\"", "alternatives": ["&quot;"] }`.

Here only `"` is forbidden. The two quotes are reported and the apostrophe is not:

{/* bad {"count": 2, "options": [{"forbid": ["\""]}]} */}

```jsx
const note = <p>Don't press "Delete".</p>;
```

{/* good {"options": [{"forbid": ["\""]}]} */}

```jsx
const note = <p>Don't press &quot;Delete&quot;.</p>;
```

## When not to use it

In text with many apostrophes and quotes, the entities make the source hard to read. Leave the rule off there, or shorten `forbid`.
