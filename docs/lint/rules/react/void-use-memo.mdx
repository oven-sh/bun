---
title: "react-hooks/void-use-memo"
description: "Require `useMemo()` callbacks to return a value, and the value to be used"
---

`useMemo()` caches what its callback returns. A callback that returns nothing caches `undefined`, which usually means a forgotten `return`, or a side effect that belongs in `useEffect()`. React can skip or repeat the callback, so a side effect in it does not run when you expect.

The rule also reports a `useMemo()` call with a result that nobody uses.

## Examples

Reported:

{/* bad */}

```jsx
import { useMemo } from "react";

function Report({ rows }) {
  const visible = useMemo(() => {
    rows.filter(row => !row.hidden);
  }, [rows]);
  return <Table rows={visible} />;
}
```

{/* bad */}

```jsx
import { useMemo } from "react";

function Report({ rows }) {
  useMemo(() => rows.filter(row => !row.hidden), [rows]);
  return <Table rows={rows} />;
}
```

Not reported:

{/* good */}

```jsx
import { useMemo } from "react";

function Report({ rows }) {
  const visible = useMemo(() => {
    return rows.filter(row => !row.hidden);
  }, [rows]);
  return <Table rows={visible} />;
}
```

A side effect goes in an effect:

{/* good */}

```jsx
import { useEffect } from "react";

function Report({ rows }) {
  useEffect(() => {
    track("report", rows.length);
  }, [rows]);
  return <Table rows={rows} />;
}
```
