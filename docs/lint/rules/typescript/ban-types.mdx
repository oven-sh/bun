---
title: "@typescript-eslint/ban-types"
description: "Disallow `String`, `Number`, `Object`, `Function`, `{}` and similar types"
---

Some built-in types do not mean what they look like:

- `String`, `Number`, `Boolean`, `Symbol`, and `BigInt` are the wrapper objects. You almost always want the lowercase `string`, `number`, `boolean`, `symbol`, or `bigint`.
- `Function` accepts any function, and calling it returns `any`, so arguments and results are not checked.
- `Object` and `{}` accept every value except `null` and `undefined`, including `0` and `""`.

Names that a class `implements` or an interface `extends` are not reported.

## Examples

Reported:

{/* bad {"count": 2} */}

```ts
function greet(name: String, onDone: Function) {
  onDone(`Hello, ${name}`);
}
```

{/* bad {"count": 2} */}

```ts
let settings: {} = 0;
let extra: Object = "";
```

Not reported:

{/* good */}

```ts
function greet(name: string, onDone: (message: string) => void) {
  onDone(`Hello, ${name}`);
}

let settings: Record<string, unknown> = {};
let extra: object = {};

interface Handler extends Function {
  priority: number;
}
```

## When not to use it

Three newer rules split the same checks, so you can turn each on by itself: `@typescript-eslint/no-wrapper-object-types`, `@typescript-eslint/no-unsafe-function-type`, and `@typescript-eslint/no-empty-object-type`.
