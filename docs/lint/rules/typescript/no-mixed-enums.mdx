---
title: "@typescript-eslint/no-mixed-enums"
description: "Disallow enums that have both number and string members"
---

Number members and string members of an enum behave differently. A number member gets a reverse mapping, so `Status[0]` is `"Active"`, and `Object.values(Status)` holds the names next to the numbers. A string member gets neither. In an enum with both, code that loops over the members or looks one up by value has to handle two shapes.

The first member decides the kind. The first member of the other kind is reported. An enum that is declared in several parts counts as one.

This rule needs type information. Run `bun lint --type-aware`.

## Examples

Reported:

{/* bad */}

```ts
enum Status {
  Active,
  Archived = "archived",
}
```

Not reported:

{/* good */}

```ts
enum Status {
  Active = "active",
  Archived = "archived",
}

enum Priority {
  Low,
  High,
}
```

The second part of this enum does not match the first:

{/* bad */}

```ts
enum Color {
  Red = "red",
}

enum Color {
  Green = 1,
}
```
