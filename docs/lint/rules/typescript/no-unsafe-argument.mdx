---
title: "@typescript-eslint/no-unsafe-argument"
description: "Disallow passing a value of type `any` as an argument"
---

The compiler accepts `any` for every parameter. Pass an `any` to a function that wants a `number` and nothing checks that it is one. The function then runs with whatever came in.

The rule also reports `any` inside a generic type, such as a `Set<any>` passed where a `Set<string>` is expected, and spreading an `any`, an `any[]` or a tuple with an `any` element into the arguments.

This rule needs type information. Run `bun lint --type-aware`. With that flag, it is on by default in TypeScript files.

## Examples

Reported:

{/* bad {"count": 3} */}

```ts
declare function resize(width: number, height: number): void;
declare function addTags(tags: Set<string>): void;

const config = JSON.parse("{}");

resize(config.width, 100);
resize(...config.size);
addTags(new Set<any>());
```

Not reported:

{/* good */}

```ts
declare function resize(width: number, height: number): void;
declare function addTags(tags: Set<string>): void;

const config = JSON.parse("{}") as { width: number; size: [number, number] };

resize(config.width, 100);
resize(...config.size);
addTags(new Set<string>());
```

A parameter of type `unknown` or `any` accepts an `any`:

{/* good */}

```ts
declare function log(value: unknown): void;
declare function debug(value: any): void;

log(JSON.parse("{}"));
debug(JSON.parse("{}"));
```

## When not to use it

In a codebase that is still moving from JavaScript to TypeScript, `any` is everywhere and the reports drown out the rest. Turn the rule on once most values have real types.
