---
title: "@typescript-eslint/no-unsafe-assignment"
description: "Disallow assigning a value of type `any` to a variable or a property"
---

A variable that is given an `any` becomes `any` itself, or claims a type that nobody checked. From there every property read, call and argument goes unchecked too, far from the place where the `any` came in.

The rule checks variable declarations, assignments, default values, class properties, object properties, JSX attributes, destructuring and array spreads. It also reports `any` inside a generic type, such as a `Set<any>` assigned to a `Set<string>`.

This rule needs type information. Run `bun lint --type-aware`. With that flag, it is on by default in TypeScript files.

## Examples

Reported:

{/* bad {"count": 4} */}

```ts
const config = JSON.parse("{}");
const port: number = JSON.parse("8080");
const { host } = JSON.parse("{}") as { host: any };
const tags: Set<string> = new Set<any>();
```

Not reported:

{/* good */}

```ts
interface Config {
  host: string;
  port: number;
}

const config = JSON.parse("{}") as Config;
const { host } = config;
const tags: Set<string> = new Set<string>();
```

Assigning an `any` to something declared as `unknown` is allowed. That is the safe way to receive a value you know nothing about:

{/* good */}

```ts
const data: unknown = JSON.parse("{}");

if (typeof data === "string") {
  console.log(data.length);
}
```

## When not to use it

In a codebase that is still moving from JavaScript to TypeScript, `any` is everywhere and the reports drown out the rest. Turn the rule on once most values have real types.
