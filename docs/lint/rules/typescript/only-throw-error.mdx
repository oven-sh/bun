---
title: "@typescript-eslint/only-throw-error"
description: "Disallow throwing values that are not `Error` objects"
---

You can `throw` any value, but only an `Error` records the stack at the place where it was created. Code that catches it also expects an `Error`: with `throw "not found"`, `error.message` is `undefined` and `error instanceof Error` is `false`.

By default, values of type `any` or `unknown` may be thrown, and so may an error that you caught.

This rule needs type information. Run `bun lint --type-aware`.

## Examples

Reported:

{/* bad {"count": 3} */}

```ts
function load(path: string, status: number) {
  if (!path) throw "path is required";
  if (status === 404) throw { status };
  throw undefined;
}
```

Not reported:

{/* good */}

```ts
class HttpError extends Error {
  constructor(public status: number) {
    super(`Request failed with ${status}`);
  }
}

function load(path: string, status: number) {
  if (!path) throw new Error("path is required");
  throw new HttpError(status);
}
```

## Options

| Option                 | Default | What it does                                                                                                                          |
| ---------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `allowThrowingAny`     | `true`  | Allow throwing a value of type `any`.                                                                                                 |
| `allowThrowingUnknown` | `true`  | Allow throwing a value of type `unknown`.                                                                                             |
| `allowRethrowing`      | `true`  | Allow throwing the `error` of `catch (error)`, of `.catch(error => ...)`, and of the second callback of `.then()`, whatever its type. |
| `allow`                | `[]`    | Other types that may be thrown.                                                                                                       |

{/* bad {"options": [{"allowThrowingAny": false}]} */}

```ts
function fail(reason: any) {
  throw reason;
}
```

In strict mode, the `error` of a `catch` is `unknown`. With `allowThrowingUnknown: false`, you can still throw it again:

{/* good {"options": [{"allowThrowingUnknown": false}]} */}

```ts
function parse(text: string): unknown {
  try {
    return JSON.parse(text);
  } catch (error) {
    console.error("invalid JSON");
    throw error;
  }
}
```

{/* bad {"options": [{"allowThrowingUnknown": false, "allowRethrowing": false}]} */}

```ts
function parse(text: string): unknown {
  try {
    return JSON.parse(text);
  } catch (error) {
    console.error("invalid JSON");
    throw error;
  }
}
```

An entry of `allow` is the name of a type, or an object that also says where the type comes from: `{ "from": "file", "name": "Redirect" }` for your own code, `{ "from": "lib", "name": "Response" }` for a built-in type, or `{ "from": "package", "name": "Redirect", "package": "my-router" }`.

{/* good {"options": [{"allow": [{"from": "file", "name": "Redirect"}]}]} */}

```ts
class Redirect {
  constructor(public url: string) {}
}

throw new Redirect("/login");
```
