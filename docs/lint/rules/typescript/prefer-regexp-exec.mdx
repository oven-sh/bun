---
title: "@typescript-eslint/prefer-regexp-exec"
description: "Require `pattern.exec(text)` instead of `text.match(pattern)` when there is no `g` flag"
---

What `text.match(pattern)` returns depends on the flags of `pattern`. With `g` it is a list of all matches without their groups. Without `g` it is the first match with its groups, which is what `pattern.exec(text)` returns. If you use `exec` for one match and keep `match` for the `g` flag, the method name says which of the two you get.

A call is only reported if the rule can tell that there is no `g` flag. A regular expression that comes in as a parameter is left alone.

`--fix` rewrites the call. A string argument becomes a regular expression: `text.match("v1")` becomes `/v1/.exec(text)`.

This rule needs type information. Run `bun lint --type-aware`.

## Examples

Reported:

{/* bad {"count": 2} */}

```ts
function version(text: string) {
  return text.match(/v(\d+)/) ?? text.match("latest");
}
```

Not reported:

{/* good */}

```ts
function version(text: string) {
  return /v(\d+)/.exec(text) ?? /latest/.exec(text);
}

function numbers(text: string) {
  return text.match(/\d+/g);
}

function search(text: string, pattern: RegExp) {
  return text.match(pattern);
}
```
