---
title: "@typescript-eslint/return-await"
description: "Enforce consistent use of `await` when an `async` function returns a promise"
---

Inside a `try` block, `return save()` leaves the function before the promise settles. If it rejects, the `catch` does not run, and the `finally` runs too early. `return await save()` keeps the function inside the `try` until the promise is done.

The same goes for a `catch` block that is followed by a `finally`, and for code after a `using` declaration, where the resource is disposed as soon as the function returns. By default the rule requires `await` in those places and reports it everywhere else. An `await` on a returned value that is not a promise is always reported.

`--fix` adds or removes the `await` where that does not affect error handling. In a `try` or after `using`, the change is a suggestion in your editor instead.

This rule needs type information. Run `bun lint --type-aware`.

## Examples

Reported:

{/* bad {"count": 2} */}

```ts
async function save(data: string): Promise<void> {}

async function trySave(data: string) {
  try {
    return save(data);
  } catch (error) {
    console.error("not reached when save() rejects", error);
  }
}

async function saveDraft() {
  return await save("draft");
}
```

Not reported:

{/* good */}

```ts
async function save(data: string): Promise<void> {}

async function trySave(data: string) {
  try {
    return await save(data);
  } catch (error) {
    console.error("could not save", error);
  }
}

async function saveDraft() {
  return save("draft");
}
```

Here the connection is closed before the query is done:

{/* bad */}

```ts
declare function connect(): Disposable & { query(sql: string): Promise<string[]> };

async function listUsers() {
  using db = connect();
  return db.query("SELECT name FROM users");
}
```

## Options

```toml bunfig.toml
[lint.rules]
"@typescript-eslint/return-await" = ["error", "always"]
```

| Option                              | In a `try`, or after `using` | Everywhere else  |
| ----------------------------------- | ---------------------------- | ---------------- |
| `"in-try-catch"` (default)          | `await` required             | `await` reported |
| `"error-handling-correctness-only"` | `await` required             | not checked      |
| `"always"`                          | `await` required             | `await` required |
| `"never"`                           | `await` reported             | `await` reported |

`"always"` keeps the function in the stack trace of an error from the promise it returns. With it, this is reported:

{/* bad {"options": ["always"]} */}

```ts
async function save(data: string): Promise<void> {}

async function saveDraft() {
  return save("draft");
}
```

`"error-handling-correctness-only"` accepts both forms outside of a `try`:

{/* good {"options": ["error-handling-correctness-only"]} */}

```ts
async function save(data: string): Promise<void> {}

async function saveDraft() {
  return await save("draft");
}

async function saveFinal() {
  return save("final");
}
```
