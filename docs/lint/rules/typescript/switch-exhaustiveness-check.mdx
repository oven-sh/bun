---
title: "@typescript-eslint/switch-exhaustiveness-check"
description: "Require a `switch` on a union or an enum to have a `case` for every member"
---

When you add a member to a union or an enum, every `switch` on it needs a new `case`. TypeScript does not tell you which ones. The new value falls through the `switch` and nothing happens, or it lands in a `default` that was written for something else.

This rule reports a `switch` on a union of literals or an enum that does not list every member, and names the ones that are missing. By default a `default` clause does not count as covering them.

This rule needs type information. Run `bun lint --type-aware`.

## Examples

Reported:

{/* bad */}

```ts
type Status = "open" | "closed" | "merged";

function label(status: Status) {
  switch (status) {
    case "open":
      return "Open";
    case "closed":
      return "Closed";
  }
}
```

Not reported:

{/* good */}

```ts
type Status = "open" | "closed" | "merged";

function label(status: Status) {
  switch (status) {
    case "open":
      return "Open";
    case "closed":
      return "Closed";
    case "merged":
      return "Merged";
  }
}
```

## Options

| Option                                | Default                       | What it does                                                                                            |
| ------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------- |
| `considerDefaultExhaustiveForUnions`  | `false`                       | Let a `default` clause cover the members that have no `case`.                                           |
| `allowDefaultCaseForExhaustiveSwitch` | `true`                        | With `false`, report a `default` clause on a `switch` that already lists every member.                  |
| `requireDefaultForNonUnion`           | `false`                       | Require a `default` clause when the value is not a union of literals, such as a `string` or a `number`. |
| `defaultCaseCommentPattern`           | `^no default$`, ignoring case | A regular expression. A comment after the last `case` that matches it counts as a `default` clause.     |

By default `"closed"` and `"merged"` are reported as missing here. With `considerDefaultExhaustiveForUnions`, the `default` covers them:

{/* bad */}

```ts
function isOpen(status: "open" | "closed" | "merged") {
  switch (status) {
    case "open":
      return true;
    default:
      return false;
  }
}
```

A `default` on a complete `switch` hides the next member you add. With `allowDefaultCaseForExhaustiveSwitch` off, it is reported:

{/* bad {"options": [{"allowDefaultCaseForExhaustiveSwitch": false}]} */}

```ts
function isOpen(status: "open" | "closed") {
  switch (status) {
    case "open":
      return true;
    case "closed":
      return false;
    default:
      throw new Error("unknown status");
  }
}
```

With `requireDefaultForNonUnion`, a `switch` on a `number` needs a `default`:

{/* bad {"options": [{"requireDefaultForNonUnion": true}]} */}

```ts
function describe(code: number) {
  switch (code) {
    case 404:
      return "Not found";
  }
}
```

A `// no default` comment says that you left it out on purpose:

{/* good {"options": [{"requireDefaultForNonUnion": true}]} */}

```ts
function log(code: number) {
  switch (code) {
    case 404:
      console.log("Not found");
    // no default
  }
}
```
