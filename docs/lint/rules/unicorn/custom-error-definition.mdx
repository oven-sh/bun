---
title: "unicorn/custom-error-definition"
description: "Enforce that subclasses of `Error` set `name` and pass the message to `super()`"
---

A class that extends `Error` inherits `name`, so without more work `String(new ValidationError("Bad email"))` is `"Error: Bad email"`, and a check such as `error.name === "ValidationError"` never matches.

The rule looks at every named class that extends `Error` or a class with a name like `TypeError` or `HttpError`. It reports:

- a `name` that is missing, or is anything other than the class name written as a string
- a constructor that does not call `super()`
- `this.message = message` instead of `super(message)`
- a class name that does not end in `Error` or does not start with a capital letter
- `exports.A = class B extends Error`, where the two names differ

## Examples

Reported:

{/* bad {"count": 1} */}

```js
class ValidationError extends Error {}
```

{/* bad {"count": 2} */}

```js
class ValidationError extends Error {
  constructor(message) {
    super();
    this.message = message;
    this.name = this.constructor.name;
  }
}
```

{/* bad {"count": 1} */}

```js
class Validation extends Error {
  name = "Validation";
}
```

Not reported:

{/* good */}

```js
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}
```

A class field works too:

{/* good */}

```js
class ValidationError extends Error {
  name = "ValidationError";
}
```
