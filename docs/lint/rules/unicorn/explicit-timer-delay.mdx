---
title: "unicorn/explicit-timer-delay"
description: "Require or disallow an explicit delay for `setTimeout()` and `setInterval()`"
---

`setTimeout(callback)` runs the callback as soon as it can, as if the delay were `0`. A reader cannot tell whether that is on purpose or the delay was forgotten. For `setInterval()` a forgotten delay means a callback that runs over and over without a pause. Writing `0` shows that you meant it.

The rule also checks the timers on `window`, `globalThis`, `self` and `global`.

`--fix` adds `, 0`. With `"never"`, it removes the `0`.

## Examples

Reported:

{/* bad {"count": 2} */}

```js
setTimeout(() => input.focus());

window.setInterval(poll);
```

Not reported:

{/* good */}

```js
setTimeout(() => input.focus(), 0);

window.setInterval(poll, 1000);
```

## Options

| Option               | What it does                                                                 |
| -------------------- | ---------------------------------------------------------------------------- |
| `"always"` (default) | Report a timer without a delay.                                              |
| `"never"`            | Report a delay of `0`, which is the same as no delay. Other delays are fine. |

{/* bad {"options": ["never"]} */}

```js
setTimeout(() => input.focus(), 0);
```

{/* good {"options": ["never"]} */}

```js
setTimeout(() => input.focus());

setTimeout(() => input.blur(), 200);
```
