---
title: "unicorn/no-array-reverse"
description: "Require `toReversed()` instead of `reverse()`, which changes the array"
---

`reverse()` reverses the array in place and returns that same array. After `const newestFirst = posts.reverse()`, `posts` is reversed too. `toReversed()` returns a new array and leaves the original alone.

`--fix-suggestions` replaces `reverse` with `toReversed`.

## Examples

Reported:

{/* bad */}

```js
const newestFirst = posts.reverse();
```

A copy made only to reverse it is reported too, because `toReversed()` already copies:

{/* bad */}

```js
const newestFirst = [...posts].reverse();
```

Not reported:

{/* good */}

```js
const newestFirst = posts.toReversed();
```

A call that is a statement of its own is allowed by default. Nothing uses the result, so changing the array is the point:

{/* good */}

```js
posts.reverse();
```

## Options

| Option                     | Default | What it does                                        |
| -------------------------- | ------- | --------------------------------------------------- |
| `allowExpressionStatement` | `true`  | Allow `array.reverse();` as a statement of its own. |

{/* bad {"options": [{"allowExpressionStatement": false}]} */}

```js
posts.reverse();
```

## When not to use it

`toReversed()` is part of ES2023. Turn the rule off if your code has to run where that method does not exist.
