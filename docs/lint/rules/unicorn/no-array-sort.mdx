---
title: "unicorn/no-array-sort"
description: "Require `toSorted()` instead of `sort()`, which changes the array"
---

`sort()` sorts the array in place and returns that same array. After `const ranked = players.sort(byScore)`, `players` is sorted too. `toSorted()` returns a new array and leaves the original alone.

`--fix-suggestions` replaces `sort` with `toSorted`.

## Examples

Reported:

{/* bad */}

```js
const ranked = players.sort((a, b) => b.score - a.score);
```

A copy made only to sort it is reported too, because `toSorted()` already copies:

{/* bad */}

```js
const ranked = [...players].sort((a, b) => b.score - a.score);
```

Not reported:

{/* good */}

```js
const ranked = players.toSorted((a, b) => b.score - a.score);
```

A call that is a statement of its own is allowed by default. Nothing uses the result, so changing the array is the point:

{/* good */}

```js
players.sort((a, b) => b.score - a.score);
```

If the argument cannot be a compare function, such as an object or a string, `sort` belongs to something else, for example a database query:

{/* good */}

```js
const recent = await db.posts.find().sort({ createdAt: -1 });
```

## Options

| Option                     | Default | What it does                                     |
| -------------------------- | ------- | ------------------------------------------------ |
| `allowExpressionStatement` | `true`  | Allow `array.sort();` as a statement of its own. |
| `allowAfterSpread`         | `false` | Allow `[...array].sort()`.                       |

{/* bad {"options": [{"allowExpressionStatement": false}]} */}

```js
players.sort((a, b) => b.score - a.score);
```

{/* good {"options": [{"allowAfterSpread": true}]} */}

```js
const ranked = [...players].sort((a, b) => b.score - a.score);
```

## When not to use it

`toSorted()` is part of ES2023. Turn the rule off if your code has to run where that method does not exist.
