---
title: "unicorn/prefer-bigint-literals"
description: "Require `BigInt` literals such as `123n` instead of `BigInt(123)`"
---

`BigInt(123)` and `BigInt("123")` call a function to make a value you can write as `123n`. With a large number the call is also wrong: `BigInt(9007199254740993)` rounds the number before `BigInt` sees it, and gives `9007199254740992n`.

`--fix` replaces the call with the literal.

## Examples

Reported:

{/* bad {"count": 3} */}

```js
const zero = BigInt(0);
const limit = BigInt("9007199254740993");
const mask = BigInt(0xff);
```

Not reported:

{/* good */}

```js
const zero = 0n;
const limit = 9007199254740993n;
const mask = 0xffn;
```

A value that is only known when the code runs still needs the call:

{/* good */}

```js
const id = BigInt(row.id);
const size = BigInt(`${count}000`);
```
