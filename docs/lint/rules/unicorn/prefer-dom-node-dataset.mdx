---
title: "unicorn/prefer-dom-node-dataset"
description: "Require `.dataset` instead of the attribute methods for `data-*` attributes"
---

Every `data-*` attribute of an element is also a property of `element.dataset`, with the name in camel case: `data-user-id` is `dataset.userId`. Reading and writing a property is shorter than calling `getAttribute()`, `setAttribute()`, `hasAttribute()` or `removeAttribute()` with a string.

`--fix` rewrites the call. `setAttribute()` and `removeAttribute()` are only rewritten when the call is a statement on its own.

## Examples

Reported:

{/* bad {"count": 4} */}

```js
element.setAttribute("data-user-id", user.id);
const id = element.getAttribute("data-user-id");

if (element.hasAttribute("data-user-id")) {
  element.removeAttribute("data-user-id");
}
```

Not reported:

{/* good */}

```js
element.dataset.userId = user.id;
const id = element.dataset.userId;

if (Object.hasOwn(element.dataset, "userId")) {
  delete element.dataset.userId;
}
```

Other attributes are not reported. Neither is an awaited `getAttribute()`, because that is most likely a Playwright locator and not a DOM element:

{/* good */}

```js
element.setAttribute("aria-label", label);
const id = await page.locator(".user").getAttribute("data-user-id");
```

## When not to use it

For a missing attribute, `getAttribute()` returns `null` and `dataset` gives `undefined`. Check comparisons with `null` before you apply the fix.
