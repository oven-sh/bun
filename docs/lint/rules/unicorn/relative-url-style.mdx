---
title: "unicorn/relative-url-style"
description: "Enforce one style for relative URLs in `new URL()`: with or without `./`"
---

`new URL("./logo.png", base)` and `new URL("logo.png", base)` give the same URL. Pick one style so that the same file is written and searched for the same way everywhere.

Only `new URL()` with two arguments is checked, and only where adding or removing `./` does not change the result. `"../logo.png"` and `"/logo.png"` are never reported.

`--fix` removes or adds the `./` in a string. For a template literal, the editor offers the change as a suggestion.

## Examples

Reported:

{/* bad {"count": 2} */}

```js
const logo = new URL("./logo.png", import.meta.url);
const icon = new URL(`./${name}.svg`, import.meta.url);
```

Not reported:

{/* good */}

```js
const logo = new URL("logo.png", import.meta.url);
const icon = new URL(`${name}.svg`, import.meta.url);
const shared = new URL("../shared/logo.png", import.meta.url);
```

## Options

| Option              | What it does                                                                      |
| ------------------- | --------------------------------------------------------------------------------- |
| `"never"` (default) | Report a string or a template literal that starts with `./`.                      |
| `"always"`          | Report a string that does not start with `./`. Template literals are not checked. |

{/* bad {"options": ["always"]} */}

```js
const logo = new URL("logo.png", import.meta.url);
```

{/* good {"options": ["always"]} */}

```js
const logo = new URL("./logo.png", import.meta.url);
const icon = new URL(`${name}.svg`, import.meta.url);
const shared = new URL("../shared/logo.png", import.meta.url);
```
