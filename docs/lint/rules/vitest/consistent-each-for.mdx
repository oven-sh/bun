---
title: "vitest/consistent-each-for"
description: "Enforce either `.each` or `.for` for parameterized tests"
---

Vitest has two ways to run a test once per row of data. `test.each` spreads an array row into separate arguments. `test.for` passes the row as one argument. When a project mixes them, you have to check which one a test uses before you can read its callback's parameters.

The rule reports nothing until you choose a method for at least one function.

## Examples

```toml bunfig.toml
[lint.rules]
"vitest/consistent-each-for" = ["error", { test = "for" }]
```

Reported:

{/* bad {"options": [{"test": "for"}]} */}

```ts
import { expect, test } from "vitest";

test.each([
  [1, 2, 3],
  [2, 3, 5],
])("adds %i and %i", (a, b, sum) => {
  expect(a + b).toBe(sum);
});
```

Not reported:

{/* good {"options": [{"test": "for"}]} */}

```ts
import { expect, test } from "vitest";

test.for([
  [1, 2, 3],
  [2, 3, 5],
])("adds %i and %i", ([a, b, sum]) => {
  expect(a + b).toBe(sum);
});
```

## Options

Each option takes `"each"` or `"for"`, the method you want. A function you leave out is not checked.

| Option     | Default     | What it does               |
| ---------- | ----------- | -------------------------- |
| `test`     | not checked | The method for `test`.     |
| `it`       | not checked | The method for `it`.       |
| `describe` | not checked | The method for `describe`. |
| `suite`    | not checked | The method for `suite`.    |

`test` and `it` are separate settings. With only `test` set, `it.each` is allowed:

{/* good {"options": [{"test": "for"}]} */}

```ts
import { expect, it } from "vitest";

it.each([1, 2, 3])("accepts %i", value => {
  expect(value).toBeGreaterThan(0);
});
```

{/* bad {"options": [{"describe": "each"}]} */}

```ts
import { describe, expect, test } from "vitest";

describe.for(["sqlite", "postgres"])("with %s", driver => {
  test("has a name", () => {
    expect(driver).not.toBe("");
  });
});
```
