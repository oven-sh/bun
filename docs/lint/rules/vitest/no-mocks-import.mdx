---
title: "vitest/no-mocks-import"
description: "Disallow importing from a `__mocks__` directory"
---

Vitest picks up the files in `__mocks__` by itself when you call `vi.mock()`. If you import one by its path, the test gets a second copy of the module. The code under test calls one copy and your assertions look at the other, so `toHaveBeenCalled()` fails although the call happened.

Import the real path and mock it. The test and the code under test then share the same mock.

A path is reported if one of its segments is exactly `__mocks__`, in an `import` or in a `require()`.

## Examples

Reported:

{/* bad */}

```ts
import { expect, test } from "vitest";
import { sendEmail } from "./__mocks__/mailer";
import { register } from "./register";

test("sends a welcome email", () => {
  register("ada@example.com");
  expect(sendEmail).toHaveBeenCalled();
});
```

{/* bad */}

```js
const { sendEmail } = require("../__mocks__/mailer");
```

Not reported:

{/* good */}

```ts
import { expect, vi, test } from "vitest";
import { sendEmail } from "./mailer";
import { register } from "./register";

vi.mock("./mailer");

test("sends a welcome email", () => {
  register("ada@example.com");
  expect(sendEmail).toHaveBeenCalled();
});
```
