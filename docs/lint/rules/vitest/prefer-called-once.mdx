---
title: "vitest/prefer-called-once"
description: "Require `toHaveBeenCalledOnce()` instead of `toHaveBeenCalledTimes(1)`"
---

`toHaveBeenCalledTimes(1)` and `toHaveBeenCalledOnce()` assert the same thing. This rule picks the shorter one, so a project writes it one way. The aliases are covered too: `toBeCalledTimes(1)` becomes `toBeCalledOnce()`.

`--fix` rewrites the matcher.

## Examples

Reported:

{/* bad */}

```ts
import { expect, test, vi } from "vitest";

test("notifies the listener", () => {
  const listener = vi.fn();
  publish("ready", listener);
  expect(listener).toHaveBeenCalledTimes(1);
});
```

Not reported:

{/* good */}

```ts
import { expect, test, vi } from "vitest";

test("notifies the listener", () => {
  const listener = vi.fn();
  publish("ready", listener);
  expect(listener).toHaveBeenCalledOnce();

  publish("done", listener);
  expect(listener).toHaveBeenCalledTimes(2);
});
```

## When not to use it

`vitest/prefer-called-times` asks for the opposite. Turn on one of the two, not both.
