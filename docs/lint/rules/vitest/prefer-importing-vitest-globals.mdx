---
title: "vitest/prefer-importing-vitest-globals"
description: "Require `describe`, `test`, `expect` and `vi` to be imported from `vitest`"
---

With `globals: true` in the Vitest config, `describe`, `test`, `expect`, `vi` and the hooks exist without an import. A file that relies on that fails with a `ReferenceError` as soon as the setting is off, and nothing in the file says where the names come from.

A file gets one report for all the names it uses.

`--fix` adds the import, or adds the names to the import from `vitest` that is already there.

## Examples

Reported:

{/* bad {"count": 1} */}

```ts
describe("cart", () => {
  test("starts empty", () => {
    expect(cart.items).toHaveLength(0);
  });
});
```

Not reported:

{/* good */}

```ts
import { describe, expect, test } from "vitest";

describe("cart", () => {
  test("starts empty", () => {
    expect(cart.items).toHaveLength(0);
  });
});
```

A call of one of these names is also reported if the name is imported from another package:

{/* bad */}

```ts
import { test } from "node:test";

test("starts empty", () => {});
```

## When not to use it

Turn it off for files that use another test runner with the same names.
