---
title: "vitest/prefer-spy-on"
description: "Require `vi.spyOn()` instead of assigning `vi.fn()` to a property"
---

`Date.now = vi.fn()` throws the real `Date.now` away. Unless you saved it and put it back by hand, every test that runs afterwards gets the mock. `vi.spyOn(Date, "now")` remembers the original, so `mockRestore()` or `vi.restoreAllMocks()` brings it back.

A spy calls the original function until you give it an implementation, so the suggestion turns `obj.save = vi.fn()` into `vi.spyOn(obj, 'save').mockImplementation()`.

The rewrite is a suggestion in your editor. `--fix` does not apply it.

## Examples

Reported:

{/* bad {"count": 2} */}

```ts
import { beforeEach, vi } from "vitest";

beforeEach(() => {
  Date.now = vi.fn(() => 1700000000000);
  console.warn = vi.fn();
});
```

Not reported:

{/* good */}

```ts
import { afterEach, beforeEach, vi } from "vitest";

beforeEach(() => {
  vi.spyOn(Date, "now").mockImplementation(() => 1700000000000);
  vi.spyOn(console, "warn").mockImplementation(() => {});
});

afterEach(() => {
  vi.restoreAllMocks();
});
```

A mock that is stored in a variable or written in an object literal replaces nothing, so it is not reported:

{/* good */}

```ts
import { vi } from "vitest";

const onSave = vi.fn();
const logger = { warn: vi.fn() };
```
