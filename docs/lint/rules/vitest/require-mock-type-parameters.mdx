---
title: "vitest/require-mock-type-parameters"
description: "Require a type parameter on `vi.fn()`"
---

A plain `vi.fn()` stands for a function that takes any arguments and returns anything. TypeScript then accepts `mockReturnValue(42)` for a function that returns a string, and it says nothing when the real function changes and the mock no longer matches it. With a type parameter, the mock is checked like the function it replaces.

A mock with an implementation, such as `vi.fn(() => 1)`, is reported too. Only TypeScript files are checked.

## Examples

Reported:

{/* bad {"count": 2} */}

```ts
import { vi } from "vitest";

const findUser = vi.fn();
const log = vi.fn((message: string) => {});
```

Not reported:

{/* good */}

```ts
import { vi } from "vitest";

type User = { name: string };

const findUser = vi.fn<(id: string) => Promise<User>>();
const log = vi.fn<(message: string) => void>(message => {});
```

## Options

| Option                 | Default | What it does                                                                |
| ---------------------- | ------- | --------------------------------------------------------------------------- |
| `checkImportFunctions` | `false` | Also require a type parameter on `vi.importActual()` and `vi.importMock()`. |

{/* bad {"options": [{"checkImportFunctions": true}]} */}

```ts
import { vi } from "vitest";

const mailer = await vi.importActual("./mailer");
```

{/* good {"options": [{"checkImportFunctions": true}]} */}

```ts
import { vi } from "vitest";

const mailer = await vi.importActual<typeof import("./mailer")>("./mailer");
```
