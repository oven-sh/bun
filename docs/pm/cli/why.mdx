---
title: "bun why"
description: "Explain why a package is installed"
---

`bun why` explains why a package is installed in your project by showing the dependency chain that led to it.

## Usage

```bash terminal icon="terminal"
bun why <package>
```

## Arguments

- `<package>`: The name of the package to explain. Supports glob patterns like `@org/*` or `*-lodash`.

## Options

- `--top`: Show only the top-level dependencies instead of the complete dependency tree.
- `--depth <number>`: Maximum depth of the dependency tree to display.
- `--json`: Print the same tree as JSON. See [JSON output](#json-output).

## Examples

Check why a specific package is installed:

```bash terminal icon="terminal"
bun why react
```

```txt
react@18.2.0
  └─ my-app@1.0.0 (requires ^18.0.0)
```

Check why all packages matching a pattern are installed:

```bash terminal icon="terminal"
bun why "@types/*"
```

```txt
@types/react@18.2.15
  └─ dev my-app@1.0.0 (requires ^18.0.0)

@types/react-dom@18.2.7
  └─ dev my-app@1.0.0 (requires ^18.0.0)
```

Show only top-level dependencies:

```bash terminal icon="terminal"
bun why express --top
```

```txt
express@4.18.2
  └─ my-app@1.0.0 (requires ^4.18.2)
```

Limit the dependency tree depth:

```bash terminal icon="terminal"
bun why express --depth 2
```

```txt
express@4.18.2
  └─ express-pollyfill@1.20.1 (requires ^4.18.2)
     └─ body-parser@1.20.1 (requires ^1.20.1)
     └─ accepts@1.3.8 (requires ^1.3.8)
        └─ (deeper dependencies hidden)
```

## Understanding the Output

The output shows:

- The package name and version being queried
- The dependency chain that led to its installation
- The type of dependency (dev, peer, optional, or production)
- The version requirement specified in each package's dependencies

For nested dependencies, the command shows the complete dependency tree by default, with indentation indicating the relationship hierarchy.

## JSON output

Pass `--json` to get the tree as JSON, for scripts. Nothing else is written to stdout. The output is an array with one object per package that matches the pattern:

```bash terminal icon="terminal"
bun why body-parser --json
```

```json
[
  {
    "name": "body-parser",
    "version": "1.20.1",
    "dependents": [
      {
        "name": "express",
        "version": "4.18.2",
        "type": "dependencies",
        "optional": false,
        "spec": "1.20.1",
        "dependents": [
          {
            "name": "my-app",
            "version": null,
            "type": "dependencies",
            "optional": false,
            "spec": "^4.18.2",
            "dependents": []
          }
        ]
      }
    ]
  }
]
```

Each entry in `dependents` is one line of the text output:

- `name` and `version`: the package that depends on the parent entry. `version` is the resolution shown in the text output, for example `"4.18.2"` or `"workspace:packages/app"`. It is `null` for the root package.
- `type`: the `package.json` section the dependency is declared in: `dependencies`, `devDependencies`, `peerDependencies` or `optionalDependencies`.
- `optional`: `true` for an entry in `optionalDependencies` and for a peer dependency marked as optional in `peerDependenciesMeta`.
- `spec`: the version range the package declares, shown as `requires` in the text output.
- `dependents`: the packages that depend on this package, in the same order as the text output. It is `[]` when there are none. It is `null` where the text output stops: past `--depth` (or `--top`), or when the package is already listed further up in the same chain. In the second case the entry also has `"circular": true`.

`--top` and `--depth` apply as in the text output. When no package matches the pattern, the command prints `[]`, reports the error on stderr and exits with code 1.
