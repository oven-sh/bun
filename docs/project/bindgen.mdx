<Note>This document is for maintainers and contributors to Bun, and describes internal implementation details.</Note>

The bindings generator reads every `*.bind.ts` file under `src/` and generates
the glue between JavaScript and Rust: the C++ that checks and converts
arguments with JavaScriptCore's own API, the Rust that receives them already
converted, and the TypeScript types `src/js` sees.

A binding's Rust code never sees a `CallFrame`, never converts a value by hand,
and cannot keep a pointer into JavaScript-owned memory for longer than it is
valid: the borrow checker refuses.

The generator lives in `src/codegen/bindgen*.ts`, the Rust it generates against in
`src/jsc/bindgen.rs`, and the C++ in `src/jsc/bindings/Bindgen/` and
`src/jsc/bindings/BunIDL*.h`.

The body of a binding is always Rust. These do overlapping work:

- "Classes generator", converting `*.classes.ts` for custom classes.
- "JS2Native", allowing ad-hoc calls from `src/js` to native code (`$rust`, `$cpp`).
- `#[bun_jsc::host_fn]` functions, which take a `CallFrame`.

## Functions

Describe the function in a `.bind.ts` file next to the Rust file:

```ts src/jsc/bindgen_test.bind.ts icon="/icons/typescript.svg"
import * as b from "../codegen/bindgen-lib.ts";

export default b.module({ rustPath: "crate::bindgen_test" });

export const add = b.fn({
  args: {
    a: b.i32.wrap,
    b: b.i32.wrap.nullable.default(-1),
  },
  returns: b.i32,
  capability: "heap",
  throws: true,
});
```

and write it:

```rust src/jsc/bindgen_test.rs
use crate::bindgen::{self, JsHeap};

pub fn add<'a>(heap: &JsHeap<'a>, a: i32, b: i32) -> bindgen::Result<'a, i32> {
    a.checked_add(b)
        .ok_or_else(|| heap.error(format_args!("Integer overflow while adding")))
}
```

`b.module` says where the file's functions are; an export named
`requiredAndOptionalArg` is `required_and_optional_arg` there. A `rustPath` key on
a function gives its full path instead. `length` sets the function's `.length`,
which is otherwise the number of arguments up to the last that is not written
`.optional`, `.nullable`, `.falsyAsNull` or `.default()`. The ones after that are
the ones TypeScript lets a caller leave out.

Nothing else is written by hand, except once per crate: `src/<crate>/generated_bindgen.rs`
includes the generated file, and the crate root declares `mod generated_bindgen`. If the
Rust signature does not match the schema, the generated code does not compile.

To reach the function:

- from `src/js`: `$bindgen("bindgen_test.bind.ts", "add")`, which is typed from the schema;
- from a C++ static property table: `Bun::Bindgen::Generated::BindgenTest::jsAdd` in `GeneratedBindgenTest.h`.

### What a function may do: `capability`

What a function can do to the JS heap is a parameter it is given, so it is
visible in the schema, in the signature and to the compiler.

| `capability`       | First parameter    | The function can                                                     |
| ------------------ | ------------------ | -------------------------------------------------------------------- |
| `"none"` (default) | none               | compute                                                              |
| `"heap"`           | `&JsHeap<'a>`      | also allocate JS values and describe an error to throw               |
| `"js"`             | `&mut JsScope<'a>` | also run JavaScript, or anything that can call back into native code |

Ask for the least that works. The less a function can do, the more it is handed
directly: a function that cannot run JavaScript gets `&[u8]` for a typed array
and `&mut self` for its object, because nothing can invalidate either while it
runs.

The compiler holds a body to its capability as far as this API goes. The older API has
other ways to a `&JSGlobalObject` (`VirtualMachine::get().global()`), and a body that
takes one of those to run JavaScript has stepped around the check.

`throws: true` makes the return type a `Result`. The error is a
`bindgen::Error<'a>`, made by `heap.error(..)`, `heap.type_error(..)`,
`heap.range_error(..)` or `bindgen::Error::from_value(value)`, or any type that
implements `bindgen::IntoError` (`bun_sys::Error`, `SystemError`, `JsError` and a `Box` of
one do), which lets a `capability: "none"` function fail too.

`cx.global()` is the `&JSGlobalObject`, for code that takes one. It borrows all of
`cx`. Such a function can return `JsResult<T>`, and a plain `JSValue` under
`returns: b.any`.

### Overloads

`b.overloads(a, b, ..)` is one JS function with several signatures. Each names its
own Rust function, which gets exactly the types of that signature:

```ts
export const read = b.overloads(
  { args: { path: b.string.utf8, options: ReadOptions.optional }, rustPath: "crate::read_path" },
  { args: { fd: b.i32, buffer: b.bufferSource.bytes, offset: b.u32.default(0) }, rustPath: "crate::read_fd" },
);
```

Use it when the type of one argument says what the others are. A union for each
argument would accept combinations that mean nothing, and leave the body to sort them out.

The generated function starts with every signature as a candidate and looks at the
arguments from left to right:

1. It keeps the candidates whose type at that position takes the [kind](#unions-and-kinds)
   of the argument.
2. An argument that was not passed is `undefined`. So `f(x)` and `f(x, undefined)` are the
   same call.
3. A candidate with no argument at that position stays.
4. If no candidate takes the argument, all of them stay, and the next argument decides.
5. When the arguments run out, the candidate written first wins. Its conversion reports
   whatever is wrong. So of two signatures that start the same, the longer one goes first.

Choosing converts nothing and runs no JavaScript. A signature that no call can reach is
an error when the schema is loaded.

## Types

Conversions are strict unless the schema says otherwise: `b.i32` takes a number
or BigInt that is an integer in range, and nothing else. A failed strict or
`.validateInteger` conversion, or a `.loose` one of an integer, throws
`ERR_INVALID_ARG_TYPE` or `ERR_OUT_OF_RANGE` naming the argument or the dictionary
member; `.wrap`, `.enforceRange` and the other `.loose` conversions throw what WebIDL does. An argument that was not passed is `undefined` and is converted like
any other: nothing looks at how many there are.

| Schema                                           | Rust, as an argument             | Takes                                                         |
| ------------------------------------------------ | -------------------------------- | ------------------------------------------------------------- |
| `b.bool`                                         | `bool`                           | a boolean; `.loose` is `ToBoolean`                            |
| `b.u8` `b.u16` `b.u32` `b.u64` `b.usize` `b.i32` | the same                         | a number or BigInt that is an integer in range; see below     |
| `b.f64`                                          | `f64`                            | a number                                                      |
| `b.string`                                       | `bun_core::String`               | a string; `.loose` is `ToString`                              |
| `b.string.utf8`                                  | `&'a [u8]`                       | the same, and a `String` object                               |
| `b.string.utf8.owned`                            | `bun_core::Utf8Bytes<'static>`   | as `b.string.utf8`                                            |
| `b.bufferSource`                                 | `JsLocal<'a, BufferSource>`      | a typed array, `DataView` or `ArrayBuffer` that is not shared |
| `b.bufferSource.bytes`                           | `&'a [u8]`                       | the same; see [Buffers](#buffers)                             |
| `b.bufferSource.arrayBuffer`                     | `ExternalShared<JSCArrayBuffer>` | the same; the bytes of a view are copied                      |
| `b.blob`                                         | `ExternalShared<Blob>`           | a `Blob`                                                      |
| `b.any`                                          | `JsLocal<'a>`                    | anything                                                      |
| `b.null`                                         | `()`                             | `null` or `undefined`; only in a union                        |
| `b.array(T)`                                     | `Vec<T>`                         | an array                                                      |
| `b.enumeration(values)`                          | a generated `enum`               | one of the strings                                            |
| `b.dictionary(members)`                          | a generated `struct`             | an object that is not an array                                |
| `b.union(alternatives)`                          | a generated `enum`               | see [Unions and kinds](#unions-and-kinds)                     |
| `b.class(options)`                               | `JsWrapper<'a, T>`               | an instance                                                   |

One JS type has one name; a modifier picks the Rust form. The last four are named
types: each is called what it is exported as, and has to be exported.

These come last, in this order (`b.any` already takes `undefined` and `null`, so only `.withValue` applies to it):

- `.optional`: `undefined` means absent; `Option<T>`.
- `.nullable`: `null` or `undefined` means absent; `Option<T>`.
- `.falsyAsNull`: every falsy value means absent; `Option<T>`.
- `.default(value)`: what to use when absent; `T`. `.nullable.default(value)` also applies to `null`.
- `.withValue`, for arguments: see [Keeping the original value](#keeping-the-original-value). Not with `.default()`.

As results, `b.string.utf8` is anything that is `AsRef<[u8]>` and `b.array(T)` anything
that is `IntoIterator`.

### Integers

- `.loose`: `ToNumeric` first, then as strict as the default.
- `.wrap`: the WebIDL conversion, `ToNumber` then wrap modulo the width.
- `.enforceRange(min, max)`: WebIDL `[EnforceRange]`.
- `.validateInteger(min, max)`: Node's `validateInteger`, with its exact errors. Use it when implementing Node.js APIs.

### Strings

`b.string.utf8` is the one to reach for. When the JS string is 8-bit and ASCII the
slice points at the string's own bytes; otherwise it is transcoded into a buffer
in the generated function's frame, which holds 128 bytes and is sized for the worst
case up front: beyond 64 Latin-1 characters or 42 UTF-16 code units it allocates.
Nothing needs freeing. An unpaired surrogate becomes U+FFFD. `.loose` comes before
`.utf8`. A `String` object, which `b.string` refuses, is converted with `ToString`, so
its `toString` runs.

`b.string.utf8.owned` is for a body that stores the string: a
`bun_core::Utf8Bytes<'static>`, which shares the JS string's buffer when it is 8-bit
and ASCII and is a transcoded copy otherwise.

`b.string` shares the JS string's storage and can be stored. It belongs to the
JS thread: see "Cross-thread string hazards" in `src/CLAUDE.md` before sending
one anywhere.

### Dictionaries

```ts
export const BracesOptions = b.dictionary({
  tokenize: b.bool.loose.default(false),
  parse: b.bool.loose.default(false),
});
```

Each member is read, then converted, in declaration order, once. A member
whose type does not accept `undefined` is required. A member can be written
`{ type, rustName, altNames }` to rename its field or to accept other spellings.
A dictionary whose members can all be absent implements `Default`.

A member is looked up on the object and its prototype chain, **stopping before
the calling realm's `Object.prototype`**, so a polluted `Object.prototype` cannot
configure a Bun API. For a plain object, where the own properties are therefore
the whole answer, the member is read straight out of the object's property table. The two paths are indistinguishable to JavaScript;
`test/internal/bindgen.test.ts` holds them to that.

Returning a dictionary makes an object with room for its members inline and puts
each one on it. An `.optional` member that is `None` is left out.

The second argument of `b.dictionary` takes:

| Key                | What it does                                                                                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `allowArray`       | an array is read like any other object, not refused                                                                                                                                      |
| `nonObjectAsEmpty` | a value whose `typeof` is not `"object"` gives every member its default, as in Node's `if (typeof options !== "object") options = null`; every member must be optional or have a default |
| `fromJS`           | also generates `Name::from_js(global, value)`, for a `#[host_fn]` body; one that holds JS values is lent to a closure, `Name::from_js(global, value, \|converted\| ..)`                  |

### Enumerations

```ts
export const Formatter = b.enumeration(["highlight-javascript", "highlight-javascript-redacted", "escape-powershell"]);
```

generates `enum Formatter { HighlightJavascript, .. }`. An entry can be a list of
spellings; the first is the one returned to JavaScript. Returning an enumeration
allocates nothing after the first time.

### Unions and kinds

Where there is a choice, between the alternatives of a union or between overloads,
it is made on the _kind_ of the value, with the cheapest test that tells the kinds
in play apart:

| Looking at                         | Kinds                                                                            |
| ---------------------------------- | -------------------------------------------------------------------------------- |
| the bits of the value              | `undefined`, `null`, boolean, number                                             |
| the type byte in the cell's header | string, BigInt, array, `ArrayBuffer`, typed array or `DataView`, `String` object |
| the cell's `ClassInfo`             | an instance of a class                                                           |

A strict type takes the kinds its row under [Types](#types) says. A type that coerces or
reports its own error takes every kind: `.loose`, `.wrap`, `.enforceRange`,
`.validateInteger`, `b.any`, a dictionary.

**A value goes to the first alternative, in written order, that takes its kind.** That
alternative then converts it, and reports what is wrong with it: `1.5` given to
`b.union({ integer: b.i32, text: b.string })` "must be an integer", not "must be of type integer or string".
The buffer types and `b.blob` refuse some values of their kinds (a shared buffer, a
detached `Blob`); those go on to the next alternative that takes the kind and does not
refuse the same. A value no alternative takes throws `ERR_INVALID_ARG_TYPE` listing them all.

So the order only matters between alternatives that overlap, and one that takes every
kind goes last. An alternative that can never be chosen is an error when the schema is
loaded. Choosing tests whether the value is a cell once, loads the type byte once and
repeats no test. Strings as UTF-8, dictionaries and unions are then converted in the
place they end up in.

### Buffers

JavaScript can detach, resize or transfer a buffer, so `b.bufferSource.bytes` is only
for an argument (not a member or an alternative) of a function that cannot run
JavaScript. The generated code reads pointer and length after every other argument
is converted, since a conversion can run JavaScript too. A function that can run
JavaScript takes `b.bufferSource` itself and looks the bytes up when it needs them:

```rust
let before = buffer.with_bytes(&cx.heap, sum);
callback.call(cx, JsLocal::UNDEFINED, &[])?;
let after = buffer.with_bytes(&cx.heap, sum);
```

Calling `callback.call(cx, ..)` inside the closure does not compile. A detached or
out-of-bounds view is empty.

### Keeping the original value

A converted argument is for use now. To hand the value to something that holds
it longer (one of a class's `internalFields`, a `Strong`, another JS call, the result), ask
for both:

```ts
args: { name: b.string.utf8.withValue },
```

```rust
fn set_name<'a>(&mut self, this: JsWrapper<'a, Self>, heap: &JsHeap<'a>, name: WithValue<'a, &'a [u8]>) {
    this.set_name_field(heap, name.value); // the JS string itself, not a copy
    self.name_length = name.converted.len();
}
```

## Values and lifetimes

A JS value in Rust is a `JsLocal<'a>`: a `JSValue` tied to the host call it belongs
to. It is `Copy`, one register, and not rooted, because JavaScriptCore scans the
stack. The lifetime is what stops it from being stored in a struct, captured by a
task or sent to a thread. `JsLocal<'a, T>` is one known to be a `JSString`,
`JSObject`, `Callable` or `BufferSource`. `value.to_js()` gives the `JSValue`;
`JsLocal::new(heap, value)` goes the other way.

What outlives a call:

- one of a class's **`internalFields`** (below), which the GC visits;
- a `Strong`, made with `value.to_strong(heap)` and read with `JsLocal::new(heap, strong.get())`. It is made, read and dropped on the JS thread.

A list of values goes in a `MarkedArgumentBuffer`, never a `Vec` or a `Box`: the GC does
not look inside heap allocations. The compiler does not check this one.

## Classes

The keys are mostly those of `.classes.ts`, with types. `klass` is `static` and `values` is `internalFields`.

```ts
export const Glob = b.class({
  rustPath: "crate::api::glob::Glob",
  construct: {
    args: { pattern: b.string.utf8.owned },
  },
  proto: {
    match: {
      args: { str: b.string.utf8 },
      returns: b.bool,
    },
  },
});
```

generates a trait, which the struct implements:

```rust
pub(crate) struct Glob {
    pattern: bun_core::Utf8Bytes<'static>,
}

impl GlobClass for Glob {
    fn constructor(pattern: bun_core::Utf8Bytes<'static>) -> Self {
        Glob { pattern }
    }

    fn r#match<'a>(&self, str: &'a [u8]) -> bool {
        bun_glob::r#match(self.pattern.slice(), str).matches()
    }
}
```

The struct, the _payload_, is stored **inside** the JS object, the _wrapper_, so the
two have one lifetime and one allocation. It is dropped when the object is
collected. `Drop` gets no capability, so it cannot touch the JS heap, and no Rust
runs on the collector's threads. The collector is not told of memory the payload owns
outside the object: there is no `estimatedSize` yet.

| Key              | What it declares                                                                               |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| `rustPath`       | the struct                                                                                     |
| `construct`      | `new Name(..)`. Without it JavaScript cannot make one; Rust can, with `payload.into_js(heap)`. |
| `proto`          | properties of the prototype                                                                    |
| `static`         | functions on the constructor                                                                   |
| `internalFields` | JS values the object holds                                                                     |
| `configurable`   | `false` makes the native properties of the prototype non-configurable                          |

A property of `proto` is one of:

| Property                                    | What it is                                                                   |
| ------------------------------------------- | ---------------------------------------------------------------------------- |
| `{ args, returns, capability, throws, .. }` | a native function; `privateSymbol` keys it by a private name of `src/js`     |
| `{ getter: T, capability, throws }`         | an accessor; with `setter: true` it can be assigned                          |
| `{ getter: T, cache: true, .. }`            | an accessor whose value is computed once per object; it cannot have a setter |
| `{ builtin: true, length }`                 | the export of that name in `src/js/builtins/<class name>.ts`                 |

If any member has `throws: true`, the trait has a
`type Error<'a>: bindgen::IntoError<'a>` that they all fail with. `b.self` is the
class itself as an argument, a result or a getter of its own members. `Glob::get_constructor(heap)` is the
constructor function.

### The receiver

| The method is                    | It receives                 |
| -------------------------------- | --------------------------- |
| `capability: "none"` or `"heap"` | `&self`                     |
| …with `mutates: true`            | `&mut self`                 |
| `capability: "js"`               | `this: JsWrapper<'a, Self>` |

A method that can run JavaScript can be re-entered, by a callback that calls
another method of the same object. A `&mut self` held across that would be
undefined behaviour, so it gets the wrapper instead and borrows the payload for as
long as nothing else can run:

```rust
fn notify<'a>(this: JsWrapper<'a, Self>, cx: &mut JsScope<'a>) -> bindgen::Result<'a, i32> {
    if let Some(listener) = this.listener_field(&cx.heap).as_callable() {
        listener.call(cx, this.as_value(), &[])?;
    }
    Ok(this.with(&cx.payloads, |counter| counter.count))
}
```

`this.with(&cx.payloads, ..)` and `this.with_mut(&mut cx.payloads, ..)` borrow one
field of `cx`; running JavaScript needs all of it. `cx.heap` is another field, so
allocating or viewing a buffer inside the closure is fine.

### `internalFields`

`internalFields: ["listener"]` generates `this.listener_field(heap)` and
`this.set_listener_field(heap, value)` on `JsWrapper<'a, T>`. A `&self` or
`&mut self` method that needs them asks for the wrapper too, with `passThis: true`.
The wrapper reaches the internal fields and not the payload.

### Staying alive

To keep an object alive while native work is pending, hold a
`JsWrapperStrong<T>` (`this.to_strong(heap)`) with the work and drop it on the JS
thread when the work completes.

## Tests

- `test/internal/bindgen.test.ts`: conversions with hostile inputs, through `src/jsc/bindgen_test.bind.ts`. A schema named `*_test.bind.ts` is only part of a build with assertions (a debug build, CI's ASAN lane), so nothing it binds ships; `$bindgen` of one is `undefined` elsewhere, and its Rust module is `#[cfg(debug_assertions)]`. What that schema does not use is covered by the suites of the APIs that do.
