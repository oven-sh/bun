<Warning>This is experimental. It has been run with a real app on macOS and Linux only.</Warning>

`bun:desktop/electron` implements the API of Electron on [`bun:desktop`](/runtime/desktop). Once it is loaded, `electron`, `electron/main`, `electron/common`, `electron/renderer`, `electron/utility` and `original-fs` resolve to it.

```sh terminal icon="terminal"
bun --preload=bun:desktop/electron .
```

The types are those of the `electron` package, which can stay in `devDependencies`.

## Packaging

The main script, [pages](/compiler/executables#pages) and preload scripts go in the executable.

```json package.json icon="file-json"
{
  "productName": "Notes",
  "desktop": { "pages": ["dist/renderer/*.html"], "preloads": ["dist/preload.js"] }
}
```

```sh terminal icon="terminal"
bun compile --desktop ./dist/main.js
```

To ship them as files, copy them to a directory named `app` in the resources, which `app.getAppPath()` returns: `"resources": [{ "from": "dist/renderer", "to": "app" }]`.

In an app that is built with `--desktop`, these modules are built in from the start, whether or not the `electron` package is installed. `bun build --compile --desktop` does the same without compiling ahead of time, and so does `bun run --aot` for a program that imports `bun:desktop`.

## One process

There is no renderer process. Each page has a global object of its own in the JavaScript engine that runs the main script, on the same thread. So does each preload script, with `contextIsolation`.

- A page sees the globals of a browser. It has no `process`, `require` or `Bun`.
- `ipcRenderer`, `ipcMain` and `contextBridge` copy values by the rules of Electron. A message is a task on the event loop.
- Work that blocks the main script blocks painting and input, and the other way around. Move it to a `Worker` or a `utilityProcess`.
- An uncaught error in a page goes to `window.onerror` and the `console-message` event, not to `process.on("uncaughtException")`.
- A page cannot crash or hang on its own. `render-process-gone` and `unresponsive` are not emitted for it.
- Web workers and service workers are threads. `utilityProcess.fork()` starts a process.

## Security

<Warning>
  The global object of a page is not a security boundary. `sandbox: true` and `contextIsolation: true` keep code from
  meeting by accident. They do not stop code that is out to reach the rest of the process.
</Warning>

For that reason only these run in the process, in a window or a view:

- `file:` URLs inside of `app.getAppPath()`
- origins that the app has passed to `app.trustOrigins()`
- `about:blank`
- `blob:` URLs of a trusted page, unless they are HTML or XML

```ts main.ts icon="/icons/typescript.svg"
import electron from "bun:desktop/electron";

electron.app.trustOrigins(["app://bundle"]);
```

Trust an origin only if you would `require()` each script that it can load. Prefer origins that the app serves itself with `protocol.handle()`, and send a strict `Content-Security-Policy`.

Everything else, and every `<iframe>` that has a `src` or a `srcdoc`, is rendered by a browser in sandboxed processes of its own. See `app.setWebEngine()`. The site gets the cookies and the `Sec-Fetch-*` headers for the page that has navigated to it, as in a browser. If there is none, the load fails with `ERR_BLOCKED_BY_CLIENT`.

## Debugging

`ELECTRON_ENABLE_LOGGING=1` prints the console of pages.

`--remote-debugging-port=9222` serves enough of the DevTools protocol for `chromium.connectOverCDP()` of Playwright to evaluate scripts, click, type and take screenshots. `webContents.debugger` has the same commands. There is no DevTools window.

`BUN_DESKTOP_HEADLESS=1` runs without a display server.

## What is missing

See also [what the DOM lacks](/runtime/desktop#what-is-missing).

These throw or reject:

| Module            | What                                          |
| ----------------- | --------------------------------------------- |
| `app`             | `enableSandbox`                               |
| `webContents`     | `startDrag`, except on macOS                  |
| `dialog`          | `showCertificateTrustDialog`, except on macOS |
| `desktopCapturer` | All of it with Chromium as the web engine     |

`contentTracing` records the process of the app: the performance timelines of pages and workers, and samples of the stack of the main thread. See `getCategories()`. `netLog` has the requests of that process, with their status and response headers.

`crashReporter` writes minidumps on macOS and Linux, for the main process and for utility processes, into the directories that Crashpad uses. Nothing is written until the app calls `start()`. A dump has the registers and up to 512 KB of the stack of the thread that crashed, the paths of the executable and of the loaded libraries (which can have the name of the user), the message of the crash and the parameters. It has neither the heap nor other threads. Trusted pages run in the main process, so unlike in Electron its stack can have pieces of what a page was working on, such as text, URLs and form values. Treat reports as personal data. A report waits in `queued` and is uploaded when the app is launched again. There is one attempt: a report that the server has refused, or that is over the rate limit, stays in `completed`. What other programs have put into `pending` is left alone. `ignoreSystemCrashHandler` and the parameters of preload scripts are ignored. A compiled app never reports its crashes to Bun.

These do nothing: network emulation, the settings of the host resolver, and the `webPreferences` `offscreen` and `nodeIntegrationInWorker` for a trusted page.

`print()` and `printToPDF()` give a copy of a trusted page to the web engine, which lays it out. Videos, and frames that the engine renders, are empty in it.

`autoUpdater` works on macOS, and reads the feeds of Squirrel.Mac. An update has to have the bundle identifier of the app, and to satisfy its designated requirement, which is checked after the download and again before the installation. An app with an ad hoc signature cannot be updated. Unlike in Electron, the whole archive is downloaded even if the feed has a delta, nothing is installed after the app was killed or while another instance of it runs, and only `quitAndInstall()` asks for the password of an administrator. It only asks if the user can change neither the bundle nor its executable, because that is what runs as root. As with Squirrel.Mac, whoever can rename what is in the folder of the app can put another executable in its place while the prompt is shown. The app installs the update itself while it exits, so it exits later, and writes the outcome to `~/Library/Caches/<bundle identifier>.ShipIt/ShipIt_stderr.log`.

`.asar` archives are not read at run time. Unpack them with `asar extract`, and compile or ship the directory. Native addons have to use Node-API.

Trusted pages share the thread with the app. A script that does not return blocks the app, and there are no `unresponsive` and `responsive` events for it.
