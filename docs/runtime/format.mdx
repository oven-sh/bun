Bun ships with a fast, built-in code formatter. There's nothing to install and nothing to configure.

- JavaScript, TypeScript, JSX, CSS, SCSS, Less, HTML, Vue, Angular, JSON, YAML, Markdown, MDX, GraphQL, and Handlebars
- The same output as [Prettier](https://prettier.io)
- Sorts imports and Tailwind CSS classes
- Works with your existing Prettier or oxfmt config
- Format on save in your editor

## Run the formatter

```bash terminal icon="terminal"
bun format
```

```txt
src/index.ts
src/server.ts
Formatted 2 files, 2 unchanged [8.16ms]
```

`bun format` rewrites the files in the current directory that need it and prints their names. It skips `node_modules` and anything in your `.gitignore`.

To format specific files, pass paths or globs.

```bash terminal icon="terminal"
bun format src "test/**/*.ts"
```

Embedded code is formatted too: `<script>` and `<style>` in HTML and Vue, code blocks in Markdown, and `` css`...` ``, `` html`...` ``, and `` graphql`...` `` templates in JavaScript.

## Check without writing

`--check` lists the files that need formatting and writes nothing.

```bash terminal icon="terminal"
bun format --check
```

The exit code is `1` if a file needs formatting and `0` if none do.

## Options

Options live in `bunfig.toml`. The names and defaults are [Prettier's](https://prettier.io/docs/options).

```toml bunfig.toml icon="settings"
[format]
printWidth = 100
semi = false
singleQuote = true
```

To create the section, run `bun format --init`.

| Option           | Default    | What it does                            |
| ---------------- | ---------- | --------------------------------------- |
| `printWidth`     | `80`       | Wrap lines at this column               |
| `tabWidth`       | `2`        | Spaces per indentation level            |
| `useTabs`        | `false`    | Indent with tabs                        |
| `semi`           | `true`     | Print semicolons                        |
| `singleQuote`    | `false`    | Use single quotes                       |
| `trailingComma`  | `"all"`    | `"all"`, `"es5"`, or `"none"`           |
| `bracketSpacing` | `true`     | `{ a }` or `{a}`                        |
| `arrowParens`    | `"always"` | `(x) => x` or, with `"avoid"`, `x => x` |
| `endOfLine`      | `"lf"`     | `"lf"`, `"crlf"`, `"cr"`, or `"auto"`   |

See [`bunfig.toml`](/runtime/bunfig#formatter) for all of them. Each one is also a flag, like `--print-width 100` or `--no-semi`.

### Different options for some files

```toml bunfig.toml icon="settings"
[[format.overrides]]
files = ["*.test.ts", "scripts/**"]
options = { printWidth = 120 }
```

### `.editorconfig`

`bun format` reads `indent_style`, `indent_size`, `tab_width`, `max_line_length`, and `end_of_line` from `.editorconfig`. `bunfig.toml` overrides them.

## Ignore files

`bun format` also skips what `.prettierignore` lists.

```toml bunfig.toml icon="settings"
[format]
ignorePatterns = ["vendor/", "**/*.gen.ts"]
```

## Ignore code

`bun format` uses Prettier's comment, so existing ones keep working. It applies to the next statement, element, or rule.

```ts
// prettier-ignore
const matrix = [
  1, 0, 0,
  0, 1, 0,
  0, 0, 1,
];
```

| Language       | Comment                    |
| -------------- | -------------------------- |
| JSX            | `{/* prettier-ignore */}`  |
| CSS            | `/* prettier-ignore */`    |
| HTML, Markdown | `<!-- prettier-ignore -->` |
| YAML, GraphQL  | `# prettier-ignore`        |

## Sort imports

```toml bunfig.toml icon="settings"
[format]
sortImports = true
```

Imports are grouped (built-in modules, packages, aliases like `@/`, relative paths, styles), with a blank line between groups, and sorted by path within each group.

```ts
import { readFile } from "node:fs/promises";

import { z } from "zod";

import { db } from "@/db";

import { b, a } from "./util";
```

Side-effect imports like `import "./setup"` don't move. To pick your own groups, use a table. See [`format.sortImports`](/runtime/bunfig#format-sortimports) for every option.

```toml bunfig.toml icon="settings"
[format.sortImports]
groups = ["builtin", "external", "internal", ["parent", "sibling", "index"]]
internalPattern = ["@/", "~/"]
newlinesBetween = false
```

## Sort Tailwind CSS classes

```toml bunfig.toml icon="settings"
[format]
sortTailwindcss = true
```

Classes in `class` and `className` are sorted in Tailwind's recommended order. The order comes from the `tailwindcss` package in your project, so version 3 or 4 has to be installed.

```tsx
<a className="p-4 flex m-2" /> // [!code --]
<a className="m-2 flex p-4" /> // [!code ++]
```

To sort the arguments of functions like `clsx` too, or to name your stylesheet, use a table. See [`format.sortTailwindcss`](/runtime/bunfig#format-sorttailwindcss) for every option.

```toml bunfig.toml icon="settings"
[format.sortTailwindcss]
stylesheet = "./src/app.css"
functions = ["clsx", "cn"]
```

## Editors

Install the [Bun extension for VS Code](https://marketplace.visualstudio.com/items?itemName=oven.bun-vscode) and make it your formatter.

```json .vscode/settings.json icon="file-json"
{
  "editor.defaultFormatter": "oven.bun-vscode",
  "editor.formatOnSave": true
}
```

For any other editor, point its LSP client at `bun lint --lsp`. The same server lints and formats.

```bash terminal icon="terminal"
bun lint --lsp
```

No LSP client? Pipe the buffer through `bun format`. The path picks the language and the options. The file doesn't have to exist.

```bash terminal icon="terminal"
bun format --stdin-filepath src/index.ts < src/index.ts
```

## Git hooks

`--staged` formats only the files you're about to commit and stages them again, so you don't need `lint-staged`.

```sh .git/hooks/pre-commit icon="terminal"
#!/bin/sh
bun format --staged
```

`--changed` formats the files that differ from your default branch. Pass a ref to compare with something else.

```bash terminal icon="terminal"
bun format --changed
bun format --changed=origin/dev
```

## CI

```yaml .github/workflows/format.yml icon="file-code"
steps:
  - uses: actions/checkout@v4
  - uses: oven-sh/setup-bun@v2
  - run: bun format --check
```

The exit code is `2` if something went wrong, like a syntax error. Bun reports that file and still checks the rest.

## Migrate from Prettier or oxfmt

Already have a `.prettierrc` or an `.oxfmtrc.json`? `bun format` reads it and prints what that tool prints. Change the script and you're done.

```json package.json icon="file-json"
{
  "scripts": {
    "format": "prettier --write .", // [!code --]
    "format": "bun format" // [!code ++]
  }
}
```

If `package.json` has a `format` script, `bun format` runs that script. Inside the script, `bun format` is the formatter.

Svelte and Astro aren't built in. Bun sends those files to your installed Prettier and its plugin. To see which files those are, and which packages you can uninstall:

```bash terminal icon="terminal"
bun format --doctor
```

See the guides: [Migrate from Prettier](/guides/format/migrate-from-prettier) and [Migrate from oxfmt](/guides/format/migrate-from-oxfmt).
