Fixed in a766fa4d233. A file of the project is now known by its path, not by the address of its parsed value: `BundleOptions::lay_tsconfig` compares the paths from `TSConfigJSON::jsx_by_file`. The path is the real path of the directory plus the file name (`TSConfigJSON::name_files_under`), so a tsconfig.json that is read again after `bust_dir_cache`, or that is reached through a symbolic link to its directory, is still the project's. Tests: the unit test in `src/bundler/options.rs` reads the file a second time, and `jsx-tsconfig-react-jsx.test.ts` builds through a link to the project directory.

Two of the three triggers do not reach this code. The runtime (`bun --hot`) transpiles with `options.jsx`, which is resolved once at startup and does not call `jsx_for`. The dev server builds its transpilers from `TransformOptions::default()`, so they have no option that a user states. A `Bun.build` that overlaps a directory-cache bust does reach it.
