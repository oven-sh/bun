model.cjs              The four rules as they can be written on Bun's tree, on the tree of bunshape.cjs driven by driver.cjs:
                       no parent pointer (the class, the object literal and the call say from above which function is a getter
                       or a constructor, which object is a property descriptor), getter-return and no-fallthrough read the
                       current segments while the walk runs, the two constructor rules keep the steps of a constructor of a
                       class with `extends` and run ESLint's handlers over them when its code path ends. Compared with
                       ESLint's four rules: rule, line:column, message.
                       node model.cjs [--upstream] [--list cases.json]... [--files list.txt] [--live] [--update-enter-only] [--show]
                       --live: also runs the two constructor rules without the replay and counts where that differs.
                       --update-enter-only: only the segments that start when the update of a `for` is entered get the flag.
fuzz.cjs               node fuzz.cjs <count> <seed> <out.json> [ctor|getter|switch|all]   random constructors of classes with
                       `extends` (71 forms of superclass), getters and descriptors, `switch` with comments and blank lines.
tokens-check.cjs       The forward reads of tokens that give a place where the tree has none, on ESLint's tokens against its
                       nodes: where a property of an object literal starts, where a clause of a `switch` starts (one rule for
                       `case` and `default`), the `:` of a clause.  node tokens-check.cjs [--cases corpus.json] [--files list.txt]
comment-matcher.cjs    `isFallThroughComment` without a regular expression, on UTF-8 bytes, against ESLint's two patterns on
                       random texts; writes answers/fallthrough-comment-table.json (120 texts with ESLint's answer, for a test).
