What to know before a sweep is started again
  - sweep.ts needs a file of lists: without expectations.json beside it, give --expectations.
  - --jobs defaults to the number of processors (16 here): give --jobs 4.
  - A selector with "*" makes sweep.ts read every case first: about 30 s on this machine under load, per chunk.
  - The report keeps outcome and reason and not what the command wrote: the reason names the first code alone.
    Everything else (all lines, the category, a panic text) is in raw.jsonl.
  - merge.ts reads the outcomes and reasons of the default check of 3110ce85cf. When that check changes (the patch of
    round2/default-check-classification gives a rule report and a syntax error other outcomes), its function classify
    has to follow, or the lists `crashes` and `timeouts` of the new report are read instead.
  - materialise.ts ancestorProjectFile: a node_modules, package.json, tsconfig.json or jsconfig.json in /tmp or in /
    makes every instance "unsupported". The driver says so before a chunk.
  - A panic of the debug build writes its banner and message to stderr and its frames to STDOUT, then SIGABRT
    (seen with crash_handler.panic() of bun:internal-for-testing). An error of AddressSanitizer ends a process with
    the exit code 1 by the default of the sanitizer (no abort_on_error in the environment of the sweep; not provoked
    here): the default check then says "the command refused: ...", which merge.ts counts under "else", not under
    "diagnostic". raw.ts says "exit code 1" and keeps the text.
  - The debug binary has to be the build of the commit whose src/ is swept: `<binary> --revision`.
  - Today the command parses a TypeScript file with Parser::parse and a JavaScript file with Parser::parse_only
    (src/runtime/cli/lint_command.rs:238): the parse of the transpiler. Parser::parse_for_lint and its table of
    TypeScript codes (src/js_parser/parse/syntax_errors.rs) have no caller outside tests. A sweep without a crash
    says nothing about that code: sweep again when the command calls it.
