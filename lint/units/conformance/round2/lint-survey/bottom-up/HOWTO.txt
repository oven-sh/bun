What to know before a sweep is started again
  - sweep.ts needs a file of lists: without expectations.json beside it, give --expectations.
  - --jobs defaults to the number of processors (16 here): give --jobs 4.
  - A selector with "*" makes sweep.ts read every case first: about 30 s on this machine under load, per chunk.
  - The report keeps outcome and reason and not what the command wrote: the reason names the first code alone.
    Everything else (all lines, the category, a panic text) is in raw.jsonl.
  - materialise.ts ancestorProjectFile: a node_modules, package.json, tsconfig.json or jsconfig.json in /tmp or in /
    makes every instance "unsupported". The driver says so before a chunk.
  - A panic of the debug build writes its banner and message to stderr and its frames to STDOUT, then SIGABRT.
    An error of AddressSanitizer ends the command with the exit code 1 (no abort_on_error in the environment of the
    sweep): the default check then says "the command refused: =====...", which merge.ts counts under "else", not
    under "diagnostic". raw.ts says "exit code 1" and keeps the text.
  - The debug binary has to be the build of the commit whose src/ is swept: `<binary> --revision`.
