This is the defect of #23264, and #43515 is the open PR for it. The package.json parse registers a `Version` whose strings are offsets into the temporary lockfile, and the map keeps it. #43515 makes the map own the specifier text, which covers every writer. This PR does not change that path: on main the package.json parse replaces the entry of the loader in the same way.

I ran the trigger from this comment on release builds of main (a4f1429148) and of this branch. The root has `"kept": "npm:some-other-package@1.0.0"`, `parent` has a plain `kept@^1.0.0`, the lockfile is kept (bun.lock and bun.lockb), and package.json does not change. `bun install`, `bun update`, `bun update parent`, `bun update some-other-package`, `bun update kept` and `bun add new-dependency` all exit 0 on both builds and request `/some-other-package`. The offsets are equal there, because both string buffers start with the strings of the root package. The case that fails on main is the one of #23264: the alias is in a workspace that comes after the package.json that changed.
