### Problem
- `BUN_CONFIG_REGISTRY=HTTP://host/` (or a typo, `htp://host/`) is ignored without a message. `bun install` and `bun publish` then use the next registry, `registry.npmjs.org` by default.
- A registry that is not an http(s) URL (`htps://host/`, `host:4873/`, `http://host:demo/`) makes `publish`, `audit`, `pm whoami`, `pm view`, `pm diff` and lockfile installs send the token over plain HTTP. Only the manifest request answered `Registry URL must be http:// or https://`.
- Causes: a lowercase prefix gate in `Options::load` (`PackageManagerOptions.rs:632`), and a `Scope` that stores any text while the HTTP client dials all schemes but https as plain HTTP.

### Fix
- `Scope::set_url` records whether the value is a WHATWG http(s) URL. URL and credentials are private. Requests get them only from `Scope::checked()`.
- All sources take that path: the environment value is not filtered, `--registry` uses the same parse, and `Scope::from_api` no longer invents `http://`.
- `AsyncHTTP::send_sync` refuses a non-http(s) URL (a `dist.tarball` in `pm diff`).
- Verified: 85 new tests in six `test/cli/install/` files. SELF_REVIEW_LINE

### Background
- A `Scope` is one registry (default or `@scope`): URL, token, basic auth. Each source builds one.
- The check runs at the first request. Validation at load was considered: it changes the exit code of commands that send nothing (`pm bin`, `publish --dry-run`) or have an unused bad `@scope` registry.
- Takes the request-site checks and tests of #41882 and #41662 into one place.

### Downsides
- A scheme-less value with credentials (`host:4873/:_authToken=T`) became `http://host:4873/`. It is now refused.
- `--registry=http://host:demo/` (not a URL) now fails at startup.
- `Scope` grows from 88 to 96 bytes. Release binary size: not measured (Notes).

**Cost for a valid registry**, counted from the diff:
- `size_of::<Scope>()`: 88 to 96 bytes (one `bool`, checked with a const assert).
- `Options::load`: one more lenient `URL::parse` per registry scope (no allocation). With `BUN_CONFIG_REGISTRY` / `NPM_CONFIG_REGISTRY` set and no credentials in it: one more WHATWG parse and one allocation. With `--registry`: two more WHATWG parses.
- Per manifest or tarball task: one boolean load and branch. `Options::scope_for_package_name`, `HTTPClient::start` and `HTTPThread::dial` are not touched.
- Per synchronous CLI request (`send_sync`): two case-insensitive compares of the scheme, no allocation.
- Not measured: instruction counts under gdb and the release binary size. A release build did not finish on the build host.

**What is refused, and what is printed.** A refused value is stored without userinfo, `:_authToken=` style path credentials, query and fragment, so no message or lockfile can carry them. `bun install` keeps its two messages (`Failed to join registry ...` and `Registry URL must be http:// or https://` with the joined URL). Every other command prints `Registry URL must be http:// or https://` and `Received: "<value>"`. `bun audit` with a bad `@scope` registry skips it with a warning, like a registry that does not answer. A bad default registry is an error.

**Inputs that stop working.** (1) A value with no `scheme://` that bun used to complete to `http://`: this only happened when the value carried path credentials or userinfo. `http:host/` and `https:host/` are http(s) URLs to the WHATWG parser and still work. (2) `--registry` with a value that starts with `http://` or `https://` and is not a URL.

**Question for a maintainer.** Values from the environment, bunfig.toml and `.npmrc` are refused at the first request that would use them, which is when npm refuses an unsupported scheme. Only `--registry` fails at startup, as before. The API rule in `.claude/docs/landing-prs.md` says to reject a value at parse time. I kept first use because validation at load changes the exit code of 153 cells that send nothing, and of the optional-only install that `test/cli/install/bun-install.test.ts` pins at exit 0.

**Other open PRs on these lines.** #38997 redacts the registry URL in the `for_manifest` and `for_tarball` messages. This PR leaves those message lines with only the accessor swap, so that redaction stays there. After this lands, a PR that reads `scope.url`, `scope.token` or `scope.auth` needs `href_unchecked()` (messages, cache keys, lockfile comparisons) or `checked()` (requests). #41636 and #44294 touch neighbouring lines in `PackageManagerDirectories.rs` and `bun.lock.rs`.
