# The app workloads' features, in the order they are traced (scripts/orderfile/generate.ts).
# The order is part of the result: a function lands in the order file where the first
# feature to enter it is, so the features whose code a long-running TUI/CLI application
# is most likely to use come first and the ones that drag in code it rarely needs come last.
# It was chosen by scoring candidate orders against a function-entry trace of such an
# application; when adding a feature, put it next to the features it most resembles.
# A `!` marks one feature of each family (terminal UI, fetch with and without TLS, a TLS
# socket, a child process, JIT-hot code): the generator fails if one of those cannot be
# traced, where any other feature failing only costs the order file that feature.
