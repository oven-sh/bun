## Libraries that are known not to work

`libraries-known-not-to-work.test.ts` reads this table. For each row it has a small program that does what the package does. The program runs under plain Bun, and its executable has to print the messages of the row, letter for letter. `docs/compiler/libraries.mdx` names the same packages.

To add a row, add a program under the same name in the test, and name the package on that page. The last code span of the second column is the line of the package that does it. The last column links to a heading of `docs/compiler/compatibility.mdx` or `docs/compiler/libraries.mdx`. The versions are the ones that were tried.

Where a row cuts a `TypeError` short with `...`, it ends like this one:

```txt
TypeError: Cannot assign to Promise.prototype.then because built-in objects are read-only in a compiled executable (bun compile differs from bun run here: https://bun.com/docs/compiler/compatibility)
```
