# What the C fixtures cover

One row per item of the C surface; each row names the fixture(s) under `fixtures/` that exercise it (`area/name`
is `fixtures/area/name.c`, or the directory `fixtures/area/name/` for a project), or says what is missing.
Every fixture is a self-checking program run two ways (`bun name.c`, and bundled: `bun build --target=bun` then the
bundle, with `bun build --compile` and its executable for the first fixture of each area) against one `.expected`, which
is what GCC and Clang print, at `-O0` and at `-O2`, agreeing with each other (section 10 lists the few that are not, and
why); the tests taken from other
compilers, and our own table-driven ones, also print every value they check, and the test compares them one by one
with `<name>.values.json` (one `toEqual` over the whole list, so a failure names the expressions that differ).

Status: **covered** (a fixture exists and passes), **not yet** (planned, no fixture), **not supported** (the
compiler refuses it on purpose; the diagnostic is asserted by a case in `fixtures/diagnostics/cases.json`).

## 11. Considered and not done

- A loop that counts through a few constants over a small local array (a ChaCha or MD5 round) keeps its array in memory:
  the pass that unrolled such loops in the front end so that the array could live in registers is gone (it was wrong when
  the loop was left by `goto`, and it copied every function body to try). Doing it belongs to the backend, after B3's own
  unrolling; it is worth about 2x on such kernels and nothing on SQLite.
- On Apple arm64 a structure that holds a 16-byte vector, read with `va_arg` after a 4-byte argument, after an 8-byte one
  when it holds two vectors, or after the registers are used up, is not pinned: Apple's own compiler reads those right at
  -O0 and reads garbage or crashes once it optimizes, so there is nothing to agree with. This compiler puts them at the
  next multiple of 16 bytes, as the ABI document says. (varargs/a-structure-that-holds-a-vector-through-an-ellipsis has the
  three calls that Apple's compiler reads the same at every level.)
- Conversions between `long double` and `__int128` at run time; `_Atomic` structures; the rest of section 7.

## 12. Open

Known and not done, each in a line.

- The path of a source file has to be UTF-8.
- Loops over a few constants and a small local array (a ChaCha round) are not unrolled: twice as slow there as they were
  with the pass that is gone (section 11); it would be scalar replacement in the backend.
- Three places in JavaScriptCore take seconds on huge generated expressions, all quadratic steps in passes it shares with
  JavaScript, after the C compiler has finished and with no local fix: a sum of 10,000 `__int128` terms (B3 rebalances a long
  chain of additions into a tree that keeps all its leaves alive to the root, so there are as many spills as terms, and Air
  sorts the spill slots again for each), a `?:` chain of 20,000 links (B3's inference of switches copies every case gathered
  so far at each link it merges), and an `&&` chain of 80,000 terms (27 s).
- On macOS a C program cannot write code into a `MAP_JIT` page: `pthread_jit_write_protect_np` switches every such
  page of the thread between writable and executable at once, and the code compiled from the program is in one. (A
  page that is written and then made executable with `mprotect` works.)
- `abort()` on Windows ends the process with the system's fast-fail status and no report, as it does for a native program.
- On Windows a library named by `#pragma comment(lib, ...)` is looked for the way `LoadLibrary` looks, the current
  directory included; nothing narrows the search. (Without the pragma a program has `ucrtbase`, `vcruntime140` and
  `kernel32`; `user32`, `advapi32`, `ws2_32` and the rest are asked for by name.)
- `fflush(NULL)` when a C program's `main` returns can wait for ever on a stream another thread holds locked.
- A bundle loses an export named `__proto__`, C's like anyone's (an existing bug of the bundler's).
- JavaScriptCore's own tests for all of this (`JSTests/stress/bir-*.js`, `testb3`) run where somebody runs them: the
  fork's CI does not check `JSTests` out.
