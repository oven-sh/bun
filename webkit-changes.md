#### Performance

- WebKit/WebKit@aeca1a989ffc (webkit.org/b/329474): `JSON.stringify` is faster when the value holds many objects with the same Structure, for example an array of rows with the same keys (from the commit message, which gives no numbers). During one call, the runtime fast path (`FastStringifier` in `Source/JavaScriptCore/runtime/JSONObject.cpp`) keeps a small cache keyed by StructureID. For a later object of a cached Structure, it copies the key text and reads the values directly from their storage slots. The VM also keeps the lengths of the last two results from the dynamic buffer, and uses them to size the next one. Tests: `JSTests/stress/json-stringify-prepared-structure.js` and `JSTests/stress/json-stringify-prepared-structure-large.js`.
- WebKit/WebKit@c8e6298f1ac9 (webkit.org/b/329716): `JSON.parse` without a reviver (runtime, `LiteralParser::parseRecursively`) now parses the objects in an array such as `[{...}, {...}]` in the stack frame of the array. Before, it made one recursive call for each object element. The commit message gives no numbers, and the commit adds no test.
- WebKit/WebKit@d24e80edb596 (webkit.org/b/329545): `JSON.parse` (runtime, `LiteralParser`) now scans a number with a fraction, an exponent or more than nine digits only once. Before, `Lexer::lexNumber` scanned the integer part, and `WTF::parseJSONDouble` then scanned the number again from the start. The new `WTF::parseJSONDoubleFromDigits` converts the digits, and a number with more than 19 significant digits still goes to `WTF::parseJSONDouble`, so results and error messages do not change (from the commit message, which gives no numbers). Tests: `JSTests/stress/json-parse-doubles.js`, `JSTests/stress/json-parse-doubles-near-halfway.js`, `JSTests/stress/json-parse-cached-number-values.js` and `Tools/TestWebKitAPI/Tests/WTF/FastFloat.cpp`.
- WebKit/WebKit@d3a7b79dce3e (webkit.org/b/329860): The runtime function `JSCellButterfly::createFromArray`, which array spread such as `[...array]` and `f(...array)` uses, now copies Int32, Contiguous, Double and Undecided arrays with `copyArrayElements`. Before, it copied element by element, with a write barrier or a `getDirectIndex` call for each element (from the commit message). Tests: `JSTests/microbenchmarks/spread-contiguous-array-generic.js`, `JSTests/microbenchmarks/spread-undecided-array.js` and `JSTests/stress/spread-array-indexing-types.js`.
- WebKit/WebKit@94b9e31c9dd8 (webkit.org/b/329634): A spread call `f(...array)` no longer calls the C++ operations `operationSizeOfVarargs` and `operationLoadVarargs` when DFG or FTL inlines the callee.
